---
title: Validate a command or query
description: Check a command's or query's input in a FluentValidation validator beside it, and get every failure back as Errors before the handler runs.
---

## What you build

One validator per command or query that needs input checks: an `internal` FluentValidation `AbstractValidator<T>` beside it in the [Feature](/docs/reference/glossary#feature). Every failure of every validator comes back as one failed [Result](/docs/reference/glossary#result) before the handler runs, each an [Error](/docs/reference/glossary#error) of kind validation with its code and the property it names as its target. Nothing throws.

<Callout type="warn" title="Shape here, business rules in the aggregate">
  A validator checks the shape of the input: present, long enough, in range. A rule that depends on state, such as a name already in use or a sale that has ended, belongs in the aggregate, through `CheckRule`, or in a unique index. See [Business rules](/docs/capabilities/domain-primitives#business-rules).
</Callout>

## When to use it

For any command or query whose input can be wrong. A command or query with no validator has nothing checked in that step.

## What the Kit guarantees

| Guarantee | Where the skill states it |
| --- | --- |
| Every failure as one failed Result, with its code and target | [Validation](/docs/capabilities/commands-queries-validation#validation) |
| A validator only reads | [Code that only reads](/docs/capabilities/commands-queries-validation#code-that-only-reads) |
| Validation answers 400 with every failure | [Problem responses](/docs/capabilities/web#problem-responses) |

## Failure messages

<Accordions>
  <Accordion title="400 with an errors array">
    Over HTTP, a failed validation answers 400 as a problem response whose `errors` lists each failure with its `code`, `message` and `target`.
  </Accordion>
  <Accordion title="A command sent from a validator">
    A validator may run a query, such as an existence lookup, but a command it sends throws: `A command was sent from an authorizer or a validator.`
  </Accordion>
</Accordions>
