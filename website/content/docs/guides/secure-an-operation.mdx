title: Secure an Operation
description: Declare the permission a command or query requires, register its check, and say which permissions each Actor holds.

## What you build

A permission declared on the command or query itself, checked in the pipeline's authorization step for every [Operation](/docs/reference/glossary#operation), whatever entry point started it. The application says which permissions an [Actor](/docs/reference/glossary#actor) holds; the [Kit](/docs/reference/glossary#kit) reads no claim and no request itself. An Actor without the permission is denied with a forbidden [Error](/docs/reference/glossary#error), and the command commits nothing: see [Denial](/docs/capabilities/security#denial).

<Callout type="warn" title="A trusted continuation is not checked again">
  Work an authorized Operation causes, such as a delivery the Kit restores or a `Continue()` inside the running Operation, runs on its recorded authority: a declared permission is not checked again for it. So a handler can continue into protected work its Actor holds no permission for. Declare a permission on the Operation that decides to cause such work.
</Callout>

## When to use it

When a command or query must be limited to Actors who hold a named permission. Every HTTP caller is already authenticated by default. A rule that is not "this Actor holds this permission", such as one that reads the command's data, is an `IAuthorizer<TOperation>` of the [Module](/docs/reference/glossary#module)'s own: see [Authorization hook](/docs/capabilities/commands-queries-validation#authorization-hook).

<Steps>
<Step>

### Declare the permission on the record

One permission per command or query, named as [Declaring a permission](/docs/capabilities/security#declaring-a-permission) says and kept in a constant on the record, so tests and grants name it without repeating the string.

</Step>
<Step>

### Register its check

Call `AddPouryaKitPermissions()` in the [Composition Root](/docs/reference/glossary#composition-root) of every Module whose [Features](/docs/reference/glossary#feature) declare a permission. A declared permission whose check no Composition Root registered fails the [Host](/docs/reference/glossary#host) when it is built, so it never runs unchecked.

</Step>
<Step>

### Say which permissions each Actor holds

Implement `IActorPermissions` in the Host and register it. It receives the Operation's context, so the answer can depend on the Actor and the [tenant](/docs/reference/glossary#tenant). The [Proving Sample](/docs/reference/glossary#proving-sample)'s Host reads them from the HTTP caller's permission claims, matched to the Operation's Actor:

</Step>

### Prove it both ways

## Failure messages

<Accordions>
  <Accordion title="Permission.Denied">
    The Actor does not hold the permission. Over HTTP the [Error](/docs/reference/glossary#error) answers a problem response for its kind, and nothing commits: [Denial](/docs/capabilities/security#denial).
  </Accordion>
  <Accordion title="The Host does not build: its check is not registered">
    `Build()` throws, one line per command or query, naming the assembly to give `AddPouryaKitPermissions` in the Composition Root that registers its handler. [Declaring a permission](/docs/capabilities/security#declaring-a-permission) quotes the message.
  </Accordion>
  <Accordion title="The Host does not build: no permission source">
    A Host whose Modules declare permissions and that registers no `IActorPermissions` fails when it is built.
  </Accordion>
</Accordions>
