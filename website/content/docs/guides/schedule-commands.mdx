---
title: Schedule a delayed or recurring command
description: Schedule one of a Module's commands to run later from the Operation that causes it, or declare one to run on a cadence as a system Actor.
---

## What you build

Either kind is an ordinary command with an ordinary handler, declared in its [Module](/docs/reference/glossary#module)'s [Composition Root](/docs/reference/glossary#composition-root) under a durable name:

- a [delayed command](/docs/concepts/delayed-and-recurring-commands), which an [Operation](/docs/reference/glossary#operation) schedules and which runs once due, as that Operation's continuation;
- a [recurring command](/docs/reference/glossary#recurring-command), which runs at every occurrence of a cadence as the system [Actor](/docs/reference/glossary#actor) its declaration names.

<Callout type="warn" title="The name is durable">
  A delayed or recurring command's name is its queue and half of its [Receipts](/docs/reference/glossary#receipt)' key. The commands stored before you rename the declaration, or rename or move the command's type, are set aside as dead letters and never run.
</Callout>

## When to use it

A [delayed command](/docs/reference/glossary#delayed-command) when an Operation causes something that must happen later, such as a quote's expiry. A recurring command for work on a cadence that no Operation asks for, such as a nightly reconciliation. A tenant-scoped Module declares no recurring command.

## Steps: a delayed command

<Steps>
<Step>

### Schedule it from the Operation that causes it

Inject `IDelayedCommands` into a command's handler, a [Domain Event Handler](/docs/reference/glossary#domain-event-handler), or a [Notification](/docs/reference/glossary#notification) or [Integration Event Handler](/docs/reference/glossary#integration-event-handler), and call `Schedule` with the command and the time it is due. It only records the command: the [Unit of Work](/docs/reference/glossary#unit-of-work) writes it in the same commit as the change, or not at all.

### Declare it in the Composition Root

Declare each delayed command once, under its name, with `AddPouryaKitDelayedCommand`, as Billing declares `ExpireQuoteCommand` under `billing.expire-quote`. A Module schedules only commands it declared.

</Step>

### Handle it for the state it finds

## Steps: a recurring command

<Steps>
<Step>

### Write the command and its handler

The command carries the occurrence it runs. The handler runs as the system Actor of the declaration, with no [tenant](/docs/reference/glossary#tenant).

<Snippet file="samples/ModularMonolith/src/Modules/Inventory/Inventory/StockItems/Features/ReconcileStock/ReconcileStockCommandHandler.cs" region="reconcile-stock-handler" />

</Step>
<Step>

### Declare it with its system Actor and bind its cadence

Declare it once with `AddPouryaKitRecurringCommand`: its name, the system Actor every occurrence runs as, and the function that builds the command for each occurrence. Bind the cadence from configuration on the options builder it returns, as Inventory binds `Inventory:ReconcileStock`. [Recurring commands](/docs/capabilities/messaging#recurring-commands) shows Inventory's declaration.

</Step>
<Step>

### Set the cadence in the Host's configuration

Set `Every` under that section, as `Inventory:ReconcileStock:Every`. A missing or zero cadence stops the [Host](/docs/reference/glossary#host) when it starts: it never runs at a default.

</Step>
</Steps>

## Testing

The message store compares due times with the system clock, not the Host's `TimeProvider`, so a test that needs a delayed command to run uses a short real delay. The test fixture does not wait for a command not yet due. A test that needs occurrences to run starts its own Host, on a database of its own, with a short cadence. See [Deliveries](/docs/capabilities/testing#deliveries).

## Failure messages

<Accordions>
  <Accordion title="Schedule throws InvalidOperationException">
    The command was not declared as a delayed command of this Module, it is a recurring command, the caller only reads, or no Unit of Work runs there, such as an endpoint or a hosted service.
  </Accordion>
  <Accordion title="OptionsValidationException when the Host starts">
    The recurring command's `Every` is not longer than zero, or is longer than the maximum.
  </Accordion>
  <Accordion title="A dead letter received at the command's name">
    A run failed on every attempt, or was stored under a name or type no declaration has any more. A failed [Result](/docs/reference/glossary#result) becomes a `DelayedCommandFailedException`, naming each [Error](/docs/reference/glossary#error).
  </Accordion>
</Accordions>
