## What it is

A Host is a deployable application that runs Operations. A Module is a business boundary inside a Host that owns its data, its rules and its public Contracts. Anything outside a Module reaches it through its Gateway, and every Gateway call is one Operation in its own scope, run with the `OperationContext` the caller passes.

<Callout type="warn" title="Feature code never commits">
  The Unit of Work writes the Outbox, saves and commits, and sends what it wrote only after the commit. Feature code returns its Result and leaves all of it to the Unit of Work.
</Callout>

## When to use each template

`PouryaKit.Templates` is a `dotnet new` template package: a new application starts from the Proving Sample's business code in one of three compositions.

<Tabs items={['Monolith', 'Modular monolith', 'Service']}>
  <Tab value="Monolith">The single-Module start: one Module's data and rules, which grows into the modular monolith when a second Module arrives.</Tab>
  <Tab value="Modular monolith">Several Modules in one Host, each reached through its Gateway.</Tab>
  <Tab value="Service">One Module in a Host of its own, which receives from another Host over RabbitMQ.</Tab>
</Tabs>

## Generate a solution

<Steps>
<Step>

### Pick a composition

Each template generates a solution in a folder named after `-n`.

```bash title="Terminal"
dotnet new pouryakit-modular-monolith -n Acme.Shop
```

</Step>
<Step>

### Restore it

`dotnet new` restores the solution once it is generated, and `--no-restore` skips that. The restore needs a NuGet source with the Kit's packages.

</Step>
</Steps>

## What the Kit guarantees

| Rule | In practice |
| --- | --- |
| A handler returns a Result, and an expected business failure is an Error in that Result | Exceptions are for bugs and infrastructure |
| HTTP access is authenticated by default | A public endpoint says so |
| A Module references no other Module's implementation | Structure tests reject it, and any save or commit in a Module's code |
| A declaration refuses its own mistakes while the Host is composed | A composition check when the container is built, a startup check when the Host starts |

## Failure messages

<Accordions>
  <Accordion title="A save refused in a tenant-scoped Module">
    The Unit of Work refuses the save with `Tenant.Mismatch` when an aggregate belongs to another tenant than the Operation's, and with `Tenant.NotLoaded` when it changes an entity no query loaded.
  </Accordion>
  <Accordion title="A delivery with no tenant">
    A delivery to a tenant-scoped Module that carries no tenant fails with `Tenant.Required`, is retried, then set aside as a dead letter.
  </Accordion>
</Accordions>
