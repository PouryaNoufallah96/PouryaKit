title: Snapshots and Tombstones
description: The current state of one aggregate, published in the commit of every change for a Module that keeps its own copy, and applied only when it is newer.
---

## What it is

A [Snapshot](/docs/reference/glossary#snapshot) is the current state of one aggregate, published for other [Modules](/docs/reference/glossary#module), and it supersedes every earlier Snapshot of that aggregate. A [Tombstone](/docs/reference/glossary#tombstone) is the Snapshot that says the aggregate no longer exists.

An [Integration Event](/docs/reference/glossary#integration-event) is a fact, and each one matters on its own. A Snapshot is state, and only the newest matters: once a newer one is applied, an older one is worth nothing. One aggregate may have both, as Catalog's product does.

<Callout type="warn" title="Feature code never publishes a Snapshot">
  The [Unit of Work](/docs/reference/glossary#unit-of-work) publishes it, in the commit of every change of the aggregate, built by a mapper you write. The receiver applies the newest version it is given and skips older ones, so a Snapshot handler keeps a copy current: it never counts or reacts to each change.
</Callout>

## When to use it

When another Module keeps its own copy of this Module's data, as Inventory keeps a copy of each catalog product. When another Module reacts to something that happened, publish an [Integration Event](/docs/concepts/integration-events) instead.

<Steps>
<Step>

### Declare the Snapshot

A public record in the publishing Module's [Contracts](/docs/reference/glossary#contracts), with the aggregate's key, the state other Modules need, a field that says whether it is the Tombstone, and the aggregate's version.

</Step>
<Step>

### Write its mapper

`Map` builds the Snapshot of an aggregate that exists, and `Tombstone` the Snapshot of one the [Operation](/docs/reference/glossary#operation) removed. The mapper runs after every reaction, with the version being committed, and only reads.

<Snippet file="samples/ModularMonolith/src/Modules/Catalog/Catalog/Products/Events/ProductSnapshotMapper.cs" region="product-snapshot-mapper" />

</Step>
<Step>

### Declare it in the Composition Root

The publishing Module declares the aggregate, the Snapshot type, the mapper and the [wire name](/docs/reference/glossary#wire-name) with `PublishSnapshot`, as Catalog declares `ProductSnapshotV1` under `catalog.product-snapshot.v1`. The receiving Module subscribes an ordinary [Integration Event Handler](/docs/reference/glossary#integration-event-handler) with `Subscribe`.

</Step>
<Step>

### Keep the copy

Write only the effect: insert or update for a Snapshot, delete for a Tombstone. The copy is a table of the receiving Module's own that no aggregate maps, written with plain SQL in the receiving Module's Unit of Work. The handler compares no version: the [Kit](/docs/reference/glossary#kit) runs it only for a newer one.

<Snippet file="samples/ModularMonolith/src/Modules/Inventory/Inventory/CatalogProducts/Features/CopyProduct/CopyProductIntegrationEventHandler.cs" region="copy-product" />

The receiving Module's migration creates the copy's table and the table where the Kit keeps the versions applied, with `CreateSnapshotVersionTable`, beside its [Receipt](/docs/reference/glossary#receipt) table.

</Step>
</Steps>

## Failure messages

<Accordions>
  <Accordion title="A mapper that writes">
    A mapper that sends a command, adds or removes through a repository, joins the connection or publishes is refused with an `InvalidOperationException`, which fails the Operation, and nothing commits. A mapper that catches the refusal of its command still fails the Operation.
  </Accordion>
  <Accordion title="A key the database generates">
    The Snapshot is built before the save, so a key the database generates does not exist yet. The Operation that creates such an aggregate fails at its commit with an `InvalidOperationException`. Create keys in the application, as `TypedId.New` does.
  </Accordion>
  <Accordion title="A type published both ways">
    Declaring a type with both `Publish` and `PublishSnapshot` fails while the [Host](/docs/reference/glossary#host) is composed. A type is either an Integration Event or the Snapshot of one aggregate.
  </Accordion>
</Accordions>
