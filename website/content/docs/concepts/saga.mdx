## What it is

A [Saga](/docs/reference/glossary#saga) is a [Module](/docs/reference/glossary#module)'s long-running reaction across [Integration Events](/docs/reference/glossary#integration-event) that keeps its own state between steps. Integration Events start and advance it, its own timeouts end it, and each step can emit Integration Events of its own. A saga's identity is the [tenant](/docs/reference/glossary#tenant) of the event that started it with that event's business id.

A Saga is the one reaction that runs outside an [Operation](/docs/reference/glossary#operation). Each step runs with no [Operation Context](/docs/reference/glossary#operation-context), is claimed once in its own transaction, and emits its Integration Events under the saga's system [Actor](/docs/reference/glossary#actor).

<Callout type="warn" title="A step only changes the saga's state, emits and schedules">
  No authorizer, validator, [Unit of Work](/docs/reference/glossary#unit-of-work) or [Receipt](/docs/reference/glossary#receipt) runs for a step. A step that dies before its commit runs again, so a call to another service or a file it wrote would repeat. Anything else is the work of a [subscription](/docs/reference/glossary#subscription) that receives what the saga emits.
</Callout>

## When to use it

When a reaction waits for several Integration Events, keeps what it has seen between them, and gives up after a time. In the [Kit](/docs/reference/glossary#kit)'s tests, a fulfilment saga starts when an order is placed, counts its payments, and either fulfils the order once all payments arrived or cancels it when they did not arrive in time. A reaction to one Integration Event at a time is an [Integration Event Handler](/docs/reference/glossary#integration-event-handler): see [Integration Events](/docs/concepts/integration-events).

## Failure messages

<Accordions>
  <Accordion title="SagaInputRefusedException in a dead letter">
    An event with no tenant, or one whose identity names a saga that does not exist and that it does not start, is refused before any step, retried, then set aside. An advancing event that arrives after its saga completed is refused the same way.
  </Accordion>
  <Accordion title="InvalidServiceLocationException">
    A step that takes a Kit scoped service, such as the Integration Event publisher, is refused at its first message. Emit with `PublishAsync` instead.
  </Accordion>
  <Accordion title="MissingPreBuiltTypesException outside Development">
    The Host was published without the saga's generated code. Run `codegen write` before the release build.
  </Accordion>
</Accordions>
