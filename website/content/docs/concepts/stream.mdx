## What it is

A [Stream](/docs/reference/glossary#stream) is an aggregate whose stored state is the ordered events it has appended, loaded by folding them. It is the [Kit](/docs/reference/glossary#kit)'s second write model, beside EF Core aggregates, stored by Marten in the same PostgreSQL database. Its [Unit of Work](/docs/reference/glossary#unit-of-work) commits its events with the [Operation](/docs/reference/glossary#operation)'s [Notifications](/docs/reference/glossary#notification) and [Integration Events](/docs/reference/glossary#integration-event) in one transaction. A Stream belongs to the [tenant](/docs/reference/glossary#tenant) of the Operation that wrote it.

<Callout type="warn" title="One commit owner per write model">
  A Stream [Module](/docs/reference/glossary#module)'s Operations commit through the Marten Unit of Work alone, and an EF Core Module's through the EF Core one: no Operation commits through both. A Stream publishes no [Snapshot](/docs/reference/glossary#snapshot), and a Stream Module and a [Saga](/docs/reference/glossary#saga) cannot share one [Host](/docs/reference/glossary#host) yet.
</Callout>

## When to use it

When an aggregate is best kept as the events it went through. In the [Proving Sample](/docs/reference/glossary#proving-sample), Ledger is a Stream Module beside the EF Core Modules Catalog, Inventory and Billing: it keeps accounts, posts entries to them, and reads an account's balance by folding its entries. [Stream or EF Core aggregate](/docs/decision-guides/stream-or-ef-core-aggregate) compares the two write models.

A Stream Module declares its write model in its [Composition Root](/docs/reference/glossary#composition-root) with `AddPouryaKitStreams`, with a schema of its own, and the Host registers its one Marten store with `UsePouryaKitMarten`, after `UsePouryaKitWolverine` when it also has EF Core Modules. A Stream Module needs no migration. Each event is a [Domain Event](/docs/reference/glossary#domain-event), so a [Notification Handler](/docs/reference/glossary#notification-handler) subscribes to it as to any other. [Registering](/docs/capabilities/stream#registering) shows Ledger's Composition Root and the Host.

## Failure messages

<Accordions>
  <Accordion title="UnitOfWork.ConcurrencyConflict">
    Another Operation appended to the Stream after this one read it, or started the same Stream. Nothing is appended and nothing is sent; nothing retries.
  </Accordion>
  <Accordion title="An internal Apply method">
    Marten folds a Stream only through public `Apply` methods. With an internal one, loading the Stream throws Marten's invalid-projection exception when the Operation runs, not at build. See [Writing a Stream](/docs/capabilities/stream#writing-a-stream).
  </Accordion>
  <Accordion title="A write model with no Outbox">
    A Host with a message store fails when it is built when one write model's Unit of Work would write no [Outbox](/docs/reference/glossary#outbox), such as Stream Modules beside `UsePouryaKitWolverine` with `AddPouryaKitMarten`. The line names the Modules and the registration to call.
  </Accordion>
</Accordions>
