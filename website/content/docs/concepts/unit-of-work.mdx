## What it is

The [Unit of Work](/docs/reference/glossary#unit-of-work) is the single owner of an [Operation](/docs/reference/glossary#operation)'s outcome: everything the Operation changed is kept together or discarded together. Each command runs in one transaction that the Unit of Work begins and owns. Your handler changes aggregates through a repository and returns its [Result](/docs/reference/glossary#result); the Unit of Work does everything after that.

<Callout type="warn" title="Feature code never saves, commits or touches the Outbox">
  No `SaveChanges`, no transaction, no [Outbox](/docs/reference/glossary#outbox) write in a handler of any kind. The Unit of Work does each of them once, for the whole Operation, and structure tests reject a [Module](/docs/reference/glossary#module) whose code does any of it.
</Callout>

## When it matters

Every command. You never call the Unit of Work yourself: the Module's persistence package registers it when the [Composition Root](/docs/reference/glossary#composition-root) declares the Module's data, for example with `UsePouryaKitPostgres`, and the [Kit](/docs/reference/glossary#kit) runs it around each command. A query starts none of its own.

## How it works

After the outermost handler returns a success, the Unit of Work:

1. runs the [Domain Event Handlers](/docs/concepts/domain-event) of the [Domain Events](/docs/reference/glossary#domain-event) the Operation's aggregates raised;
2. prepares persistence: audit and soft-delete fields, and each changed aggregate's version;
3. builds the [Snapshots](/docs/concepts/snapshots) other Modules subscribe to;
4. writes the [Outbox](/docs/concepts/outbox-and-notifications);
5. saves once and commits;
6. only then sends what it wrote.

A failed Result anywhere, a nested command's or a [Domain Event Handler](/docs/reference/glossary#domain-event-handler)'s included, rolls all of it back, so nothing is saved and nothing is sent. This handler changes a product and saves nothing; the Unit of Work commits the change:

Each aggregate's version is its concurrency token. When another Operation committed a change to the same aggregate first, the save is refused and the Operation fails with a conflict [Error](/docs/reference/glossary#error). Nothing retries it: the caller sends the command again through the [Gateway](/docs/reference/glossary#gateway), which runs a new Operation on the current state.

## What the Kit guarantees

The Kit states each guarantee and names the test that proves it in [What the Kit guarantees](/docs/capabilities/persistence#what-the-kit-guarantees):

| Guarantee | Where the skill states it |
| --- | --- |
| One commit or nothing | [What the Kit guarantees](/docs/capabilities/persistence#what-the-kit-guarantees) |
| Saved with no save in Feature code | [What the Kit guarantees](/docs/capabilities/persistence#what-the-kit-guarantees) |
| The Outbox in the commit, the send after it | [What the Kit guarantees](/docs/capabilities/persistence#what-the-kit-guarantees) |
| One version step per Operation | [Versions and conflicts](/docs/capabilities/persistence#versions-and-conflicts) |
| A refused save is an Error | [Unique values](/docs/capabilities/persistence#unique-values) |
| No write without a Unit of Work | [The repository](/docs/capabilities/persistence#the-repository) |

## Failure messages

<Accordions>
  <Accordion title="UnitOfWork.ConcurrencyConflict">
    Another Operation committed a change to the same aggregate first. Everything rolls back, and over HTTP it answers 409. Send the command again, or report the conflict.
  </Accordion>
  <Accordion title="A unique index the Module mapped">
    A save that violates a unique index the Composition Root mapped fails with that Module's own Error, such as `Product.NameInUse`. An unmapped constraint stays an exception.
  </Accordion>
  <Accordion title="A repository write with no Unit of Work">
    A write where no command runs, such as in an endpoint or a hosted service, throws: `The repository of Product was asked to write while no Unit of Work is active, so no commit would save the change and it would be lost.` Send a command to write.
  </Accordion>
</Accordions>
