description: "Declare the permission a command or query requires, answer which permissions an Actor holds, and optionally hash passwords and verify JWT bearer tokens."
---

`PouryaKit.Security` checks one kind of rule: "this [Actor](/docs/reference/glossary#actor) holds this permission". You put `[RequiresPermission]` on a command or query, and the pipeline's authorization step asks your application's `IActorPermissions` before validation and the handler run. An Actor without it gets `Permission.Denied`, and nothing commits ([Denial](#denial)). A trusted continuation, such as a delivery the Kit restored or a question one authorized Operation asks another Module, is not asked again.

The same package hashes and verifies stored passwords with PBKDF2, and `PouryaKit.Security.JwtBearer` sets up the Host's JWT bearer authentication so each verified token names the Actor and the [tenant](/docs/reference/glossary#tenant). The Kit issues no token and has no role system, policy framework or identity store.

<Callout type="warn" title="Nothing holds a permission by default">
  The Kit reads no claim itself: your `IActorPermissions` decides for every Actor, a named system Actor included. Match the claims to the context's Actor, since code inside a request may run an Operation as someone else.
</Callout>

## When to use it

- A command or query may run only for Actors that hold a permission.
- You supply the permissions an Actor holds, from claims or your own store.
- You decide what a continuation or a system Actor may run.
- Your application stores its own passwords and needs to hash, verify and upgrade them.
- Callers present bearer tokens from an identity provider, and the Host must turn their verified claims into the Actor and tenant.

## How it works

<Steps>
<Step>

### Declare the permission on the record

Put `[RequiresPermission(name)]` on the command or query, one permission each, named `<module>.<resource>.<action>` and kept in a constant on the record so tests and grants name it without repeating the string.

</Step>
<Step>

### Register the check in the Composition Root

`AddPouryaKitPermissions()` registers the check for every command and query of the Module that declares one. A declared permission whose check no Composition Root registered fails the Host when it is built, so it never runs unchecked.

</Step>
<Step>

### Say which permissions an Actor holds

The Host implements `IActorPermissions` and registers it. It receives the Operation Context, so its answer can depend on the Actor and the tenant.

</Step>
</Steps>
