`PouryaKit.Domain` is the package your aggregates are made of. An aggregate derives from `AggregateRoot<TId>` and is keyed by a typed ID, a sealed record over a `Guid`, `long`, `int` or `string`. A method that can fail checks its business rules and returns a [Result](/docs/reference/glossary#result): a value, or an [Error](/docs/reference/glossary#error) for an expected business failure. When something worth reacting to happens, the aggregate raises a [Domain Event](/docs/reference/glossary#domain-event). The package has no dependencies, so it adds nothing to your domain but these types.

<Callout type="warn" title="A business failure is a Result, never an exception">
  Return an Error for anything a caller can cause, such as a missing name or an unknown product. Exceptions are for bugs and infrastructure. And never set an aggregate's `Version` or clear its Domain Events: the [Unit of Work](/docs/reference/glossary#unit-of-work) owns both.
</Callout>

## When to use it

- You are writing an aggregate, an entity or the typed ID that keys it.
- A business rule decides whether a change may happen.
- Something in the domain happened that other code reacts to: a Domain Event.
- You are declaring the Errors of a Business Area.
- A business rule compares with the current time, or a test fixes the time a Domain Event records.

## How it works

<Steps>
<Step>

### Key each aggregate by its own ID type

Declare one typed ID per aggregate. Two IDs are equal only when their type and value are, so a product's ID can never be passed where a category's is expected. `TypedId.New<ProductId>()` creates a new, time-ordered one, and the Kit's JSON, EF Core and Dapper setup all read and write it as its bare value, with no converter of yours.

</Step>
<Step>

### Return a Result from a behaviour that can fail

A value or an Error converts to a Result on its own, so a method returns either directly. Check a rule with `CheckRule` from inside the aggregate: a broken rule comes back as a failed Result, and you pass it on with `return result.Errors;`.

</Step>
<Step>

### Raise what happened

Call `Raise` with a Domain Event, a sealed record named in the past tense. It carries typed IDs and values, never the aggregate. Inside the Module, a Domain Event Handler reacts in the same commit; after the commit, a Notification Handler can tell the world.

</Step>
<Step>

### Declare each Error once

Give every Error a stable code, a message and a kind through its factory, such as `Error.Validation` or `Error.NotFound`. The kind, not an HTTP status, is what the Web package turns into a response.

</Step>
</Steps>
