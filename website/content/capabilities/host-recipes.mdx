The Host recipes are a Host's service defaults, shaped like .NET Aspire's `ServiceDefaults` template: OpenTelemetry that exports the Kit's activities and metrics, liveness and readiness endpoints, service discovery, one standard resilience pipeline for every outgoing client, and Serilog when the Host wants it. They live in the Proving Sample's `ModularMonolith.ServiceDefaults` project.

They are template content, not a Kit package: the project templates generate the project as `<Name>.ServiceDefaults` and compose the recipes in their Hosts, and your application owns and changes its copy. Each recipe is optional, and none is needed for the Kit to work.

<Callout type="warn" title="The recipe exports; the Kit emits">
  A Host without `AddPouryaKitObservability()` exports no Operation of the Kit, whatever its exporters listen to. And readiness outside Development is the platform's probe: the recipe maps its liveness endpoint everywhere and its database check in Development only ([Liveness and readiness](#liveness-and-readiness)).
</Callout>

## When to use it

- You compose a Host's telemetry export, health endpoints, service discovery and outgoing HTTP in one place.
- An orchestrator probes the Host's liveness, without a token.
- One outgoing client needs other retry limits than the shared pipeline's.
- You log through Serilog, or test a Host that uses the recipes.

## How it works

<Steps>
<Step>

### Add the service defaults to the Host

`AddServiceDefaults()` adds OpenTelemetry, the health checks, service discovery and the shared resilience pipeline. `MapDefaultEndpoints()` maps the health endpoints, and `AddSerilogDefaults()` opts into Serilog.

</Step>
<Step>

### Keep liveness inside the process

The liveness endpoint asks only the checks that never leave the process, so it stays healthy while a database is down: an orchestrator gains nothing by restarting the Host then. It is anonymous and exempt from the rate limit, since a probe carries no token.

</Step>
<Step>

### Retry safe methods only

Every client gets the Kit's standard handler, which retries safe methods and sends a write once. A client that needs other limits removes the shared pipeline and adds its own, under a name of its own.

</Step>
</Steps>
