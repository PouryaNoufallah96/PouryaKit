description: "Serve a Module's gRPC service from a Protobuf contract in its Contracts, answer a failed Result as a gRPC status with every Error in a trailer, and call another Host with the Operation Context."
---

`PouryaKit.Grpc` puts gRPC on the same conventions as the Kit's HTTP endpoints. The `.proto` contract lives in the Module's [Contracts](/docs/reference/glossary#contracts), which both sides compile: the Module's service and another Host's client. A service is declared in the Module's [Composition Root](/docs/reference/glossary#composition-root), mapped once in the Host, and runs each call through the Module's [Gateway](/docs/reference/glossary#gateway) with the [Operation Context](/docs/reference/glossary#operation-context) the call began with. A failed [Result](/docs/reference/glossary#result) answers a gRPC status chosen as HTTP chooses its status, with every Error in the `pouryakit-errors-bin` trailer.

On the calling side, a client registered with the Kit carries the Operation Context in its call metadata, with a deadline from validated options, so the called Host continues the caller's Operation when it trusts the caller as a peer.

<Callout type="warn" title="gRPC without TLS needs an HTTP/2-only listener">
  Over TLS one listener serves gRPC and REST alike. Without TLS, Kestrel's default listener speaks HTTP/1.1 and every gRPC call fails with `HTTP_1_1_REQUIRED`, so the Host needs a second listener of HTTP/2 alone for gRPC, beside the one REST callers reach.
</Callout>

## When to use it

- Another Host asks a Module questions over gRPC rather than HTTP.
- You write a Module's gRPC service from a Protobuf contract, and map the services in the Host.
- A client must read every Error of a failed call, not only its status.
- A Host calls another Host with a client that carries the Operation Context and a deadline.
- You test two Hosts over gRPC.

## How it works

<Steps>
<Step>

### Put the contract in the Contracts

The `.proto` file lives in the Module's Contracts project, which takes the code generator and the Protobuf runtime itself and still references nothing of the Kit.

</Step>
<Step>

### Declare the service and map it once

`AddPouryaKitGrpcService` in the Composition Root declares the service, and `MapPouryaKitGrpcServices` in the Host maps every declared service on one authenticated route group. The service injects the call's Operation Context and its Module's Gateway, and turns the Result into a response with `ToGrpcResponse`.

</Step>
<Step>

### Call another Host through a registered client

`AddPouryaKitGrpcClient` registers a generated client under a name, with an address and a deadline from options. Each call passes its context with `WithOperationContext`. A client never calls its own Host: a call between Modules of one Host goes through the Gateway.

</Step>
</Steps>
