---
description: "Write a Module's messages in English and Persian, and run each HTTP request in the culture its client's Accept-Language header names."
---

`PouryaKit.Localization` lets a Module answer in English or Persian. A Feature injects `IStringLocalizer<T>` for a type of its own and reads each message by its key, from `.resx` files beside that type's file: the neutral file holds English and the `.fa.resx` file Persian. Each HTTP request runs in the culture its client's `Accept-Language` header names ([What the Kit guarantees](#what-the-kit-guarantees)), and that culture flows through the [Gateway](/docs/reference/glossary#gateway) into the Operation's handlers.

It is optional and adds no NuGet package: it references `PouryaKit.Cqrs` and the ASP.NET Core shared framework only. A Host that answers in English alone leaves it out, as both of the Proving Sample's Hosts do.

<Callout type="warn" title="A delivery runs in the process's culture">
  A Notification Handler, an Integration Event Handler or a delayed or recurring command runs outside any HTTP request, so it does not read the culture of the request that caused it. What else stays unlocalized is under [Limits](#limits) and [What the Kit guarantees](#what-the-kit-guarantees).
</Callout>

## When to use it

- A Module's messages must read in English and Persian.
- You read the request culture from the client's `Accept-Language` header.
- A cached query must answer each culture's callers in their own language.
- You test a localized message over HTTP.

## How it works

<Steps>
<Step>

### Register it in the Composition Root

`AddPouryaKitLocalization()` on the Module's builder records the Module's assembly, registers the shared framework's localization with English and Persian, and puts the request localization middleware ahead of everything the application adds. The Host calls nothing in its pipeline.

</Step>
<Step>

### Put the messages beside a marker type

Declare an empty `internal sealed` class first in its file, and put its `.resx` files beside it, named after it. The SDK compiles them into the Module's assembly and a Persian satellite assembly; there is no generated class.

</Step>
<Step>

### Read a message by its key

Inject `IStringLocalizer<T>` for the marker type and read `messages["Key"]` in the request's culture. What a missing entry answers is under [A Module writing localized messages](#a-module-writing-localized-messages).

</Step>
</Steps>
