# PouryaKit.Messaging.Wolverine.Sagas provenance

Adopted implementations in `PouryaKit.Messaging.Wolverine.Sagas`. Format and rules: [README](README.md).

The package has no adopted implementation. It is the shape Spike #141 proved and ADR 0013 records (`spikes/saga/SagaSpike.Kit/` at `629b85a8`, tag `spike/saga`, not merged; ticket #142), rebuilt on the Kit's seams: the Kit's route, `SagaRouteSource`, returns an Integration Event's subscription routes and each saga's input route as Wolverine's `ExplicitRouting` and `TransformedMessageRouteSource` do (`JasperFx/wolverine` tag `V6.48.3`, `src/Wolverine/Runtime/WolverineRuntime.Routing.cs`, `src/Wolverine/Runtime/Routing/IMessageRoute.cs`); the step policy, `SagaStepPolicy`, puts Wolverine's own `EnrollAndFetchSagaStorageFrame` first in a declared saga's chain with the Kit's `SagaStorage` as its helper type (`src/Wolverine/Persistence/Sagas/EnrollAndFetchSagaStorageFrame.cs`), which opens Wolverine's `DatabaseSagaStorage` on a transaction of its own as Wolverine's `MessageDatabase` does (`src/Persistence/Wolverine.RDBMS/MessageDatabase.cs`); and each emission is written through the Messaging package's `OutboxWriter` with the Operation Context headers `WithOperationContext` writes. The claim statement follows `ReceiptStatements`' shape, and the claims table is created under the advisory lock Wolverine migrates the store under, `DatabaseSettings.MigrationLockId`.
