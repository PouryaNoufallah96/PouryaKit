# PouryaKit.Persistence.EFCore provenance

Adopted implementations in `PouryaKit.Persistence.EFCore`. Format and rules: [README](README.md).

The Unit of Work (`EfUnitOfWork`), the generic repository (`EfRepository`), the DbContext base (`PouryaKitDbContext`) and the Unit of Work connection (`EfUnitOfWorkConnection`, ticket #9) are new Kit code (plan section B.2, "Unit of work"; ADR 0003; ADR 0004), so they have no record here. The order of the Unit of Work's Domain Event drain is recorded with the drain, in [PouryaKit.Cqrs](PouryaKit.Cqrs.md).

Persistence preparation (`PersistencePreparation`, `PouryaKitModelConvention`) and the conflict Errors (`UnitOfWorkErrors`, `IUniqueConstraintReader`, `MapUniqueConstraint`), ticket #11, are new Kit code too: no upstream code was taken. Plan section B.2, "EF base, audit, soft delete", names the designs they replace. `PouryaNoufallah96/cybernod` at `bae8ac3`, `src/BuildingBlocks/BuildingBlocks.Core/Persistence/Interceptors/AuditableEntityInterceptor.cs`, stamps dates in a `SaveChanges` interceptor and counts only owned references that are added or modified; `mehdihadeli/CloudNativeKit` at `e81d65e`, `src/CloudNativeKit.Core/Persistence/EfCore/Interceptors/SoftDeleteInterceptor.cs`, flips a shadow flag during the save. The Kit stamps and converts as a Unit of Work step before the save, with deletion state in real properties, and counts any change to an owned type or a child entity, a removed one included, as a change of its aggregate. The aggregate version it advances is recorded in [PouryaKit.Domain](PouryaKit.Domain.md).

The Outbox seam of the commit sequence's step 5 (`IUnitOfWorkOutbox`, called by `EfUnitOfWork`) and the accessor to the Unit of Work's DbContext for Kit packages (`EfUnitOfWorkExtensions`), ticket #15, are new Kit code too; `PouryaKit.Messaging.Wolverine.EFCore` implements the seam, and its record holds what was taken from Spike S1.

## Typed-ID value converter

- **Kit files:** `src/PouryaKit.Persistence.EFCore/TypedIdConverter.cs`, `src/PouryaKit.Persistence.EFCore/PouryaKitDbContext.cs`
- **Upstream:** https://github.com/PouryaNoufallah96/cybernod
- **Commit:** bae8ac3b7e46f09e9375647786d03391a500876a
- **Upstream paths:** `src/BuildingBlocks/BuildingBlocks.Core/Persistence/Converters/TypedIdValueConverter.cs`, `src/BuildingBlocks/BuildingBlocks.Core/Persistence/Converters/StronglyTypedIdValueConverterSelector.cs`
- **Licence:** MIT
- **Adoption:** adapted
- **Ticket:** #8
- **Intentional differences:**
  - Registered once per DbContext in `ConfigureConventions` for every typed ID in the DbContext's assembly, instead of replacing EF Core's internal `IValueConverterSelector` service (plan section B.2).
  - Generic over the typed ID's value type (Guid, long, int or string, G.3) instead of Guid only.
  - Creates the ID through `TypedId.From`, a constructor looked up once per type, instead of reflection on every read.
  - A key with a value converter is never database-generated by convention: a numeric typed ID the database generates needs `ValueGeneratedOnAdd()` in its mapping.
