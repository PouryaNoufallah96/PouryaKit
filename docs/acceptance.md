# Wave 1 acceptance

Spec #1's Testing Decisions list the Gateway-seam acceptance scenarios, from plan Phases 2 to 4. Each row names the tests that prove the scenario. A test name is `Class.Method`. Classes without a project prefix are in `tests/ModularMonolith.Tests`, which drives the Proving Sample through Module Gateways (and HTTP) against PostgreSQL in Testcontainers. The `PouryaKit.Cqrs.Tests` classes run the dispatcher with stand-ins and no database. "Not proven" means no test proves the scenario as stated, and the Notes say what is missing.

The plan row is the B.1 behaviour the Phase acceptance line cites, or the Phase when it cites none.

## Structure seam

The third seam of the Testing Decisions is proven in `tests/PouryaKit.ArchitectureTests`. Each rule judges the Proving Sample and an offending fixture Module (`tests/PouryaKit.ArchitectureTests/Offending`) with the same function.

| Rule | Proven by |
|---|---|
| No Module references another Module's implementation; Contracts reference nothing from the Kit | `ModuleBoundaryTests` |
| A Module's only public types are its Composition Root and what its Host implements for it | `ModuleBoundaryTests` |
| Feature code never saves or commits | `FeatureCodeTests` |
| No transport type in Feature code; no envelope storage in a Module's DbContext | `FeatureCodeTests` |
| Only the Kit's drain clears Domain Events | `FeatureCodeTests` |
| No Dapper write to an aggregate's table | `DapperWriteTests` |
| Every Kit package's dependency closure matches plan section C | `PackageGraphTests` |
| No package with a licence outside the permissive list | `LicenceTests` |
