# Wave 1 acceptance

Spec #1's Testing Decisions list the Gateway-seam acceptance scenarios, from plan Phases 2 to 4. Each row names the tests that prove the scenario. A test name is `Class.Method`. Classes without a project prefix are in `tests/ModularMonolith.Tests`, which drives the Proving Sample through Module Gateways (and HTTP) against PostgreSQL in Testcontainers. The `PouryaKit.Cqrs.Tests` classes run the dispatcher with stand-ins and no database, and support a row that a Gateway-seam test already proves. Every scenario has Gateway-seam proof; a row notes any supplementary check that calls the dispatcher directly.

## Structure seam

The third seam of the Testing Decisions is proven in `tests/PouryaKit.ArchitectureTests`, described in [the architecture doc](architecture/README.md#structure-tests). Each rule judges the Proving Sample and an offending fixture Module (`tests/PouryaKit.ArchitectureTests/Offending`) with the same function.

| Rule | Proven by |
|---|---|
| No Module references another Module's implementation; Contracts reference nothing from the Kit | `ModuleBoundaryTests` |
| A Module's only public types are its Composition Root and what its Host implements for it | `ModuleBoundaryTests` |
| Feature code never saves, commits, writes in bulk or calls a step only the Kit runs | `FeatureCodeTests` |
| No transport type in Feature code; no envelope storage in a Module's DbContext | `FeatureCodeTests` |
| Only the Kit's drain clears Domain Events | `FeatureCodeTests` |
| No Dapper write to an aggregate's table | `DapperWriteTests` |
| Every Kit package's dependency closure matches plan section C | `PackageGraphTests` |
| No package with a licence outside the permissive list | `LicenceTests` |

## Stored-delivery schema regression

`StoredDeliveriesSchemaTests.Message_store_queries_use_the_exact_schema_name` exercises IDs, delivery enumeration, pending counts and deletion against PostgreSQL with `review-store` and `review-store"quoted`. These tests provision the message tables directly. They prove the reader quotes identifiers correctly; Wolverine 6.46.0 itself fails Host startup with these names in both Solo and Balanced mode, so this is not a Gateway or custom-schema Host-startup guarantee.

## Phase 5 package proof, ticket #25

[`python3 scripts/packaging/validate.py`](../scripts/packaging/validate.py) runs the existing suite against one Release build, then packs with `--no-build`. Its evidence directory records runtime results separately from package and consumer results. [Package guidance](packages.md) gives the command, artifact contract and evidence limits.

| Acceptance | Proof |
|---|---|
| MinVer is shared, with minimum 0.1, v prefix and preview.0 default | Real package/build versions agree; `minver.json` records an isolated Git repository's untagged, tagged and post-tag outputs |
| Exactly thirteen shipped packages; tests and samples excluded | Every project is evaluated against `inventory.json`; `InventoryTests.test_inventory_is_nonempty_and_exact` and `inventory-controls.log` reject empty/missing/extra/mismatched entries and accidental packability |
| MIT/notices, repository/source commit and SourceLink in each artifact | `PackageArtifactTests.Invalid_release_metadata_is_rejected`, `Embedded_source_link_identifies_the_commit_and_rejects_a_different_commit`, and the package validator inspect archive bytes and embedded PDBs |
| Existing graph and license restrictions survive shipping | `PackageGraphTests.Produced_nuspecs_obey_the_same_reference_rules_as_source_projects`, artifact graph checks and `consumer-closures.log` reuse `PackageGraph` and `LicenceTests` |
| Every package and supported composition restores/builds independently of Kit source | Thirteen package-only applications, the single-Module set without Modularity/Messaging, and the copied modular monolith build with isolated caches, source mapping, exact versions and nupkg SHA-256 checks |
| Defects fail the shared path | Per-control logs show missing/extra artifacts, wrong version/commit, missing notices, forbidden references and invalid symbols rejected by the same package validator |

This is package restore/build proof, alongside the existing PostgreSQL runtime suite above. It proves neither hosted publication nor private-feed recovery.

## Phase 5 CI validation, ticket #26

[CI guidance](ci.md) defines the read-only reusable workflow, preserved artifact contract and trusted-main handoff. The shared path replaces the former source-only build/test job and retains the AI configuration check.

| Acceptance | Evidence and remaining gate |
|---|---|
| Build/test/pack/consumers share full-history Release output | Reusable workflow invokes the shared path with the actual `github.sha`; history tests prove credential-free checkout mode, shallow rejection and unchanged default tag fetching. Hosted history/version/runtime evidence is pending. |
| Exact tested SHA and retained original artifacts | CI evidence tests exercise a real Git checkout, distinct PR head/base identity, successful receipts, SHA/checksum rejection and bounded packages/logs/assets without caches or configuration. |
| Failed validation stays failed and preserves diagnostics | Workflow retains the shared command's failing step/job; the failure receipt test proves no successful version/manifest pointer. Deliberately failing hosted PR proof is pending. |
| PR credentials and writes are isolated | Static YAML grants only `contents: read`, removes checkout credentials and forwards no secrets to the reusable job or shared command. Observed hosted effective permissions are pending. |
| Same-repository and fork execution | Same-repository hosted success/failure/restored-success proof is pending. Real private fork execution remains unverified under the [owner exception](https://github.com/PouryaNoufallah96/PouryaKit/issues/26#issuecomment-6013184398); no access settings may change. |

Local script tests and workflow lint are not hosted isolation proof. Publication must verify a successful trusted main run at the exact selected SHA; a PR receipt alone cannot authorize it.
