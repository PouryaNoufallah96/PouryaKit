# Docs site

`website/` is the Kit's public documentation site, a Next.js static export. Everything it renders is read outside this private repository.

## What a page may say

- **English only.**
- **Nothing private in rendered text.** No link or text pointing at the private repository (`github.com/PouryaNoufallah96/PouryaKit`), no local machine path, no name of the owner's private projects (Cybernod, Ultrabusiness), no delivery vocabulary (Wave, Phase, Spike), no tracker code (`W4`, `spec #183`, an issue number such as `#123`) and no citation of the private plan (`G.6`, `section G`, `plan I.3`, `plan section D`). The build enforces each ("Content from the Kit's sources" below); the public reference projects may be named.
- **Facts live in the Kit skill.** A Capability's guarantees, options and rules are in `.agents/skills/pourya-kit/` and a package's purpose and quick start in its `src/<Id>/README.md`; a page explains and renders them, and never holds a fact the skill lacks. A new how-to fact goes into the skill first.
- **Names are real.** `check-docs.py` checks the backticked names of every `website/content/**/*.mdx` page against the code; the pre-commit hook refuses an `.mdx` file staged in part.

## How it is built

- **No `public/` directory**, top-level or nested, and no `.vscode/`: they were the 2026-10-25 incident's payload paths, and `check-tree.py` refuses either segment anywhere. The icon uses the Next.js app-directory file convention (`app/icon.svg`), images are static imports, and each Open Graph image is a static `.png` route drawn with `next/og` (`app/og/image.png/route.tsx`, `app/og/docs/[...slug]/route.tsx`).
- **A static export** (`output: 'export'`): every route handler is a force-static `GET`, with `generateStaticParams` where its path has segments; no rewrite, redirect, header, proxy or handler that reads the request, which Next.js refuses in an export. A page's Markdown is the static file `/llms.mdx/docs/<slugs>/content.md`, which "Copy as Markdown" fetches, and search runs in the browser on the static index `/api/search.json`; there is no AI chat.
- **Design**: shadcn tokens in OKLCH with Fumadocs' `shadcn.css` and `preset.css`; light background `oklch(1 0 0)`, dark `oklch(0.16 0.004 285)`; one accent, Cobalt Indigo `oklch(0.585 0.233 277.117)`; Geist and Geist Mono through `next/font`; radius 0.625rem; cards rounded-xl with a 2px muted border and no shadow at rest; a neutral focus ring; reduced motion respected. No gradient text, side stripes, glassmorphism or em dashes. Fumadocs Cards, Steps, Tabs, Accordions and titled code blocks, with the site's own Card and Callout in MDX (`components/card.tsx`, `components/callout.tsx`), since Fumadocs' draw a 1px border, a shadowed icon and a side stripe; "Copy as Markdown" on each page; the theme toggle on Mod+Shift+D; static Open Graph images through `next/og`. Badges are native components; no external badge host.
- **Page skeleton**: title and one-line description; what it is; the key caveat; when to use it; steps with code; a guarantee table; failure messages; next steps.
- **Dependencies**: exact versions in `website/package.json`, pnpm pinned by its `packageManager`, the committed `website/pnpm-lock.yaml` installed with `--frozen-lockfile`. pnpm's settings are in `website/pnpm-workspace.yaml` (pnpm 11 and later read no `pnpm` field in `package.json`): a dependency's install script runs only when `allowBuilds` lists it `true`, and an unlisted one fails the install; `ignoredOptionalDependencies` keeps out `sharp`, whose libvips is LGPL-3.0-or-later and which an export never loads.
- **Licences** (ADR 0002): `pnpm --dir website check-licences` (`scripts/check-licences.mjs`) holds every package of the npm closure, dev dependencies included, to the licence its own `package.json` declares. It admits MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause, ISC and 0BSD, an `OR` with one admitted side and an `AND` of admitted terms, and fails every other shape: a missing, unknown or custom licence. Two exceptions are admitted for their named packages only: `caniuse-lite` under CC-BY-4.0, browser-support data that browserslist reads at build time, a hard dependency of next, attribution only; and `lightningcss` with its platform binaries under MPL-2.0, Tailwind 4's CSS compiler, run only at build time, nothing of it in `out/`. A new licence or exception is an owner decision.
- **CI**: the `website` job installs, checks the licences, runs the site's tests (`pnpm --dir website test`: the licence check's and the content pipeline's), lints with Biome and builds the export; `.agents/scripts/ci-local.sh` runs the same steps.
- **Ultrabusiness** (the owner's docs app) is a pattern source only: reimplement its patterns, never copy its code, and run nothing in its checkout.

## Content from the Kit's sources

- **One reader.** `lib/kit-sources/` is the only code that reads the Kit's sources (the skill, `docs/adr/`, `GLOSSARY.md`, `src/`, the Proving Sample and the tests) and rewrites their links: the site build uses it, and so is the public repository's sync to. `pnpm --dir website build` runs `scripts/kit-content.ts generate`, then `next build`, then `scripts/kit-content.ts check-export`. The generated pages are written into ignored folders, `content/docs/capabilities/`, `content/docs/reference/` and `.generated/`, emptied on every run: never edit them, and never edit a source for the site.
- **What is published.** The skill references on `PUBLISHED_REFERENCES` (`lib/kit-sources/references.ts`): every file under `references/` but the maintainer guides `packages.md` and `publication.md`. A reference on neither list fails the build, so a new one is published only once it is listed. Each gets a Capability page in the order of the skill's Capability table, the Host recipes under Guides. The Reference pages are the package matrix with a page per package (its `src/<Id>/README.md`, or its matrix row while it has none), the ADRs, the glossary, the Error codes (read from each package's `*Errors` and `*ErrorCodes` types; a member shape the reader does not know fails) and the Host checks, which link to the skill's sections, since the checks' messages are interpolated strings no reader extracts reliably.
- **A Capability page's top.** The hand-written part of a Capability page is `content/capabilities/<reference>.mdx`, with an optional `description` in its frontmatter and no `import` or `export`. The generated page includes it, then a "Reference" heading and the skill reference. A top heading whose anchor would renumber one of the reference's fails the build, since links between references name the reference's own anchors.
- **The public projection.** The glossary loses exactly its Wave, Phase and Spike entries (`EXCLUDED_ENTRIES` in `lib/kit-sources/glossary.ts`; a selector that matches no entry fails), and every other term gets an anchor. An ADR loses each parenthetical that only cites the tracker or the private plan, an amendment heading's citation and a table column that cites the tracker in every row; `lib/kit-sources/adr-rewrites.json` rewrites, each keyed by ADR and line, the sentences that lean on a tracker item, a Spike or the private plan, restated as the fact, and a private project's name, which becomes "a reference project"; a keyed line whose text has changed fails. A section whose heading fails, such as "Confirmed by Spike ...", is left out whole. Every passage that still fails the rules is left out and listed in `lib/kit-sources/adr-manifest.json`: a change to what is left out fails the build until `pnpm --dir website adr-manifest` rewrites the manifest, whose diff is then reviewed. A rewrite never changes what a decision says; a passage that cannot be projected cleanly is left out.
- **Links.** A link to a rendered source becomes its page, with its anchor carried over (an ADR's renamed heading anchors are mapped); a link into the repository with no page becomes its own text. A link to the private repository, or to an anchor the target lacks, fails.
- **Snippets.** `<Snippet file="samples/ModularMonolith/..." region="name" />`, on a line of its own, quotes a region of the Proving Sample's or the tests' code, marked `#region name` and `#endregion` (or `// #region name` where the language has no directive), as a code block titled with the file's name. A missing file or region fails the build. The templates pack the sample's Module code, so a marker in a file that a template replaces needs the template's copy too.
- **The rules over the export.** `check-export` reads every file of `out/` for a private repository link (each GitHub URL shape and an owner/repo name, compared as GitHub resolves them, ignoring case) a local path (`/Users/`, `/home/`, `/private/tmp/`, a Windows drive) and a private project's name (Cybernod, Ultrabusiness, whole words in any case), with character references and string escapes undone. It reads only rendered text for delivery vocabulary (the capitalised `Wave`, `Phase`, `Spike`), tracker codes (`W<n>`, `spec #`, `#<n>` of two digits or more) and the private plan's citations (`G.<n>`, `I.<n>`, `section G`, `plan section <letter>`): an HTML page's text outside scripts and styles, each page's Markdown and `llms*.txt` (text and code, not link destinations or heading ids) and every string of the search index. A finding fails the build.
