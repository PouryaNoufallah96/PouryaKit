## The retarget (#208, 2026-11-15; SDK 11.0.100, Microsoft.NETCore.App 11.0.0, CSharpier 1.4.0)

- **`global.json` decides the SDK**: SDK 10.0.402 and 11.0.100 sit side by side under mise's `dotnet-root`; after the pin moves, `dotnet --version` in the worktree prints 11.0.100 at once, no restore or install. Never run `mise install`.
- **NU1510 is a build error here** (warnings as errors): `Microsoft.NETCore.App` 11.0.0 ships `Microsoft.Extensions.Options`, `.Primitives` and the Caching, Configuration, DependencyInjection, Diagnostics, FileProviders, Hosting and Logging abstractions (10.0.x shipped none), so a `PackageReference` to one fails restore. `Microsoft.Extensions.DependencyInjection`, `.Hosting`, `.Http` and the other implementations are not in it and stay referenced. The build stops at the first projects that fail, so the next diagnostics (IDE0005, IDE0028) appear only after the NU1510 lines go.
- **SDK 11 adds `System.Net.Http.Json` to the implicit usings of net11.0**: every explicit `using System.Net.Http.Json;` fails IDE0005. Template content is outside the solution, so the build never flags its two (`CrossModuleTests.cs`, the shared `HostTests.cs`): grep for them.
- **IDE0028 now rewrites a comparer or copy-source constructor to `[with(...)]`**: `dotnet format style PouryaKit.slnx --diagnostics IDE0005 IDE0028` fixed exactly the build's 29 files; CSharpier then re-lays the eight `with` sites. Read each: in this tree every site kept its comparer or copied source; none was the `new(n)` plus `AddRange` shape whose fix drops the capacity.
- **CSharpier 1.4.0 re-lays 105 files** (a last lambda argument stays on the call line; `??` breaks before the operator). Proof it is layout only: compare each changed file with all whitespace removed against HEAD (`scratchpad/p208/layoutonly.py`); three files differ only by a trailing comma in a re-laid initialiser.
- **A reformat moves diagram citations like any edit**: nine diagrams needed re-ranged sources in the reformat commit and a pin commit after it. A difflib line map from HEAD to the working file, with each range's whitespace-stripped text compared before and after (`scratchpad/p208/remap208.py <worktree> [--write]`), flagged one range whose first line `??` merged (Dispatcher.cs) and was right. A citation whose numbers do not move but whose lines changed (PersistencePreparation.cs 18-160) still needs its diagram staged: `repin-diagram.py … --pin-only` to HEAD as the interim change, then the real pin.
- **The produced nuspecs prove the removals**: `dotnet pack src/<id>/<id>.csproj -c Release -o <scratch>` and read `<id>.nuspec` from the nupkg (`scratchpad/p208/nuspecs.py`); the eight packages list no removed dependency and a `net11.0` group. `PackageGraphTests.Produced_nuspecs…` uses a literal nuspec, red once the Dapper row changed; `validate.py`'s artifact step runs `PackageGraph.Violations` on the real ones.
- **Held on the 10 line, consumed from net11.0** (`Microsoft.AspNetCore.OpenApi` moved to 11.0.0 in #212, see [[web-security-and-openapi-facts]]): EF Core Relational and Design, `Microsoft.AspNetCore.OpenApi` and `dotnet-ef` 10.0.15 (their nuspecs carry a `net10.0` group only), Npgsql 10.0.3, its EF provider, EFCore.NamingConventions 10.0.1 and `Asp.Versioning.*` 10.2.3: restore and build clean, no NU1608.
- **The integration branch moved after my pins** (#211 re-pinned ci-and-publication mid-ticket): instead of `git rebase`, whose replayed pin commits conflict and pin commits the rebase orphans, stop any running validation (it refuses a checkout that changes), `git checkout -B ticket-<n> <new tip>`, `git cherry-pick` each code commit, re-pin after each with `repin-diagram.py`, and resolve the interim pin's conflict by writing the new HEAD as its revision. `git diff <old commit> <replayed commit> --stat` then shows only the tip's files and revision lines. The memory index's union merge doubles a line the tip changed: keep the tip's.
- **Docs that restate a moved pin**: section C's rows and the I.3 rows carry dated `*… until 2026-11-15*` notes in the style #167 and #207 used; the architecture document's sentences change in place; `docs/packages.md` states the `net11.0` assembly the artifact check reads.

## Feature adoption (#213, 2026-11-15; SDK 11.0.100, C# 15)

- **The SDK 11 CA rules are `none` at the default analysis level**; raised in `.editorconfig` they fire in the build: only CA2026 had sites (six `JsonDocument.Parse(x).RootElement` in tests, now `JsonElement.Parse(x)`; drop a `.Clone()` too). Proof each raised rule fires: a scratch file in `tests/PouryaKit.Core.Tests` with one offender per rule, built, then deleted. CA2028 fires on `if (r.IsMatch(t)) { var m = r.Match(t); }`, not on a ternary; IDE0410 fires on a `goto` to a label at the end of a loop body, not on a flag variable.
- **`public closed record ReportText(string Text);`** compiles (no `class` needed; `abstract` is implied and refused). The compiler emits `[IsClosedType(DerivedTypes = [..])]`, public in `System.Runtime.CompilerServices`, so a reflection test can pin the subtype list; a third in-assembly leaf fails the PDF switch with CS8509, and so does dropping `closed` (an open base needs a `_` arm), so that test's red run drops `closed` and adds a `_` arm together.
- **`dotnet test --timeout 45m`** is accepted before `--`; a run that reaches it exits 3 ("Aborted"). `Process.TryGetProcessById(int, out Process?)` (`[NotNullWhen(true)]`, throws for id 0 or less) and `Process.RunAndCaptureTextAsync(ProcessStartInfo, ct)` (both redirects required, `ExitStatus.ExitCode`) are in `System.Diagnostics.Process` 11.0.0; the ref pack's XML documents neither, so read the implementation with `ilspycmd`.
- **A package README quotes code lines**: the site's test failed when `.AddMeter(OperationTelemetry.SourceName, ChatClientSource)` grew two arguments in the service defaults (the Observability README quotes it); a second `.AddMeter(...)` call kept the quoted line and the README untouched. Run `pnpm --dir website test` after any sample edit.

## The docs pass (#214, 2026-11-15; SDK 11.0.100, C# 15, Microsoft.Extensions.AI 11.0.0)

- **C# 15 rules, probed in a scratch net11.0 project** (`scratchpad/p214/probe/`, `run_probe.py`): a switch over a `closed` type that names every leaf needs no `null` arm for a non-nullable input (the Kit's `PdfReport` switch has none); a nullable input without one fails CS8655 under warnings as errors; a `_` arm hides a new leaf, while naming every leaf turns it into CS8509. That holds for a switch expression only: a switch statement with a leaf missing and no default builds clean under warnings as errors and falls through at run time (`probe4/`, review R2 of #214). `[with(...)]` builds a `HashSet<T>` or `Dictionary<,>`; an `ISet<T>` target fails CS9174 ("not constructible"). The `field` keyword's CS9264 and the extension blocks' exported `<G>$`/`<M>$` nested types are unchanged on C# 15 (`probe2/`). Through its base, System.Text.Json writes only the base's members of a closed record (`{"Value":"Title"}` for a leaf with a second member) and reading it back throws `NotSupportedException` (abstract type) (`probe3/`); an empty base gives `{}`. A union with no attributes writes its case's value with no discriminator: `union Pet(Cat, Dog)` writes `{"Name":"Rex","Age":3}` and reading either case back throws `JsonException: JSON value type 'Object' is ambiguous for union type 'Pet'`, while `union Mixed(Cat, int)` round-trips both (`{"Name":"Tom"}` and `7`): it reads back only when no two cases share a JSON value kind (`probe4/`, review R1 of #214).
- **A version in a comment the skill quotes**: `ai.md`'s fence copies the sample handler's `#pragma` comment, so the comment, its two test copies and the skill's prose move together (a `.cs` comment needs a scope grant). `Microsoft.Extensions.AI` 11.0.0 keeps the reducers `[Experimental("MEAI001")]` (`ilspycmd -t Microsoft.Extensions.AI.MessageCountingChatReducer`).
- **Pins against prose, mechanically**: `scratchpad/p214/literals.py <worktree>` lists every `<package id> <version>` literal in the architecture document, `docs/packages.md`, the skill, the site pages and the package READMEs against `Directory.Packages.props` and the tool manifest; `literals_records.py` does the plan and the ADRs and says whether the line carries a 2026-11-15 note. "Since WolverineFx 6.51.0" and "on WolverineFx 6.46.0, not checked since" are history, not pins.
- **A memory version tag is a record**: re-tag only what a check re-observed (name the check and date), correct a recipe path that moved (`bin/Debug/net11.0`, a net11.0 scratch consumer), and drop only a language-version label that dates a feature.

## Settling the facts #214 left open (2026-11-15; SDK 11.0.100, Microsoft.Extensions.Hosting 11.0.0)

- **Hosting 11.0.0 reversed `Host.StartAsync`'s first two steps**: the startup validation (`ValidateOnStart`, and the new `IAsyncStartupValidator`) now runs before the hosted services are resolved, so before Wolverine's options and the Kit's `IWolverineExtension`s; 10.0.12 resolved them first. `StartingAsync`, where the Kit's startup checks run, still comes after both. A re-tag pass that only compares a cited type's name across versions misses an order change: diff the method body (`ilspycmd -t Microsoft.Extensions.Hosting.Internal.Host` on both packages). Details in [[wolverine-runtime-and-delivery-facts]] (Timing).
- **A closure claim is read from the restored graph**, not the nuspec: on net11.0 NuGet prunes every dependency `Microsoft.NETCore.App` 11.0.0 ships (`packagesToPrune` in `obj/project.assets.json`), so Npgsql 10.0.3 restores with none. `dotnet restore <one csproj>` in the worktree, then walk `targets["net11.0"]` (`scratchpad/memre/closure.py <assets> <id>` prints what only that id reaches). List an assembly's types one assembly per command (`ilspycmd -l c <dll> | grep`): two in one line give unlabelled output.

## EF Core 11 on the provider's release candidate (#215, 2026-11-15; EF Core and provider 11.0.0-rc.3, Roslyn 5.12.0)

- **Only one combination restores clean:** the provider's 11.0.0-rc.3 pins `Microsoft.EntityFrameworkCore` and `.Relational` to exactly `[11.0.0-rc.3.26522.148]`, so EF Core 11.0.0 stable beside it is NU1608 on the exact pin even with a direct Relational reference. Everything EF on that rc (Relational, Design, `dotnet-ef`) restores; `EFCore.NamingConventions` 10.0.1's `< 11.0.0` cap admits the rc, so no override.
- **Design 10.0.4 sits in every closure above `PouryaKit.Messaging.Wolverine.EFCore`** through `WolverineFx.EntityFrameworkCore` (minimum 10.0.4, NuGet takes the lowest): a direct Design reference in that package lifts it in every closure and nuspec. Then Roslyn collides where Design 11 (5.9.0+) meets `WolverineFx.RuntimeCompilation` (meta-packages pinning siblings exactly at 5.0.0): `Microsoft.CodeAnalysis`, `.Scripting` and, at 5.12.0, `.Workspaces.MSBuild` too (else MSBuild 5.9.0 pins `Workspaces.Common` 5.9.0), in `PouryaKit.Testing` and each Host's Debug group. WireMock.Net brings `Humanizer` 2.14.1 whose locale parts pin `Humanizer.Core` exactly; Design 11 needs 3.0.10: `Humanizer` 3.0.10 in the Gateway test project only. Templates restore clean with none of these of their own (the probe in `scratchpad/p215/probe215.py` reuses `validate.py`'s helpers: about 6 minutes).
- **EF Core 11 throws `MigrationsNotFound`** (added to the default warnings-as-errors in `RelationalOptionsExtension`) for `MigrateAsync` on a DbContext with no migrations; EF Core 10 logged it. **Provider 11's `NpgsqlDatabase.SaveChanges` rewraps 40P01 and 40001 as `DbUpdateConcurrencyException`** with the `PostgresException` inside, and it reaches the Unit of Work unwrapped; on EF Core 10 the execution strategy wrapped the deadlock as `InvalidOperationException` ("…likely due to a transient failure") around `DbUpdateException`. EF's own row-count conflict has no inner exception.
- **A release candidate drags others in as minimums** (review F1): EF Core rc.3 asks for `Microsoft.Extensions.Logging` and `.Caching.Memory` at rc.3, Design for `.DependencyModel` at rc.3, and stable Roslyn 5.9.0's `Common` for `Microsoft.CodeAnalysis.Analyzers` 5.9.0-1.26328.17; NuGet takes the lowest, so each stays a prerelease until a stable direct reference lifts it where EF Core (Persistence.EFCore) and Design (Messaging.Wolverine.EFCore) enter. The analyzer is a `developmentDependency`, yet a plain `PackageReference` to it still flows into the nuspec (no `suppressParent` in the assets). `PackageGraph`'s `TemporaryPrereleases` names the only prereleases allowed; scan every graph with `scratchpad/p215/prerelease.py <roots>`.
- **`has-pending-model-changes` traps:** Inventory through the monolith Host needs no `ConnectionStrings__broker` (with one, that Host leaves Inventory out and dotnet-ef cannot build the context); the Stub needs a temporary `IDesignTimeDbContextFactory` in the test project (`scratchpad/p215/pending.py`).
- **Re-ranging diagram sources:** never re-serialise a source with `json.dumps` (`module-boundaries` keeps `“` escapes); edit the numbers in the text and assert the parsed result (`scratchpad/p215/remap215.py <worktree> <path>... [--write]`, then `narrow.py` to drop a new comment line from a row's range).

**Why:** the retarget touched about 170 files; each of these cost a probe or a second run.
**How to apply:** for any later step of the .NET 11 move (#209 to #217), a new package on SDK 11, or a CSharpier bump. Related: [[templates-packaging-and-publication-facts]], [[docs-verification-tools]], [[worktree-shell-and-check-gotchas]].
