## Typed IDs and records under System.Text.Json (#6, 2026-10-05; SDK 10.0.401)

- System.Text.Json does NOT apply `[JsonConverter]` declared on an abstract base record to derived types; a derived typed ID serialized as `{"Value":...}`. So the converter must sit in the options' `Converters`; since #34 that happens only through Domain's `options.UsePouryaKitJson()` (Web and Wolverine call it), and since #81 `TypedIdJsonConverterFactory` is internal, so the compiler (CS0122) refuses any other construction; Domain has no `InternalsVisibleTo`, so tests match it by full name.
- STJ deserializing a positional derived record still sets the base record's public `init` properties (DomainEvent `Id`, `OccurredOn`) after the constructor runs, so identity and time survive a round-trip with no `[JsonConstructor]`.
- `sealed record ProductId(Guid Value) : TypedId<Guid>(Value)` with a getter-only `Value` on the base compiles warning-free and synthesizes no second `Value` property.

## Shared JSON options (#34, 2026-10-07; ASP.NET Core 10.0.12, WolverineFx 6.46.0)

- `Microsoft.AspNetCore.Http.Json.JsonOptions.SerializerOptions` is **getter-only**, so a Kit "factory" can only configure the instance ASP.NET hands over (`ConfigureHttpJsonOptions`), never replace it. Its defaults: `JsonSerializerDefaults.Web` (camelCase, case-insensitive, AllowReadingFromString) plus `UnsafeRelaxedJsonEscaping`.
- Wolverine `UseSystemTextJsonForSerialization(Action<JsonSerializerOptions>)` starts from `SystemTextJsonSerializer.DefaultOptions()` (camelCase, case-insensitive, trailing commas, comment skip, relaxed encoder), and the `SystemTextJsonSerializer` constructor **appends** `CustomJsonConverterForType` to the options it gets: never hand it a shared or already-used instance.
- Hence the Kit's shape: `options.UsePouryaKitJson()` (Domain, `JsonSerializerOptionsExtensions`) configures and returns a given instance; both frameworks call it in their own lambda.
- `wolverine_incoming_envelopes.body` is the whole envelope: `EnvelopeSerializer.Deserialize(byte[])` (public) gives `.Data`, the message JSON; `IWolverineRuntime.Options.DefaultSerializer.ReadFromData(type, envelope)` reads it back with the Host's real serializer. That proves serialization where the first local attempt only hands over the in-memory instance. Handled rows stay 5 min, so read them after `WaitUntilDeliveredAsync`.
- Without the Kit's options, Wolverine stored a typed ID as `{"value":"<guid>"}` and delivery still succeeded: only a representation check catches the drift.
- A C# 14 `extension(T)` member compiles to a static method on the outer class; `Il.CallsIn` resolves calls to it and `nameof(Outer.Method)` compiles. `GetConstructors(Static|NonPublic)` includes `.cctor`, so field initializers are scanned.
- ASP.NET Core 10's HTTP JSON default encoder is already `UnsafeRelaxedJsonEscaping` (decompiled `JsonOptions.DefaultSerializerOptions`), so setting it in `UsePouryaKitJson` changed nothing for HTTP.

## PouryaKit.Core helpers (#37, 2026-10-07)

- **A C# 14 `extension<T>(...)` block emits public nested types** (``Outer+<G>$<hash>`1`` and `+<M>$<hash>`), `IsSpecialName` true but no `[CompilerGenerated]`. `GetExportedTypes()` lists them, so any public-type count or list must drop names starting with `<`.
- **A new `src/` package breaks the architecture tests until they reference it:** `Sample.KitPackages` calls `Assembly.Load(folderName)` for every `src/*` folder. Also bump `PackageGraphTests`' package count, add a `PackageGraph.Table` row, and add it to `scripts/packaging/inventory.json` (validate.py, publication workflow and the inventory controls all read that file; nothing else enumerates packages).
- **Negative case for a package-shape rule:** `tests/PouryaKit.ArchitectureTests/Offending.Core` compiles `..\..\..\src\PouryaKit.Core\*.cs` (Compile Include with LinkBase) plus one extra public type; the arch csproj references it with `Aliases="OffendingCore"` and `extern alias` so its same-named types do not clash. Add the folder to the arch csproj's `Compile Remove`/`None Remove` and to the slnx.
- **Expression parameter substitution must not reuse a given parameter** (review finding, #37 fix round): replacing the right lambda's parameter by the left one's rebinds a nested lambda in the right body that declares the left's `ParameterExpression` instance (`p > q` became `p > p`). Put both bodies on a fresh `Expression.Parameter`; a lambda-written test cannot reproduce it, only a hand-built tree sharing the instance.

## ImplementingTypes lookup (#55, 2026-10-07)

- **`ImplementingTypes.Of` never returns an abstract class or an open generic definition**, so a registration that rejects those (Cqrs's generic handlers, Security's permission on an abstract or generic type, Messaging.Wolverine's generic Notification Handler) cannot use it. The first brief stopped on that; the orchestrator added `ImplementingTypes.Candidates`: every class the contract describes, abstract, open generic and compiler-generated included, interfaces and structs out. Excluding compiler-generated classes was a review high (F2): the old scans never did, so a marked type would have been skipped silently. Match the old enumeration exactly, and record a widened Core contract as a dated note on the plan's I.3 row (F1). `Of` and `Candidates` share private `ThrowIfNotAContract` and `Describes`.
- **`Assembly.GetTypes()` order is `MetadataToken` order (declaration order), and tests depend on it:** `NotificationTests.Startup_fails_on_a_missing_an_invalid_or_a_duplicate_name` pins which of two clashing Domain Events is named first. Full-name order flipped it. Cqrs and Messaging.Wolverine re-sort `Candidates` by `MetadataToken` (Cqrs by assembly position first) to keep the old order; Web accepts full-name order.
- **`Candidates(typeof(object), assemblies)` means every class**: Cqrs and Security use it, because Security must see the attribute on a type that is no Operation.
- An iterator method gives a `[CompilerGenerated]` class implementing `IEnumerable<T>`, a cheap fixture for the compiler-generated case.
- `TypeLookupTests` reads the IL for `Assembly.GetTypes`, `get_DefinedTypes`, `get_ExportedTypes`, `GetExportedTypes`, `get_Modules`, `GetModules`, `Module.GetTypes` and `Module.FindTypes`; ordinal sort puts `GetX` before `get_X` in the expected list.
- Adding a Kit project reference also changes `PackageGraphTests`' inline Dapper nuspec. A Host-killing test, `IntegrationEventTests...died_before_acknowledging_it_is_applied_once`, failed once in validate.py with a delivery turned away twice (the Solo recovery race); the rerun passed.
- **Wolverine's shape rejections had no test** before #55's fix round. Any type added to `ModularMonolith.Tests` itself breaks the fixture Host (the Stub Module scans that assembly), and a new fixture project needs a slnx entry. The stand-ins went into the existing `Misnamed` project, and the two startup tests split its message on the `" is a Notification Handler of "` marker. The naming test's name is cited in ADR 0006, so do not rename it.

## Architecture tests (#19, 2026-10-06)

Check `tests/PouryaKit.ArchitectureTests` before relying on the design.

- **IL scanning needs no package.** `MethodBody.GetILAsByteArray()` plus an opcode table built from `OpCodes` fields, tokens resolved with `Module.ResolveMethod(token, typeArgs, methodArgs)` / `ResolveString`. Async methods and lambdas live in compiler-generated nested types (`<Handle>d__0`, `<>c`): scan `assembly.GetTypes()` (nested included) and attribute to the outermost declaring type. A mutation that skipped `<`-named types failed both the fixture and the positive anti-vacuous checks.
- **Transport check** reads `MetadataReader.TypeReferences` (System.Reflection.Metadata, BCL): names every Wolverine/JasperFx type an assembly's code or signatures touch. The compiler drops an unused assembly reference, so a fixture must really use the forbidden type.
- **Sample Module discovery:** `DependencyContext.Default.RuntimeLibraries` with `Type == "project"` gives the repo's own assemblies; walk the Host's references through them only (walking NuGet assemblies can fail to load).
- **EF models with real table names:** build `ModularMonolithHost.CreateBuilder([... "--ConnectionStrings:app=Host=localhost;Database=x"])` + `ModularMonolithHost.Build`, never start; resolve each internal DbContext by `Type` from a scope; `GetService<IDesignTimeModel>().Model` (namespace `Microsoft.EntityFrameworkCore.Metadata`). A hand-built options object would miss snake_case and the schema.
- **`project.assets.json`:** `libraries` of type `project` is transitive; direct project refs are `project.restore.frameworks.<tfm>.projectReferences`, direct packages `project.frameworks.<tfm>.dependencies`. Nuspec path = `packageFolders[0]` + library `path` + the `.nuspec` in `files`.
- **Routing answers 405 and 415 itself** with an empty body ("415 HTTP Unsupported Media Type" endpoint), before any endpoint or exception handler: `ThrowOnBadRequest` does not reach it. Web now registers status code pages through an `IStartupFilter`.
- **Recovery race between test Hosts:** the fixture Host and any Host a test composes all run Solo as node 1 on one store, so a dead Host's delivery can be recovered by two live Hosts at once (seen once in ten runs: 3 attempts instead of 2; the Receipt kept one effect). Count attempts as a range, or assert effects, when a test kills a Host while the fixture Host runs.
- **Distinct node numbers cannot fix the Solo double recovery** (#19 fix round, decompiled 6.46.0): `NodeAgentController.StartSoloModeAsync` hard-codes `AssignedNodeNumber = 1` and first calls `ReleaseAllOwnershipAsync()` (a starting Solo Host releases every live Host's rows); `DurabilitySettings.AssignedNodeNumber` has an internal setter; `RecoverIncomingMessagesCommand` loads owner-0 rows with a plain select and `MessageDatabase.ReassignIncomingAsync` updates by id with no `owner_id = 0` guard, so two live pollers both take a row whatever their numbers.
- F4: a ProjectReference no emitted code uses leaves no AssemblyRef; read the restored closure (`RestoredPackage.Of(csproj)`, project paths from the Host's `project.assets.json` `libraries[*].path`).
- EF Core 10 declares `ExecuteUpdate(Async)`/`ExecuteDelete(Async)` on `EntityFrameworkQueryableExtensions` (Microsoft.EntityFrameworkCore namespace).
- Test-only failure injection without touching a Module: `DeliveryProbes.FailAfterReceipt(subscription)` throws in the `IReceipts` decorator after the Receipt is recorded. The Stub Module registers its validators (`AddPouryaKitValidation`) since #19.
- Suite time (230 tests, ~30 s): one PostgreSQL container per run (not per test), ~5 s fixed start, ~17 s in 25 tests whose waits are the mechanism (retry delays and polling in `PouryaKit.Testing`, stale times, second Hosts). Tests run sequentially (`CollectionPerAssembly`).

## Pipeline contract rule (#54 slot rule, 2026-10-08)

In `PipelineContractTests` and `ModuleRules.ImplementsPipelineContracts`.

- **`type.IsAssignableTo(typeof(IValidationStep<>))` is always false.** Match an open generic contract with `type.GetInterfaces().Any(i => i.IsGenericType && i.GetGenericTypeDefinition() == contract)`; an open generic class (``FluentValidationStep`1``) is caught that way, and its `FullName` keeps the backtick.
- **The set is the pipeline's entries and seams**, 14 contracts. The orchestrator decided (2026-10-08) that `IDispatcher` and `IGatewayProcessor<T>` belong: Feature code calls them, but an application decorator is a pipeline step by another name; `IDispatcher` has two Kit implementations (Cqrs's `Dispatcher`, Observability's `ObservedDispatcher`), the rest one each. `IUniqueConstraintReader` (Persistence.EFCore, filled by Persistence.Postgres's internal `PostgresUniqueConstraintReader`) joined after review R1 (2026-10-08): when sizing the set, also sweep contracts a non-Cqrs Kit package fills for the Unit of Work. Left out on purpose: `IRequiresQueryCache` (every `ICacheableQuery` of the sample implements it transitively, so an assignability rule flags legitimate queries), composition-time contracts (`ICompositionCheck`, `IStartupCheck`, `IModuleServices`, `IRequiresAuthorizer`: they add nothing to the pipeline), `HostComposition` (sealed, internal constructor), sealed classes of the calling rule (`DomainEventDrain`, `TrackedState`).
- **Both Hosts since #54.** The arch-test csproj references `Inventory.Host` too, and `Sample.Application` is both Hosts plus every repository project they reach whose name does not start with `PouryaKit` (Modules, Contracts, `ModularMonolith.ServiceDefaults`); the rule judges that. `Sample.Modules` still comes from `ModularMonolith.Host` only, so the older rules were unaffected. A static field initializer that uses another static field must come after it in the class.
- **A rule that names the source file would differ between builds:** sample and test projects have a portable PDB beside the dll, Kit packages an embedded one, and `validate.py` builds with `ContinuousIntegrationBuild=true`, so document paths become `/_/…`. The rule reports the assembly's file name instead.

## The namespace rule (#77, 2026-10-09; SDK 10.0.401, ASP.NET Core 10.0.12)

In `NamespaceTests` (ADR 0010).

- **Generated top-level definitions outside a Kit package's namespace exist in 11 of 20 packages** (35 at `1a5803e`), not the two the ticket named: `[CompilerGenerated]` `<PrivateImplementationDetails>`, `<>f__AnonymousType*` and the collection-expression types `<>z__ReadOnlyArray/List/SingleElementList` in the global namespace; `[GeneratedCode]` only on the `GeneratedRegex` output (`System.Text.RegularExpressions.Generated`) and on ASP.NET Core's OpenAPI XML comment generator output (`Microsoft.AspNetCore.OpenApi.Generated` and an `InterceptsLocationAttribute` in `System.Runtime.CompilerServices`), which runs in any project that reaches `Microsoft.AspNetCore.OpenApi`, even transitively (`Offending` gets it through Catalog). Exclude by both markers and judge top-level types only: their nested types (`+Enumerator`, the regex `RunnerFactory`) carry no marker. The arch-test assembly also holds a generator's `Microsoft.CodeAnalysis.EmbeddedAttribute` with neither marker; a Kit package that gains such a generator would fail the rule by name.
- **Listing a compiled assembly's types without loading its dependencies:** a scratchpad console app over `System.Reflection.Metadata` (`PEReader`, `TypeDefinitions`, `GetDeclaringType().IsNil`, custom attribute constructor parents) reads every dll in the arch-test bin in under a second.
- **A namespace rule needs two negatives (review R1 of #77):** `Offending.Core`'s namespace is unrelated to its assembly name, so alone it passed a prefix check (the reviewer's mutation). `Offending/Stray/StrayType.cs` (`Offending.Stray`, internal, no member) adds the sub-namespace case; with only sub-namespaces rejected, `Offending.Core` fails instead, so both stay. An internal empty type in `Offending` leaves every other Module rule's exact assertion unchanged, and a folder-matching namespace needs no IDE0130 `none`.

## Folder moves and type identity (#78, 2026-10-09; SDK 10.0.401)

- **Commit the `git mv` moves alone, then the companion-type splits.** Over the whole range, `git diff -M` pairs a split file with whichever new file took most of its bytes: `FilterOperator.cs => Paging/FilterOperatorNames.cs` (63%) and `PouryaKitCorsOptions.cs => Defaults/PouryaKitCorsPolicy.cs` (56%), and lists the real `Paging/FilterOperator.cs` as new. The moves commit alone shows 97 `R100`; the split commit alone shows each file in place. Derive a citation mapping from the move list or the moves commit, never from the range's renames: a script that did pointed the CORS record at the wrong file.
- **A declaration moved into its own file can leave an unused using**, which IDE0005 fails (warning as error in `src/`): the using moves with it (`System.Globalization` with `FilterField`, `PouryaKit.Cqrs` with `UnmappedApiVersionsCheck`). A namespace one level up (`PouryaKit.Web` from `PouryaKit.Web.OpenApi`) needs no using.
- **Type-identity proof:** the `System.Reflection.Metadata` lister above, per assembly a sorted list of exported full names and of every definition with its visibility, before and after; `diff -r` empty. C# 14 extension blocks emit exported grouping types (`FilterOperatorNames+<G>$<hash>`) whose names are content hashes, stable across a move. An incremental `dotnet build` after `git mv` recompiles the moved packages (check the dll times).

## Duplicate properties (#86, 2026-10-10; .NET 10.0.12 STJ)

- **`AllowDuplicateProperties = false` (in `UsePouryaKitJson` since #86) honours `PropertyNameCaseInsensitive`:** `name` and `Name` both mapping to one member throw `JsonException` "Duplicate property 'name' encountered during deserialization of type 'Ns.T'." (full name). Under `JsonUnmappedMemberHandling.Skip`, a member the type lacks is skipped even when it appears twice. The default (true) reads last-wins. Probed with a file-based `dotnet run probe.cs` (`#:property PublishAot=false`).
- **Writing a duplicate on purpose:** `[JsonExtensionData] Dictionary<string, object>` entries are written after the members with no name check, so a record with `Name` plus `["Name"] = "x"` serializes `"name"` and `"Name"`, even under the strict wire options. A `[JsonPropertyName]` that collides ignoring case throws `InvalidOperationException` ("collides with another property") on write instead.

## The typed-ID factory (#99, 2026-10-10; SDK 10.0.401, Release)

- **`TypedId.From` builds a compiled `Expression.New` lambda once per ID type** (it was `ConstructorInvoker.Invoke(object)`, which boxed the value). A million `From<Guid ID>` calls: 14.0 ms and 64 B a call before, 6.5 ms and 32 B after, the same as `new`. The one-time cost grew: the first ID type's factory 1.1 ms to 7.9 ms (the expression compiler loads), each later type 31 to 148 us. The compiled lambda calls a non-public constructor too, and passes the constructor's own `ArgumentException` through unwrapped. Harness: a console project in the scratchpad with absolute `ProjectReference`s to the worktree's packages, `dotnet run -c Release`.
- **Allocation test of an ID factory:** after one warm-up call, 1,000 `From` calls allocate exactly what 1,000 `new` calls do (32,000 bytes in Debug for a Guid ID); the boxing version allocated 64,000.

## The Dapper tenant rule (#118, 2026-10-17; SDK 10.0.402)

- **A `const` interpolated into `$"..."` with only const holes is folded at compile time:** `ListProducts`' `$"select … {From}"` reaches the IL as one complete `ldstr` per SELECT and COUNT, and the `const From` itself is never a literal. A `static readonly` fragment concatenated at run time would be its own literal, so a SQL rule must judge a fragment that names a table (the tenant rule rejects it as "is not a SELECT").
- **Which Modules are tenant-scoped:** `Sample`'s static constructor builds the Host once and reads `HostComposition` (registered by the composition checks) beside the models; the Offending Module is never composed, so its test passes Catalog's tenant tables directly, as `DapperWriteTests` passes the aggregate tables.
- **A mutation that disables a check must stay compilable under TreatWarningsAsErrors:** `if (false && …)` is CS0162 (unreachable code); use a runtime-false guard such as `where.Length < 0 && …`.
- **A regex SQL reader is beaten by syntax it does not model** (#118 dual review, 4 findings): `and` inside `CASE … END`, a predicate inside `$$…$$` read as code, `from (a p cross join b c)` hiding the first relation, a keyword inside `"limit"` ending a clause early. The owner's direction: a fail-closed rule rejects what it cannot parse (fault messages for each) rather than parsing more; blank double-quoted identifier bodies before keyword scans, but keep them for name matching.
- **Context discovery plus a deny-list lost four more times** (#118 second review: `@limit` ending the WHERE, `TABLE x` finding no read, a nested `/* /* */ */`, a column-alias list `c(id, tenant, …)`). What held: tokenise (block comment, `$`, backslash, unknown character are faults), then an allow-list grammar over tokens. Discovery "by name anywhere" breaks on a Module's non-SQL literals (Catalog: `"/products"`, the cache tag `"products"`, the permission `"catalog.products.remove"`, `ToTable("products")`), so gate it on a SQL word (command word, `from`, `join`) in the raw text. Don't tokenise comment bodies for discovery: a `'` inside a comment swallows real code; scan raw words instead. `U&"!0070roducts" UESCAPE '!'` spells a name without its letters.
- A SQL shape rule needs one weaker-predicate mutation per offending shape: each shape was caught by more than one check, so removing one check only changed the violation's wording; the meaningful red runs model the weaker rule (substring anywhere, OR split as AND, only the first branch of a set operator, one table of a join enough).

**Why:** each decides the shape of a public Kit type, a structure rule or a test that would otherwise pass vacuously; guessing wrong costs a public-API rewrite.
**How to apply:** when a ticket wires JSON (through `UsePouryaKitJson`), EF or Dapper for typed IDs or Domain Events, build on these instead of re-probing; re-probe only after an SDK band change. For idempotency-style payloads create options with `new JsonSerializerOptions().UsePouryaKitJson()`: the structure rule allows that and nothing else. Also when adding a Kit package (update `PackageGraph`'s table), a structure or public-type rule, an offending fixture, a Kit registration that finds types, a refactor that changes the order types are enumerated in, a Kit project reference, a rule over implemented types or the slot set, or a test that kills a Host.
