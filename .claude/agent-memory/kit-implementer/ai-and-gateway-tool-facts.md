## The chat client and the Gateway tool (#135, 2026-10-18; Microsoft.Extensions.AI 10.11.0, OpenAI 2.14.0, System.ClientModel 1.15.0)

- **`FunctionInvokingChatClient` at the cap** (`MaximumIterationsPerRequest`, default 40): at iteration == cap it strips the tools from the request (`PrepareOptionsForLastIteration`) and invokes nothing the answer asks for, so a model that always calls a tool gets `cap` invocations and `cap + 1` requests. A call of a tool not in `ChatOptions.Tools` is answered `Error: Requested function "X" not found.`; a throwing function `Error: Function failed.` (message only with `IncludeDetailedErrors`), and the fourth iteration in a row with a failed call rethrows (`MaximumConsecutiveErrorsPerRequest` 3). A returned value (a failed `Result` as JSON) is no error. Source read with `gh api repos/dotnet/extensions/contents/<path>?ref=v10.11.0`.
- **The OpenAI client retries on its own**: System.ClientModel's default `ClientRetryPolicy` retries 503 three times (honouring `Retry-After: 0`), so a stub 503 saw 4 requests. `RetryPolicy = new ClientRetryPolicy(maxRetries: 0)` leaves the Host's pipeline the only one; with the service defaults a POST then goes once. A second `AddPouryaKitResilience()` on the named client throws `InvalidOperationException` when it is created (Web's `SingleResilienceHandler`).
- **IHttpClientFactory for a singleton client**: `new HttpClientPipelineTransport(factory.CreateClient(name))` keeps one HttpClient, so the named client gets `UseSocketsHttpHandler((h, _) => h.PooledConnectionLifetime = 2 min).SetHandlerLifetime(Timeout.InfiniteTimeSpan)`, the documented long-lived pattern.
- **Three providers, one client**: Azure OpenAI's v1 API takes `new OpenAIClient(new ApiKeyCredential(key), new OpenAIClientOptions { Endpoint = new("https://<resource>.openai.azure.com/openai/v1/") })` (learn.microsoft.com, Azure OpenAI v1 API); Ollama `http://<host>:11434/v1` with any non-empty key (`ApiKeyCredential` refuses an empty one).
- **Options validation with one failure per row**: write provider-specific rules as `ai.Provider is not (A or B) || …`, or an undefined `Provider=99` also fails the key rule. An empty `--PouryaKit:AI:Endpoint=` binds a null `Uri`.
- **`AIJsonUtilities.CreateJsonSchema` with the Kit's JSON**: `SharedJsonTests` forbids any `JsonSerializerOptions` setter outside Domain, so lock the options with `MakeReadOnly(populateMissingResolver: true)` (a method, allowed) in the method that applies `UsePouryaKitJson`, and add that type to the test's two owner lists.
- **Trust of a tool call**: `run.Continue()` per invocation is trusted only inside the authorized Operation `run` belongs to (a handler injecting its `OperationContext`), so a permission-declared tool runs without its permission check there (G.6); from a fabricated context it is untrusted and `PermissionAuthorizer` denies an Actor without the permission. A denied permission as a failed tool result therefore needs a run outside an Operation. `RecordCatalogQuestionContext` (Stub's `IAuthorizer<GetProductQuery>`) records each tool call's context, by correlation.
- **Dapper tenant rule over prompts**: a string literal in a tenant-scoped Module naming `products` beside a SQL word (`with`) is read as SQL and fails `DapperTenantTests`; word a model's instructions around table names.
- **Stub server**: a Kestrel `WebApplication.CreateSlimBuilder()` on `http://127.0.0.1:0` mapping `POST /v1/chat/completions` with `id`, `object`, `created`, `model`, `choices[{index, message{role, content, tool_calls[{id, type:function, function{name, arguments as a JSON string}}]}, finish_reason}]`, `usage` is enough for the OpenAI client; `app.Urls.Single()` holds the bound port after start.
- **The Ollama probe**: `Testcontainers.Ollama` 4.15.0, `new OllamaBuilder("ollama/ollama:0.40.6")`, `ExecAsync(["ollama","pull","qwen2.5:0.5b"])`, `GetBaseAddress()` ends in `/`, so the endpoint is `{base}v1`. The image is 7.07 GB on arm64; the first run with no image took 7 min 22 s, and qwen2.5:0.5b called GetProduct and named the product. `Assert.SkipUnless` reports skipped and MTP exits 0.
- **Template ripple of a Gateway-bound Catalog feature**: the monolith has no Modularity, so `content/monolith/.template.config/template.json` excludes the folder, `TemplateTests.Unreplaced` lists each excluded file and the monolith Catalog csproj pair drops the package; the modular template's Catalog csproj, Host csproj, `Directory.Packages.props`, `AppHost.cs` and `appsettings.json` gain it; `inventory.json`'s template-monolith `excluded` names it.
- **execution-core had room for one more node**: Core narrowed from 1110 to 820 frees (910, 700) under Modularity; `ai-modularity` top to bottom and an `ai-cqrs` with no sides passed every gate. A `via` must leave and enter perpendicular to the sides it names, and ports sit at side centres. kit-context round-trips through `json.dumps(indent=2, ensure_ascii=False)`, execution-core does not (edit it as text). Tools: `scratchpad/p135/trial135.py` (move, size, add, finalize into the scratchpad), `diagrams135.py`.

- **"Keeps the Host's one pipeline" needs exactly one, not at most one** (#135 review F1): a single 503 request also passes with no resilience handler at all. Count `ResilienceHandler` in `IHttpMessageHandlerFactory.CreateHandler(name)`'s chain (walk `DelegatingHandler.InnerHandler`): `Assert.Single` is red with `RemoveAllResilienceHandlers()` on the client (EXTEXP0001 pragma) and throws with a second `AddPouryaKitResilience()`. The service defaults' tracing must add `Experimental.Microsoft.Extensions.AI` (source and meter) or no model-call span is exported (F2).

## Agents over the Host's client (#136, 2026-10-18; Microsoft.Agents.AI and .Workflows 1.25.0)

- **`ChatClientAgent` keeps the Host's function invocation**: its constructor's `WithDefaultAgentMiddleware` builds on `chatClient.AsBuilder()`, adding approval decorators and an inert `DeferredOpenTelemetryChatClient` outside the Host's client, and adds a `FunctionInvokingChatClient` only when `GetService<FunctionInvokingChatClient>()` finds none (a `DelegatingChatClient` such as `ToolAllowList` forwards `GetService`). So the allow-list, the cap and any step inside the Host's client apply to every agent. Source read at tag `dotnet-1.25.0` of microsoft/agent-framework with a scratchpad script calling `gh api repos/<r>/contents/<path>?ref=<tag>` (`p136/fetch.py`).
- **A handoff workflow's tools are declarations** (`AIFunctionFactory.CreateDeclaration("handoff_to_<n>")`, added through run options): a name-based allow-list withholds them and the handoff never routes. `ToolAllowList` passes `AIFunctionDeclaration and not AIFunction`, which function invocation hands back to the caller; MCP tools (#137) are `AIFunction`s and stay under the list.
- **Trust flows into workflows**: `InProcessExecution.Default` is off-thread, yet each agent's tool call inside a handler was `IsTrustedContinuation` (the `AsyncLocal` of `AuthorizedOperation` flows into the started tasks). Concurrent agents call one recorder at once: lock a shared `List` in a test authorizer.
- **Experimental surface**: MAF's `AgentSessionStore` (MAAI001) and the reducers `MessageCountingChatReducer`/`SummarizingChatReducer` (MEAI001) are `[Experimental]`; `AIContextProvider`, `InMemoryChatHistoryProvider`, `SerializeSessionAsync`/`DeserializeSessionAsync` are stable. The Kit's port `IAgentSessionStore` avoids exposing MAAI001; tests and docs disable MEAI001 locally.
- **Closure**: Microsoft.Agents.AI brings Microsoft.ML.Tokenizers 2.0.0 (and Google.Protobuf 3.30.2), M.E.AI.Evaluation, Compliance and VectorData abstractions, FileSystemGlobbing, ObjectPool; Workflows brings OpenTelemetry.Api 1.18.0 (Apache-2.0). All pass `LicenceTests`; `Microsoft.Agents.AI.Hosting` is prerelease only.
- **ChatStub streaming**: with `"stream": true` the OpenAI client wants `text/event-stream` lines `data: {chat.completion.chunk with choices[{index, delta, finish_reason}]}` and `data: [DONE]`; a streamed tool call's entries need `index`. Concurrent agents need a reply chosen from the request body (`Script(Func<JsonElement, ChatReply>)`); an assistant message that only calls tools has no `content`.
- **Shapes seen against the stub**: a structured run sends `response_format.type = json_schema`; `SummarizingChatReducer(chat, 1, 0)` on [user, assistant] sends one summary request, then [summary, last assistant, new user]; the Kit's JSON writes `ActorKind` as a number; `AsAIAgent(...).RunAsync` inside a recurring command's handler carries `Actor.System(name)` with no tenant, so the tool must be a non-tenant-scoped Module's (Stub's `ReadOperationContextQuery` answers the context as JSON).
- **A singleton that resolves an application's services once needs a lifetime check at build**: the client takes every `IChatGuardrail` from the root provider when it is built, so a scoped one threw only at the first run (Development) or became captive; `SingletonGuardrailsCheck` (an `ICompositionCheck` beside Cqrs's `OneProviderCheck<IChatClient>`) names each non-singleton. Caught at the advisor's pre-report pass, after the first validation: plan such a check with the type, since it moves a cited range and costs a re-pin and a second `validate.py`.
- **`ChatOptions.Instructions` is sent beside the messages** (#136 review F1): `OpenAIChatClient` yields `new SystemChatMessage(instructions)` before the messages, and an agent's instructions and its context providers' `AIContext.Instructions` arrive there, not in the message list. A hook that checks "what is sent" must prepend them as that system message; a test hook that ignores its inputs cannot catch the gap, so give one test a hook that refuses on content.
- **Diagram cost of one PackageGraph row**: keep the edit line-neutral (one comment line, a long package line) so no range moves; any change at line 105 still forces a re-pin of the four diagrams citing PackageGraph ranges at or below it (execution-core, kit-context, messaging-and-delivery, module-boundaries). The merger tools in `.claude/handoff/<session>/tools/m131/finalize.py` refinalize by slug.

## MCP clients (#137, 2026-10-18; ModelContextProtocol.Core, .AspNetCore 2.2.0)

- **`ModelContextProtocol.Core` is the whole client** (`McpClient.CreateAsync`, `StdioClientTransport`, `HttpClientTransport`, `McpClientTool : AIFunction`); the umbrella `ModelContextProtocol` only adds server hosting and DI. On net10.0 Core adds nothing else to PouryaKit.AI's closure. Read the API from the nupkg's XML docs (`lib/net10.0/*.xml`) with a Python regex over `<member>`.
- **The 2026-07-28 MCP revision dropped sessions from Streamable HTTP**, and an AspNetCore server is stateless by default: a client sends no `Mcp-Session-Id` and disposal sends no DELETE. To prove a session ends, the test server sets `WithHttpTransport(o => o.SessionMode = HttpServerSessionMode.Stateful)`; the client downgrades to the initialize handshake and holds a session.
- **`WithTools(typeof(X))` registers nothing**: it binds the generic `WithTools<T>(T target)` with `T = Type`, and every call fails `Method 'tools/list' is not available`. Use `WithTools([typeof(X)])` (the `IEnumerable<Type>` overload); a static tool class cannot be `WithTools<X>()`.
- **A stdio test server as a child process**: an Exe project inside `tests/ModularMonolith.Tests/<Folder>` (compile-removed there, project-referenced, in the slnx), started as `dotnet typeof(X).Assembly.Location`, as StreamHost is. `Host.CreateEmptyApplicationBuilder(null)` writes no logs to stdout. The server ends within milliseconds of stdin closing, but the SDK's disposal never closes it first: `StdioClientSessionTransport.CleanupAsync` waits `ShutdownTimeout` (5 s by default) for the process to exit, then kills its tree, and closes the streams last, so each Host disposal with a connected stdio server costs about 5 s whatever the server does (#137 review F5, SDK source at commit `6fa38259`). `dotnet <dll>` runs the app in the muxer's process, so `Environment.ProcessId` is the started process.
- **`StdioClientTransportOptions.InheritEnvironmentVariables` is true by default**: the child gets every secret of the Host's environment. The Kit sets it false and passes `StdioClientTransportOptions.GetDefaultEnvironmentVariables()` (PATH, HOME, SHELL, TERM, USER, LOGNAME) plus the configured ones; `dotnet` still resolves through PATH.
- **`EnableStandaloneGetStream = false`** on the HTTP transport, so the service defaults' 10 s attempt timeout never cuts a long-lived GET.
- **Diagram cost**: the registration lines in `AddPouryaKitAI` sit above execution-core's cited `Create` range, and a GLOSSARY entry after Gateway tool moves kit-context's and messaging-and-delivery's GLOSSARY ranges: plan the range moves with the edit (scratchpad `p137/rerange137.py`).

## The MCP review fix round (#137 F1 to F6, 2026-10-23; ModelContextProtocol.Core 2.2.0)

- **SDK source** at the nuspec's commit: `gh api repos/modelcontextprotocol/csharp-sdk/contents/<path>?ref=6fa3825973949a9c4f0cd8af344e15a8db09dc35`, base64 `content` (scratchpad `p137f/fetch.py`; a listing of a directory gives its files).
- **`HttpClientTransport.DisposeAsync` only disposes an owned `HttpClient`**, and `McpClient` disposes the session transport `ConnectAsync` returned, never the `HttpClientTransport`: pass a factory client unowned (the constructor's default), not `ownsHttpClient: true` with nothing disposing the transport.
- **A dead stdio server's listing fails with `IOException`** (the write to its closed pipe, "MCP server process exited unexpectedly"), possibly before `McpClient.Completion` has completed, so evict by the exception: anything but `McpProtocolException` (the server's own JSON-RPC error answer) and the caller's cancellation. An HTTP 404 on a session id is an `HttpRequestException` and disconnects the transport.
- **A deterministic failed connect**: a `WorkingDirectory` that does not exist yet fails `Process.Start`, and the SDK throws `IOException("Failed to connect transport.")`; create the directory and the next listing connects.
- **Seeing a connection under way**: the stdio test server writes a file named by its pid into a directory an `Environment` variable names (one file per start: concurrent appends to one file from several processes collide on .NET's advisory lock), and waits for a hold file before answering. Release a held start within 5 s: `DiscoverProbeTimeout` then falls back to `initialize`, and `InitializationTimeout` is 60 s, which is what a disposal that waited for the connection would cost.
- **An AspNetCore server answers a DELETE of an unknown session with an empty 200**, so the DELETE's status proves nothing. Ask the server instead: a POST `{"jsonrpc":"2.0","id":"probe","method":"ping"}` with `Mcp-Session-Id`, `Accept: application/json, text/event-stream` and no protocol header gets 200 in a kept session and 404 once it ended (`McpHttpServer.KeepsAsync`).
- `Process.GetProcessById(pid).Kill()` then `WaitForExitAsync` works on a child the SDK started; each red run of a held-server test leaves its process behind, so kill `pgrep -f ModularMonolith.Tests.McpServer` after it (scratchpad `p137f/mutate137f.py`).

## Embeddings and pgvector (#138, 2026-10-18; Microsoft.Extensions.AI 10.11.0, pgvector 0.8.7 on PostgreSQL 18)

- **CommunityToolkit.VectorData.PgVector 1.0.1 passes the licence test and targets net10.0, yet cannot serve the Kit**: its `UpsertAsync` opens its own connection from its data source (no transaction parameter), so a write would commit outside the Unit of Work (ADR 0003). Read the source with `gh api repos/CommunityToolkit/AI/contents/MEVD/src/PgVector/<file>?ref=<commit>` before choosing a store library.
- **No pgvector client is needed**: a `float[]` parameter is `real[]`, which pgvector casts to `vector` on assignment (insert, upsert); a search needs `$n::vector`. The Unit of Work's EF connection has no `UseVector()` mapping, and a package cannot add one to a Module's DbContext.
- **Search on the Module's DbContext connection**: `EfUnitOfWorkDbContext.Of(unitOfWork).Database.OpenConnectionAsync`/`CloseConnectionAsync` is ref-counted, so inside a command it reuses the Unit of Work's open connection and sees its uncommitted rows (a cloned connection does not: the red run). `((NpgsqlConnection)c).CloneWith(c.ConnectionString)` keeps the password, which makes an own-connection mutation cheap.
- **`create extension` inside `do $$ ... exception when others then raise exception using message = ..., detail = sqlerrm $$`** gives a fixed `MessageText` to assert; on `postgres:18.6` (no pgvector) the raw error is `extension "vector" is not available`. Leave the extension unqualified: putting it in the package's schema breaks a DBA-installed one and unqualified `vector`/`<=>`.
- **Ollama 0.40.6 serves no embeddings for `qwen2.5:0.5b`** (501 "This server does not support embeddings. Start it with `--embeddings`"); `all-minilm:22m` gave 384 dimensions in 24 s with the image cached.
- **OpenAI .NET asks for `encoding_format: base64`** by default: a stub embeddings endpoint answers base64 of the floats' little-endian bytes (`MemoryMarshal.AsBytes`).
- **A Module whose migration needs pgvector cannot sit in Stub**: the shared fixture runs `postgres:18.6`. A separate project under `tests/ModularMonolith.Tests/Vectors/` (like `Streams/`, with `Compile Remove` and a slnx row) composed only by its fixture's Host; a second Module in the test assembly would lose its handlers to Stub's scan.
- **execution-core layout**: a new row (height) fails `composition/desktop-readability` while the same width passes; Aspire (no edges) moved to the free (1200, 40) cell and AI.Postgres took (1200, 830), a right-right edge widening the view to 1602 and passing. Max three sources per component (schema). `trial138.py` takes a revision as its fourth argument, so a trial runs after the code commit.
- **Review fix round (2026-10-23), what the review caught:** `EnableSensitiveData = false` covers only the OpenTelemetry step; `UseLogging()` logs messages, inputs and options at Trace (`LoggingChatClient`/`LoggingEmbeddingGenerator` remarks in `~/.nuget/packages/microsoft.extensions.ai/10.11.0/lib/net10.0/Microsoft.Extensions.AI.xml`), so never write "its telemetry carries no content" of a pipeline with logging. A rollback test that asserts only an empty search passes with a no-op store: store a committed passage in the same tenant and assert exactly its key.
- **pgvector off the search_path (probed on `pgvector/pgvector:0.8.7-pg18`):** with the extension in a schema `extensions`, `create extension if not exists vector` only notices `42710 ... skipping`; a `vector(n)` column and a search's `::vector` both fail `42704: type "vector" does not exist`, while inserting a `real[]` into an existing vector column passes (the cast is found by type, not by name). A `psql -c` with several statements is one transaction: a later failure rolls back an earlier `create schema`.
