## The chat client and the Gateway tool (#135, 2026-10-18; Microsoft.Extensions.AI 10.11.0, OpenAI 2.14.0, System.ClientModel 1.15.0)

- **`FunctionInvokingChatClient` at the cap** (`MaximumIterationsPerRequest`, default 40): at iteration == cap it strips the tools from the request (`PrepareOptionsForLastIteration`) and invokes nothing the answer asks for, so a model that always calls a tool gets `cap` invocations and `cap + 1` requests. A call of a tool not in `ChatOptions.Tools` is answered `Error: Requested function "X" not found.`; a throwing function `Error: Function failed.` (message only with `IncludeDetailedErrors`), and the fourth iteration in a row with a failed call rethrows (`MaximumConsecutiveErrorsPerRequest` 3). A returned value (a failed `Result` as JSON) is no error. Source read with `gh api repos/dotnet/extensions/contents/<path>?ref=v10.11.0`.
- **The OpenAI client retries on its own**: System.ClientModel's default `ClientRetryPolicy` retries 503 three times (honouring `Retry-After: 0`), so a stub 503 saw 4 requests. `RetryPolicy = new ClientRetryPolicy(maxRetries: 0)` leaves the Host's pipeline the only one; with the service defaults a POST then goes once. A second `AddPouryaKitResilience()` on the named client throws `InvalidOperationException` when it is created (Web's `SingleResilienceHandler`).
- **IHttpClientFactory for a singleton client**: `new HttpClientPipelineTransport(factory.CreateClient(name))` keeps one HttpClient, so the named client gets `UseSocketsHttpHandler((h, _) => h.PooledConnectionLifetime = 2 min).SetHandlerLifetime(Timeout.InfiniteTimeSpan)`, the documented long-lived pattern.
- **Three providers, one client**: Azure OpenAI's v1 API takes `new OpenAIClient(new ApiKeyCredential(key), new OpenAIClientOptions { Endpoint = new("https://<resource>.openai.azure.com/openai/v1/") })` (learn.microsoft.com, Azure OpenAI v1 API); Ollama `http://<host>:11434/v1` with any non-empty key (`ApiKeyCredential` refuses an empty one).
- **Options validation with one failure per row**: write provider-specific rules as `ai.Provider is not (A or B) || …`, or an undefined `Provider=99` also fails the key rule. An empty `--PouryaKit:AI:Endpoint=` binds a null `Uri`.
- **`AIJsonUtilities.CreateJsonSchema` with the Kit's JSON**: `SharedJsonTests` forbids any `JsonSerializerOptions` setter outside Domain, so lock the options with `MakeReadOnly(populateMissingResolver: true)` (a method, allowed) in the method that applies `UsePouryaKitJson`, and add that type to the test's two owner lists.
- **Trust of a tool call**: `run.Continue()` per invocation is trusted only inside the authorized Operation `run` belongs to (a handler injecting its `OperationContext`), so a permission-declared tool runs without its permission check there (G.6); from a fabricated context it is untrusted and `PermissionAuthorizer` denies an Actor without the permission. A denied permission as a failed tool result therefore needs a run outside an Operation. `RecordCatalogQuestionContext` (Stub's `IAuthorizer<GetProductQuery>`) records each tool call's context, by correlation.
- **Dapper tenant rule over prompts**: a string literal in a tenant-scoped Module naming `products` beside a SQL word (`with`) is read as SQL and fails `DapperTenantTests`; word a model's instructions around table names.
- **Stub server**: a Kestrel `WebApplication.CreateSlimBuilder()` on `http://127.0.0.1:0` mapping `POST /v1/chat/completions` with `id`, `object`, `created`, `model`, `choices[{index, message{role, content, tool_calls[{id, type:function, function{name, arguments as a JSON string}}]}, finish_reason}]`, `usage` is enough for the OpenAI client; `app.Urls.Single()` holds the bound port after start.
- **The Ollama probe**: `Testcontainers.Ollama` 4.15.0, `new OllamaBuilder("ollama/ollama:0.40.6")`, `ExecAsync(["ollama","pull","qwen2.5:0.5b"])`, `GetBaseAddress()` ends in `/`, so the endpoint is `{base}v1`. The image is 7.07 GB on arm64; the first run with no image took 7 min 22 s, and qwen2.5:0.5b called GetProduct and named the product. `Assert.SkipUnless` reports skipped and MTP exits 0.
- **Template ripple of a Gateway-bound Catalog feature**: the monolith has no Modularity, so `content/monolith/.template.config/template.json` excludes the folder, `TemplateTests.Unreplaced` lists each excluded file and the monolith Catalog csproj pair drops the package; the modular template's Catalog csproj, Host csproj, `Directory.Packages.props`, `AppHost.cs` and `appsettings.json` gain it; `inventory.json`'s template-monolith `excluded` names it.
- **execution-core had room for one more node**: Core narrowed from 1110 to 820 frees (910, 700) under Modularity; `ai-modularity` top to bottom and an `ai-cqrs` with no sides passed every gate. A `via` must leave and enter perpendicular to the sides it names, and ports sit at side centres. kit-context round-trips through `json.dumps(indent=2, ensure_ascii=False)`, execution-core does not (edit it as text).
