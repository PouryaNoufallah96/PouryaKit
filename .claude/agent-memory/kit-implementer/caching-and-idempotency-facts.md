## Idempotency (#42, 2026-10-07; EF Core 10.0.12, Npgsql 10, PostgreSQL 18.6)

- **A Gateway opens its own scope** (`GatewayProcessor.RunAsync`: new scope, `BeginOperation(context, module)`), so state put on the HTTP request scope's `Operation` (the `TraceParent` pattern) never reaches the dispatcher. Only the `OperationContext` crosses; that is why `RequestId` is an init property on it (Modularity was outside `allowed_files`). `context with { RequestId = … }` keeps `OperationId` and the private-init `IsTrustedContinuation`.
- **`insert … on conflict do nothing` waits** on another transaction's uncommitted conflicting row, then inserts nothing (it committed) or the row (it rolled back), and leaves the transaction usable. A plain insert raises 23505, which aborts the PostgreSQL transaction (mutation showed `PostgresException 23505` in the race test).
- **Proving a duplicate waits:** `fixture.WaitUntilAsync("exists (select 1 from pg_stat_activity where wait_event_type = 'Lock' and query like 'insert into \"stub\".pouryakit_idempotency_keys%')", …)`. Npgsql rewrites `@p`/`{0}` to `$n`, the prefix stays. With the reservation moved after the handler, the first holds no key yet, so the wait never appears: that is the red.
- **EF1002 is a build error here:** an interpolated string passed straight to `ExecuteSqlRawAsync` or `SqlQueryRaw` is refused. Build the statement through `Func<string, string> sql` and pass the variable, as `EfReceipts` does.
- `Database.SqlQueryRaw<string?>("select response as \"Value\" from … where …", values)` works under `UseSnakeCaseNamingConvention`; a NULL column comes back as a null element.
- `SharedJsonTests` (ArchitectureTests) pins the owners that call `UsePouryaKitJson`; a static field initializer `new JsonSerializerOptions().UsePouryaKitJson()` passes the "own setup" rule and adds its class (`PouryaKit.Cqrs.Dispatcher`) to that list.
- **Opting an existing endpoint in breaks every test that POSTs there:** WebTests, OpenApiTests and ModularMonolith SharedJsonTests needed a key (`IdempotentRequests.PostAsJsonAsync(uri, value, key, ct)`). A malformed-body 400 test passes for the wrong reason without a key. `PersistenceTests` pins every schema's tables and migration history: a new Kit table migration goes there too.
- A missing-header test must post a valid body (existing category), or a mutation that drops the check answers 404, not 201.
- **#42 review findings, so the next Kit seam starts with them:** (F1) a stored sentinel for "none" must be a value the domain refuses: `OperationContext` now refuses a blank tenant and `HttpCallerContext` reads a blank tenant claim as null, as `VerifiedClaims` (JwtBearer) already drops blank claims. (F2) every new Kit seam Feature code must not call joins `ModuleRules.KitSteps` with an offending call in `Offending.KitStepCallingCommandHandler` and its line in `FeatureCodeTests` (precedent fd8fe1e). (F3) a requirement Web enforces on a request must reach the OpenAPI document: public Web metadata (`IdempotencyKeyRequirement`) plus an operation transformer in Web.OpenApi beside `BearerSecurity`; `operation.Parameters ??= []` then `new OpenApiParameter { In = ParameterLocation.Header, Required = true, Schema = new OpenApiSchema { Type = JsonSchemaType.String } }` (Microsoft.OpenApi 2.x). (F4) a new concept gets a GLOSSARY entry.
- The Proving Sample maps no idempotent command on PUT or DELETE; the Stub's `CountedNoteEndpoint` maps `CountNoteCommand` on both. Mutating the key read to POST only made the repeat run again (`AssertNothingSentAsync` threw), the POST test stayed green.

## Idempotency key retention (#42 follow-up, 2026-10-07; Microsoft.Extensions.Hosting.Abstractions 10.0.12, EF Core 10.0.12, PostgreSQL 18.6)

Decompiled with ilspycmd; check the merged code first (`IdempotencyKeyCleanup`, `IdempotencyRetentionTests`).

- **.NET 10 `BackgroundService.StartAsync` runs `ExecuteAsync` with `Task.Run`**, so nothing in `ExecuteAsync` has happened when `host.StartAsync` returns. A `PeriodicTimer` created there races a test's `FakeTimeProvider.Advance`; create it in a `StartAsync` override before `base.StartAsync`.
- `new PeriodicTimer(interval, timeProvider)` with the test clock fires on `Advance`; advancing several periods coalesces into one or two ticks. The tick's work is asynchronous: wait on its effect (a row gone, a log entry), never on `Advance` returning.
- **An exception escaping `ExecuteAsync` stops the Host** (`BackgroundServiceExceptionBehavior.StopHost`). Catch per tick with `when (!stoppingToken.IsCancellationRequested)`. Proof: rename the column the tick reads with `Fixture.RowsAsync("alter table … rename column …")`, restore it in `finally`, then assert the next tick works and `ApplicationStopping` is not cancelled.
- **Finding every Module's DbContext from a package that cannot see Modularity:** `AddDbContext` also registers one non-generic `DbContextOptions` per context (with `Add`), so `scope.GetServices<DbContextOptions>().Select(o => o.ContextType)` lists them, as `HostFixture.StartHostAsync` does. Filter by `PouryaKitDbContext`.
- **A Module without a Kit table:** check `select to_regclass({0}) is not null as "Value"` first; a statement on a missing table makes EF log `Failed executing DbCommand` at Error level on every tick.
- **`[LoggerMessage]` formats values with the invariant culture**, while a test's interpolated string uses the current one: put `:O` in the template (`{Cutoff:O}`) and in the test.
- `ValidateOnStart` makes `host.StartAsync` throw `OptionsValidationException` with every message in `Failures`, before any hosted service or migration, so such a test needs no database. Register the validator with `TryAddEnumerable` when the registration runs once per Module.
- **Fix round (review F1-F3):** (F3) `insert … on conflict do nothing` locks nothing it finds, so a committed delete can land between it and the next read; re-reserve in the same transaction (bounded). **Stepping between two statements of the Kit's own transaction** without an IVT: `services.ConfigureDbContext<StubDbContext>(o => o.AddInterceptors(interceptor))` (EF Core 9+, layered on `AddDbContext`) in the test Host's composition, with a `DbCommandInterceptor.NonQueryExecutedAsync` that matches the statement text and result and runs the test's action once. (F2) `PeriodicTimer` accepts 1 ms to `uint.MaxValue - 1` ms (truncated to whole ms); validate both bounds, and bound a retention so `now - retention` cannot underflow. (F1) A Kit migration helper changed in place leaves earlier databases without the new column: map SQLSTATE 42703 to a message naming the column and the SQL; once a shape ships, add a new helper instead. xUnit v3 `TheoryData<TimeSpan, TimeSpan, int, string[]>` runs and shows each case.
- Default retention source: Stripe API reference, "Idempotent requests" (24 hours, a reused key after pruning is a new request), recorded in `docs/provenance/PouryaKit.Persistence.EFCore.md`.

## Caching (#43, 2026-10-07; Microsoft.Extensions.Caching.Hybrid 10.10.0, StackExchangeRedis 10.0.12, redis:8.10.1)

HybridCache decompiled with ilspycmd.

- **HybridCache drops the caller's ExecutionContext** whenever the token can be cancelled (every HTTP and test token): `GetOrCreateAsync` then calls `ThreadPool.UnsafeQueueUserWorkItem`, and only a non-cancellable token takes `ExecuteDirectAsync`, inline on the starting call. Restoring the ExecutionContext in the factory was not enough (review F1, high): a starting caller whose token is cancelled leaves, its Gateway scope is disposed and `AuthorizedOperation` ends, while the shared token stays live for its joiners, so the run goes on with a disposed DbContext. Fix: pass `CancellationToken.None`; the starting call then runs and waits for the handler, joiners share it, and the handler gets `CancellationToken.None`. Restore became unneeded and was removed.
- **The reading boundary's tracked-state check runs at its Dispose, after `Steps` returns** (review F2, high), i.e. after HybridCache stored the answer. Close it early in the cached delegate, on a success, before the factory returns; `ReadingBoundary.Dispose` is idempotent, so the pipeline's later close does nothing. The EF guard exposes only Dispose, and EFCore was outside allowed_files.
- **A factory exception stores nothing and logs nothing** (only an EventSource counter); every joined caller gets the same exception. That is how a failed Result stays out (private `NotStored` carrying the Errors).
- **Keys with control characters or over 1024 chars silently run uncached** (`ValidateKey`). The effective key escapes each part with `Uri.EscapeDataString`, joined by `|`.
- **Default JSON** reads a keyed `JsonSerializerOptions` under `typeof(IHybridCacheSerializer<>)` (undocumented). The Kit avoids it: it caches the value as a JSON `string` with `UsePouryaKitJson`.
- **`RemoveByTagAsync(IEnumerable)`** loops the single-tag overload: local invalidation first, then an L2 write that may throw and stop the loop. Evict tag by tag in a try/catch.
- **A tag invalidated while the factory runs** makes HybridCache bump the new entry's timestamp, so it stays valid: a query racing a commit can store its old answer until expiry. Documented as a limit.
- **Single-flight proof:** an `EventListener` on `Microsoft-Extensions-HybridCache` (Verbose) sees `StampedeJoin`; hold the first handler, `Task.WhenAny(joined, second)`, then release. A get-then-set mutation completes `second` instead, and runs the handler twice.
- **Redis:** HybridCache answers the first caller before its L2 write completes; poll `server.DatabaseSizeAsync()` before the second Host reads. Two Hosts composed but never started can run Gateway queries.
- **Mutation trap:** a "evict whatever the outcome" mutation placed inside the `ReferenceEquals(outcome, returned)` branch stays green for a save refused by the Unit of Work (`NameInUse`): that outcome is a new Result. Mutate right after `EndUnitOfWork()` instead.
- **A nested query's reading boundary cannot see an enclosing change** (re-review F5, high): `EnterQuery` captures the tracked values current at its start, so a mutation an outer query, authorizer or validator made is its baseline and passes. The slot now takes only `Operation.IsOutermostQuery` (`_runningQueries == 1`, no command, check or reading step) and refuses a rollback-only Operation. Checking every enclosing boundary without closing it was not possible: the EF guard exposes only `Dispose`.
- **A rollback does not clear the ChangeTracker:** after a refused command, a query in the same scope (endpoint, test `CreateAsyncScope` + `BeginOperation`) reads the rolled-back values from `FindAsync`. `EditFolderCommand(…, FolderEdit.RelabelThenRefuse, …)` then a cacheable read is the red for the rollback-only refusal.
- **Serialize before ending the read** (re-review F6, high): a response holding a deferred enumerable mutates on enumeration, i.e. during `JsonSerializer.Serialize`. `IQueryCache.QueryAsync` takes an `Action endRead` (the dispatcher passes `reading!.Dispose`); the factory handles, serializes, calls it, returns the string. Use a concrete response record holding `IEnumerable<string>`: `Result<T>`'s implicit conversion does not apply when `T` is an interface.

## Pinning the stored keys (#81, 2026-10-10; Microsoft.Extensions.Caching.Hybrid 10.10.0)

- HybridCache writes its distributed entry under the Kit's key unchanged (no prefix): a recording `IDistributedCache` registered before `AddPouryaKitCaching()` sees `Namespace.Type%2C%20Assembly|tenant|Kind|actor|key`. The write lands after the answer, so wait on its first `Set`. The command's key is `select command from <schema>.pouryakit_idempotency_keys`. `TypeKeyTests` does both.

## Holding a Dapper read inside a cached query (#82, 2026-10-10; HybridCache 10.10.0)

- **Hold after the read, never at `OpenAsync`:** held there, the handler reads after the commit and the proof is a false green. A decorator of the singleton `IReadConnectionFactory` (its descriptor has an `ImplementationFactory`) returns a `DbConnection` wrapper that waits in `DisposeAsync`, which the handler's `await using` reaches after Dapper's query. Arm it with an `AsyncLocal` set inside a helper `async` method, so it flows into the query (HybridCache runs the factory inline with `CancellationToken.None`) and not back to the test's rename. Code: the #82 report (T1 stayed out of the tree).
- **T1 confirmed red twice:** HybridCache re-stamps an entry at factory completion when one of its tags was evicted during the run (decompiled `DefaultHybridCache.StampedeState<TState, T>.BackgroundFetchAsync`, `if (!Cache.IsValid(CacheItem)) UnsafeSetCreationTimestamp(...)`), so a read that began before a commit stores its old answer until expiry.

**Why:** these decided the #42 and #43 shapes or a test of them, or cost a run.
**How to apply:** for any Kit table written in the Unit of Work's transaction or cleaned across Modules, any race test, any endpoint opt-in, any Kit `BackgroundService` or test that drives one with the test clock, any HybridCache use, any slot that runs Feature code inside a library callback, and any single-flight or Redis test.
