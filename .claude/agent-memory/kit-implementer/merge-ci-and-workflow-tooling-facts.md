## Merges and CI logs (Wave 2 batch-4 retro and session-5 retro, 2026-10-07 to 2026-10-08)

- **`merge=union`** (`.gitattributes`, since 2026-10-07) covers this `MEMORY.md` only: `docs/acceptance.md` left it on 2026-10-08 (session-5 retro), after union put a new section inside one of its tables, so two packages that both append there now conflict and the merge keeps both sections in ticket order. Two branches that each append a section merge with exit 0 and both sections present; at `7e3aede` (no attribute) the same merge conflicts in both files. Union drops the blank line both appended sections start with, so the second heading follows the first section's last line (an ATX heading still renders). A line both branches changed is kept twice, silently: read the merged file.
- Prove a merge behaviour in a scratch clone driven by a Python script in the scratchpad (`git clone --branch <your branch> <worktree> <scratch>/x`, then `git -C <scratch>/x ...` through `subprocess`, with `-c core.hooksPath=/dev/null` and a throwaway identity). Run it once at the base commit as the negative control.
- **Failed CI logs:** `gh api repos/<o>/<r>/actions/jobs/<id>/logs` writes zero bytes and prints "the response contains terminal escape sequences" unless given `--allow-escape-sequences` (gh 2.102.0). `gh run view --job <id> --log-failed` works without it, but printed `UNKNOWN STEP` on every line and the whole job log (32,527 lines), with each escape character as the two characters `^[`. Either way the blob download is about 75 KB/s, so a 3.7 MB job log takes 45 to 50 s; `.agents/scripts/ci-failures.py` runs in about 52 s.
- MTP failure shape in the log: `failed <FQN> (<duration>)`, then indented lines (`from <dll>`, the assertion message, `at` frames); the assembly summary `<dll> failed with N error(s)` is not indented. Log lines such as `ReadFolderQuery failed with Reading.Missing` do not start with `failed`.
- **Testing a git-driving script** (`test_merge_package.py`, 2026-10-08): pass one env to both the test's git calls and the script's process, with every inherited `GIT_*` variable dropped and `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, then set identity and `core.hooksPath=/dev/null` in the throwaway repository's own config. Keep stub check scripts outside the repository, or they make its checkout dirty. A bare `origin.git` beside it proves a push or its absence by `rev-parse <branch>` there; name the throwaway integration branch `feat/wave`, since the script refuses `main`. A test-only CLI option is gated by an environment variable the tests set (`MERGE_PACKAGE_TESTS=1`). Mutation proof without touching the worktree: copy the script and its test module into one scratchpad folder per mutation (the tests find the script with `Path(__file__).with_name`), mutate the copy, run `unittest discover -s <folder>`.
- **A branch name from a report is data, not a revision** (retro B fix round, 2026-10-08): `rev-parse refs/heads/pkg~1^{commit}` resolves to an older commit, so a stale head passed a tip check. `git check-ref-format --branch <name>` rejects `pkg~1`, `pkg^`, `HEAD` and `-x`, but exits 0 on `@{-1}` and prints the previous branch: require its output to equal the name. Resolve the tip with `git show-ref --verify --hash refs/heads/<name>`. The settings' ask rule for a push to `main` matches Bash command text only, so a script that pushes from Python must refuse `main` itself.
- From an isolated worktree agent, `git -C <main checkout>` is refused like any other redirect; read the main checkout's state from the worktree (they share refs and config).
- Merging an appended acceptance section beside a paragraph the other side edited duplicated that paragraph and put the other side's tail after mine: compare with `git diff <tip> -- docs/acceptance.md | grep '^-'` and reorder.

## Workflow scripts and the Codex leg (kit-review rework, 2026-10-06 to 2026-10-08)

- Direct `node --check` of `kit-review.js` passed on Node v22.22.3 and failed with "Illegal return statement" on v24.21.0. The workflow runtime wraps the body in an async function. If the direct check rejects the workflow body's top-level `return`, check a copy with the body wrapped as `export async function body(args, agent, parallel, phase, log) { ... }`. The same wrapper, built with the AsyncFunction constructor, runs the script with stubbed agents. A syntax check alone does not prove execution in the workflow runtime.
- A script has no fs or process access. Running git, `gh` or writing a file takes an agent call. The runtime keeps only the value the script returns: `<session>/workflows/<runId>.json` (`result`) and, when the notification truncates it at about 9.8 KB, `tasks/<taskId>.output`. The script cannot name either path. `journal.jsonl` keeps each agent's return, not the final value.
- The claudex-loop runner in `inspect` mode accepts a detached worktree under `.claude/worktrees/` as `--repo` (Codex 0.160, gpt-6-astra, 2026-10-06; it completed in about 200 s). It uses `--skip-git-repo-check`, so project trust does not matter.
- When Codex fails, the runner's `result.json` `error` only says "inspect stdout.txt". The real reason is in `<artifacts>/stdout.txt`, as `{"type":"error","message":...}` and `{"type":"turn.failed","error":{"message":...}}` events.
- Writing `￿` in a file through the Write tool once left a literal U+FFFF character in the source, while `\u007f` beside it stayed escaped. After writing a regex with `\u` escapes, check for non-ASCII bytes (`grep -c -P '[^\x00-\x7F]'`).
- It happened again on 2026-10-07 even inside a Python raw string written with Write: Write turns the six characters `\uffff` into U+FFFF. Fix it with a Python script that replaces `chr(0xFFFF)` by `'\\' + 'uffff'`; a `sed` with `$'...'` is refused.
- On 2026-10-07 the only Node on the machine was v24.21.0 (fnm), so the direct `node --check` of `kit-review.js` fails at any commit. Proof that holds: the wrapped check, plus a stub harness (`AsyncFunction('args','agent','parallel','phase','log', src)`) whose prepare stub returns an absolute fake `top`/`run`/`worktree` (`.../.claude/worktrees/kit-review-x`), whose `parallel` throws so the run goes straight to Finish, and whose finish stub runs the prompt's real bash block with `bash -c`. Run the same harness on `git show HEAD:` of the file for the red.
- 2026-10-07 (retro, `.claude/reviews/` copy): the same harness proved a finish-stage change. Make the finish stub return `verdict` from the block's first stdout line and `removed` from its last, give the prepare stub a fake `top` under the scratchpad (the copy lands in `<top>/.claude/reviews/`), and pass the args as an object. A base-commit copy of the script through the same harness is the red run.
- 2026-10-08 (session-5 retro B, the Codex-leg size guard): the same harness proves a relay-stage change. The `review:codex` stub takes the prompt's first ```bash fence, runs it with `spawnSync(shell, ['-c', block])` and returns the parsed last stdout line; `parallel` maps each leg with `.catch(() => null)` so a throwing kit-reviewer stub still reaches Finish; the fake top holds a stub `runner.py` that leaves a marker file. The relay agent's shell is the user's (zsh here), so run the block under both `bash` and `zsh`. macOS `wc -c` pads its count with spaces (`tr -d ' '`). The guard is testable in process: load `.agents/hooks/guard.py` with importlib and call `denied_reason("Bash", {"command": ...}, cwd)`; append a `git push --force` line as its control.
- Codex in `inspect` mode refuses an input over 1,048,576 characters within about two seconds ("Input exceeds the maximum length of 1048576 characters"), because the runner embeds the whole diff in the prompt; `review` mode with no `--base` embeds none, and Codex reads the worktree in its read-only sandbox.

## Pull request tooling, hook input and scripts on a tree that is not checked out (session-6 retro, 2026-10-09; gh 2.102.0, git 2.54, Claude Code 2.1.295)

- **Who runs where:** a `kit-implementer`'s hook `cwd` is its worktree, but `kit-reviewer`, `kit-scout` and `/kit-review`'s workflow agents run with `cwd` = the main checkout and reach a review worktree by `cd <worktree> && …` (1002 of 2141 reviewer Bash calls in the saved transcripts). A subagent's `cd` does not persist; only the main thread's does. Claude Code's hook input carries `agent_id` only inside a subagent; Codex sends no such marker on `PreToolUse`. A guard rule keyed on `cwd` alone would have refused the reviewers, so the retro's `cd` rule was dropped. The saved transcripts (`~/.claude/projects/<project>/**/*.jsonl`, each entry with `cwd`, each subagent with a `.meta.json` naming `agentType`) answer "who really does this" in one scan: use them before adding a rule.
- **`check-ai-setup.py` in a worktree:** its `ROOT` is under `.claude/worktrees/`, and every guard proof case gets `cwd: str(ROOT)`; a proof that depends on the working directory needs an explicit one.
- **Judging a tree no checkout holds** (`merge-package.py --ready`): `git merge-tree --write-tree --name-only --no-messages HEAD <other>` prints the tree, then one conflicted path per line, exit 1 on conflicts. A script that asks git about "the checkout" (`check-tree.py`: `rev-parse --show-toplevel`, `ls-files`, `check-ignore --no-index`) runs on that tree with `GIT_DIR=<rev-parse --absolute-git-dir>`, `GIT_WORK_TREE=<scratch>`, `GIT_INDEX_FILE=<scratch>/index` after `git read-tree <tree>` and with the tree's `.gitignore` written into the scratch folder. Replaying pull request #65 (branch `90e0871`, main `94f2dd6`) this way gave `behind=1 conflicts=1 tree=FAIL(23)`.
- **`gh pr checks <pr> --json name,bucket,completedAt`** exits non-zero while a check is pending or failed and prints nothing before the head commit has checks: read the JSON, not the exit code. GitHub can leave a finished check run `IN_PROGRESS` for good (pull request #65's `publication-checks` of the push event, with a conclusion and a `completedAt`); a check without a completion time prints `0001-01-01T00:00:00Z`. The push and the pull_request event each list every job, so names repeat.
- **Review bots:** the Codex summary comment carries `<!-- codex-pull-request-review-summary -->` and a row `🔄 **Running** since …` or `✅ **Completed** …`; Codex thread bodies open with `**<sub><sub>![P2 Badge](…)</sub></sub>  Title**` and end with `Useful? React with 👍 / 👎.`; cubic's carry HTML comments and a `<details><summary>Prompt for AI agents</summary>` block (78 KB of 49 threads cleaned to 23 KB). `gh pr view --json comments` gives the author as `chatgpt-codex-connector`, the REST API as `chatgpt-codex-connector[bot]`. A reply is REST `pulls/<pr>/comments/<first comment id>/replies`; resolving is GraphQL `resolveReviewThread(input:{threadId})`.
- **Tests of a hyphenated script without a subprocess:** `importlib.util.spec_from_file_location("name", Path(__file__).with_name("pr-threads.py"))`, then `patch.object(module, "gh", fake)`; give a poll loop a clock that only the patched `sleep` moves. The copy-and-mutate red proof works for these too, but a copy of `test_validation.py` shows `test_checkout_mode_rejects_shallow_history` red even unmutated, because the copy's `ROOT` is no repository: run the control first.
- **The acceptance record's pointers** (`check-docs.py`): it also names a Python test (`InventoryTests.test_inventory_is_nonempty_and_exact`, in `scripts/packaging/`) and a file (`CrossModuleTests.cs`); the two removed `SnapshotTests` it names on purpose are in `REMOVED_TESTS`. A renamed test fails the check from now on: fix the row in the same change.
- **`validate.py --since <base>`** skips only for docs and AI-setup paths; a change under `scripts/packaging/` (the flag's own package included), `tests/` or `.github/` validates. `run()` there merges stderr into stdout, so a git warning counts as a changed path and the validation runs.

**Why:** these took probes during the retro packages and the kit-review rework (retro item 1); the CI log path decides how long the orchestrator waits.
**How to apply:** when a merge proof, a CI failure or a `gh` log download is part of the work; when a brief says to verify a workflow with `node --check`, run that direct check first and report its runtime and result, and use the wrapped check as a fallback if the runtime rejects the workflow body's top-level `return`.
