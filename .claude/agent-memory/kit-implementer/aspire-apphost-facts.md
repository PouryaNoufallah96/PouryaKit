Learned building `PouryaKit.Aspire` and `ModularMonolith.AppHost` (#130, 2026-10-18, Aspire 13.6.1).

- **`Aspire.AppHost.Sdk/13.6.1` adds `Aspire.Hosting.AppHost` itself**: a `PackageVersion` for it in `Directory.Packages.props` fails restore with NU1009. It also warns ASPIRE010 (`AspireUseCliBundle=false`, the SDK's default, which takes DCP and the dashboard from NuGet): `NoWarn` it; the AppHost then runs with Docker alone.
- **Aspire.Hosting's closure fails two Kit gates:** `MessagePack` 2.5.302 is NU1902 (GHSA-qhrr-8q5h-9q3h) under warnings-as-errors, and `Fractions` 7.3.0 (via `KubernetesClient` 19.0.2) declares a licence file, which `LicenceTests` refuses. Floors in the package: `MessagePack` 2.5.307, `Fractions` 8.3.2 (MIT expression from 8.x); the AppHost start test passed on 8.3.2. Recorded for the owner, as the Pkcs floor of #124 was. (#167, 2026-10-24: `Aspire.Hosting` 13.6.4 asks for `MessagePack` 2.5.307 itself, so the reference and its pin are gone; `KubernetesClient` is still 19.0.2, so the Fractions floor stays.)
- **The testing builder's model** (`DistributedApplicationTestingBuilder.CreateAsync<Projects.X>`) holds a hidden `<project>-rebuilder` per project and a `ParameterResource` per `AddParameter`; the generated `<name>-password` parameters are not in it. `WithEnvironment(name, parameter)` adds a `ResourceRelationshipAnnotation` of type `Reference`, so a Host's references include the parameter.
- **A Host project with no `launchSettings.json` gets no endpoint**: `WithHttpEndpoint()`; under the testing builder the Hosts run in `Production`. `WaitForResourceHealthyAsync` on a project with no health check returns once it runs.
- **Named volumes keep the first password**: pass `Parameters:postgres-password=…` (and `cache-`, `broker-`) as builder arguments, or a second run fails against the volume. Volume names are `<apphost>-<hash of the project path>-<resource>-data`, so each worktree gets its own, but a test run and `dotnet run` of one AppHost share them: `dotnet run` persists generated passwords in the AppHost's user secrets, and against a volume the tests initialised its health checks fail and the Hosts wait forever (no error, just no start). The start test therefore swaps each `ContainerMountAnnotation` for one named `<source>-tests` before `BuildAsync`.
- **An AppHost without a launch profile runs in Production and reads no user secrets**, so each `dotnet run` generates and stores new server passwords and the second run fails against its own volume (`28P01`, Hosts wait forever). Ship `Properties/launchSettings.json` with `DOTNET_ENVIRONMENT=Development`. The testing builder replaces the AppHost's `DistributedApplicationOptions` with its own (dashboard off by default), so a sample's own `DisableDashboard` is only testable if the test passes it into the builder's callback.
- **Postgres 18**: Aspire mounts the volume at `/var/lib/postgresql` for an 18.x tag; Aspire's own defaults are the floating `18.3`, `8.6`, `4.3`.
- **Namespace shadow**: inside `namespace PouryaKit.Aspire.Tests`, `Aspire.Hosting…` resolves under `PouryaKit.Aspire`; put the usings at file top or write `global::`.
- **`validate.py`'s sample consumer copies all of `samples/ModularMonolith/src`**, but only `entries` are restored and each entry takes the Host production publish (`codegen write`), so an AppHost is not an entry; the package gets its own consumer under `scripts/packaging/consumers/`.
- **The Kit skill's `description` is near the 1024-character limit** (1012 after #130): a new Capability adds a few words at most.
- **execution-core layout**: a node at (40,170) broke `storages3-cqrs`'s route (`composition/ambiguous-corridor`); (40,560) passed. Check headless screenshots with Playwright's `chrome-headless-shell --headless --screenshot`.

## Ollama in the AppHost (#139, 2026-10-18; Aspire 13.6.1, ollama/ollama:0.40.6)

- **`CommunityToolkit.Aspire.Hosting.Ollama` 13.6.0 is out**: it depends on `OllamaSharp` 5.4.12 (`license type="file"`, the A1 refusal) and on Aspire 13.6.0; check a toolkit package's nuspec dependencies, not only its own licence. A plain `AddContainer` + `VolumeNameGenerator.Generate(builder, "data")` (public in `Aspire.Hosting`) + `WithHttpEndpoint(targetPort: 11434, name: "http")` replaces it.
- **`WaitFor` waits for health checks, not for `ResourceReadyEvent` handlers**: pulling a model on the ready event lets the Host start before its model exists. A keyed `HealthCheckRegistration` in `builder.Services.AddHealthChecks()` plus `WithHealthCheck(key)` that answers `POST /api/show` 200, else pulls with `POST /api/pull {model, stream:false}` inside the check (infinite `HttpClient.Timeout`), holds the Host until the model is served. `builder.Services.AddHttpClient()` compiles in a library on Aspire.Hosting alone.
- **A Host the AppHost runs needs an HTTP route for every proof**: Hosts run as OS processes, so a Gateway-only feature (the agent) needed an endpoint (`POST /catalog/v2/products/ask`); Catalog routes need an API version (`400 Unspecified API Version` without one). A bearer token for the AppHost's Host can be an HS256 JWT built by hand (`HMACSHA256.HashData`, base64url) with `iss`, `aud`, `sub`, `tenant`, `nbf`, `exp`: no IdentityModel package in `PouryaKit.Aspire.Tests`.
- **The AppHost reads `builder.Configuration[...]`**, not `GetValue<T>` (no Binder package): `bool.TryParse`. A plain argument `LocalAgent=true` reaches it through the testing builder's args.
- **Aspire's `ResourceHealthCheckService` awaits each check with no deadline** (#139 review F1): a custom check's every request needs its own linked `CancellationTokenSource` deadline, returning Unhealthy on expiry; prove it against a `TcpListener` that accepts and never answers, building an `EndpointReference` from a `ContainerResource` whose `EndpointAnnotation.AllocatedEndpoint` is set by hand.
- **Reading a resource's environment in a model test**: `GetEnvironmentVariableValuesAsync` is obsolete in 13.6 (CS0618 is an error); invoke each `EnvironmentCallbackAnnotation` with `new EnvironmentCallbackContext(new(DistributedApplicationOperation.Publish), resource, [])` and render an `IManifestExpressionProvider` value by `ValueExpression` (`{ollama.bindings.http.url}/v1`).
- **qwen2.5:0.5b through the Host answered in about 25 s** with the image and model cached; a run without the endpoint wiring, or without the pull on a fresh volume, returns 500 from the agent.

## The Reverse proxy in the AppHost (#170, 2026-10-24; Aspire 13.6.4, YARP 2.3.0)

- **A `Urls` key in a project's `appsettings.json` beats the `ASPNETCORE_URLS` Aspire passes** (WebApplication loads `ASPNETCORE_`-prefixed variables before `appsettings.json`): the proxy listened on its own 5100 and `WaitForResourceHealthyAsync` timed out after 5 min, "Request to http://localhost:<allocated>/alive timed out". Put the URL in `Properties/launchSettings.json` (`applicationUrl`); Aspire derives the `http` endpoint from the profile, so no `WithHttpEndpoint()`, and the testing builder randomizes the port.
- Aspire runs a project resource with its project directory as content root, so an `appsettings.json` the csproj does not copy still loads (the proxy's `RunWorkingDirectory` setup).
- **The AppHost's databases hold no EF Core Module tables** (Ledger's Marten schema is applied at start by `UsePouryaKitMarten`): no Host applies an EF migration at start, so an Operation through the AppHost answers 500 (`42P01 relation "inventory.stock_items" does not exist`). Prove a route under the AppHost with an answer given before any query: Inventory's unversioned path with a token answers 400 `ApiVersionUnspecified`, where `ModularMonolith.Host` (no Inventory beside a broker) answers 404.
- **A project's effective configuration in a model test**: `ProjectResource.GetProjectMetadata().ProjectPath` gives the directory for `ConfigurationBuilder().AddJsonFile`, then the rendered environment with `__` replaced by `:` through `AddInMemoryCollection`. `WithReference(project)` renders `services__<name>__http__0` as `{<name>.bindings.http.url}`. A JSON `false` reads back as `"False"`; an environment `"true"` stays `"true"`.
- A route's configuration belongs where the topology is decided: the sample's `ModularMonolith.Host` hosts Inventory without a broker, so a `/inventory` route in the proxy's own settings would break its standalone run; the AppHost (broker on) adds it as environment.
- `ReverseProxyTests` joined `BrokerCollection` (constructor `(AppFixture app, BrokerFixture broker)`) to start `Inventory.Host`, which needs RabbitMQ; `StartInventoryHostAsync(configure: b => b.WebHost.UseKestrel().UseUrls("http://127.0.0.1:0"))` overrides the fixture's test server. An `IStartupFilter` added in `configure` records what the Host's pipeline receives.
- `dotnet test --filter-method A --filter-method B` runs several methods in one call.

## gRPC through Aspire's endpoint proxy (#172, 2026-10-25; Aspire 13.6.4, Grpc 2.84.0)

- **The endpoint proxy carries HTTP/2 with prior knowledge over cleartext**: a gRPC call on a proxied endpoint whose Kestrel listener is `Http2`-only reaches the service; on a listener of both versions it fails with `HTTP_1_1_REQUIRED`, the same when the listener is called directly, so that refusal is Kestrel's. `EndpointAnnotation.Transport = "http2"` is only manifest and dashboard metadata in run mode (decompiled: DCP services are created with protocol TCP), so it changes nothing for the proxy.
- **Two Kestrel endpoints from the AppHost**: `Kestrel__Endpoints__<name>__Url` in the environment replaces `ASPNETCORE_URLS`, so name both (`http` and `grpc`, `Protocols=Http2` on the second) with `ReferenceExpression.Create($"http://localhost:{host.GetEndpoint(name).Property(EndpointProperty.TargetPort)}")`, and `WithEndpointsInEnvironment(_ => false)` stops Aspire passing `ASPNETCORE_URLS` (no "Overriding address(es)" warning). A lambda cannot use the builder variable in its own declaration (CS0841): put `shopHost.WithEnvironment(context => ...)` in a statement after it. The callback form added no `Reference` relationship, so the model test's reference lists stayed.
- **Reading the running resource in a test**: `WaitForResourceAsync(name, state)` returns only the state; the predicate overload returns the `ResourceEvent`, whose `Snapshot.EnvironmentVariables` hold the resolved values (the listener's port). `app.GetEndpoint(resource, name)` is the proxy's URL; `CreateHttpClient(resource)` without a name prefers `https`, then `http`. A test project takes `Grpc.Net.Client` through the pinned `Grpc.Net.ClientFactory`, and the sample's `Catalog.Contracts` by `ProjectReference` for the generated client; a non-Guid `product_id` gets `InvalidArgument` before any query, the answer the AppHost's unmigrated databases allow.
- **Red runs that start the AppHost**: a scratchpad script that swaps one line of `Program.cs`, runs the start test alone (`--filter-method`, about 20 s each with images cached) and restores in `finally` (`scratchpad/p172/mutate172.py`); the unproxied red used a fixed `port: 5091`.

## Which Host answered through the proxy (#176, 2026-10-25; Aspire 13.6.4, YARP 2.3.0)

- **An anonymous request proves no route**: both sample Hosts' fallback policy answers 401 on any path, mapped or not. With the AppHost-signed token, an unversioned path of a Host's own Module answers 400 `ApiVersionUnspecified` (the header reader of `AddPouryaKitOpenApi`) and the other Host answers it 404, so assert the 400 through the proxy and the other Host's 404 directly.
- The proxy's own route is overridable from the AppHost for a red run: `.WithEnvironment("ReverseProxy__Routes__modular-monolith__ClusterId", "inventory")` sends the catch-all to `Inventory.Host` (`scratchpad/p176/red_proxy.py`).
