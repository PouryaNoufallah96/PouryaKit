## Template packages (#53 and #59, 2026-10-07; SDK 10.0.401, ASP.NET Core 10.0.12)

- **Template engine.** A source outside the template's install root fails (`MV012`), so the sample is packed into the same package (`content/sample/`) and each `template.json` points at `../sample/`. `--debug:custom-hive` needs an absolute path; a relative one fails with "Template package location … is not supported". `sourceName` is the sample's own dotless `ModularMonolith`, so packed Host files' `namespace ModularMonolith.Host` become `Acme.Shop.Host` with no copy; an identifier containing the token (`ModularMonolithHost`) would become `Acme.ShopHost`, so template content avoids that. The restore post-action works on a `.slnx` primary output.
- **Fix round (review of f29e732):** a dotless `sourceName` has identical identity and safe forms, so the engine writes the safe-namespace form into all content (paths in `.slnx` and `ProjectReference`s too) and the identity form into file names: `-n acme-shop` gives `acme-shop.Host.csproj` referenced as `acme_shop.Host`, a broken solution. Fixed in #59: template-owned `.slnx`/csproj paths use the token `PouryaKitAppName`, replaced by a `derived` symbol `projectName` (`valueSource: name`, `valueTransform: identity`; `identity` is a built-in form name, no `forms` entry needed). The restore post-action follows the rename (`primaryOutputs` `ModularMonolith.slnx` restores `acme-shop.slnx`). MSBuild's default `RootNamespace` stays raw (`acme-shop.Tests`) and all four names (`acme-shop`, `Acme.Shop`, `acme_shop`, `My Shop`) build. A probe of every name in ~1 min: `dotnet pack PouryaKit.slnx -c Release -o <feed>` (incremental, seconds), install into a custom hive, generate without `--no-restore` under a folder whose NuGet.Config maps `PouryaKit.*` to the feed, isolated `NUGET_PACKAGES`. A literal derived from the sourceName is unsafe for anything with its own syntax: the RabbitMQ service name now comes from a `derived` symbol on `name` with `forms` (`chain` of `lowerCaseInvariant` and two `replace` regexes), replacing its own token `modular-monolith`; the engine applies it in tests too.
- **WebApplicationFactory with top-level Program:** `DeferredHostBuilder` lets Program run `app.RunAsync()` right after `Build()`, so a `CreateHost` override that migrates after `builder.Build()` races the real start, and a build-only factory gets started anyway ("Hosting failed to start", ObjectDisposedException after dispose; disposing an unstarted one throws ArgumentNullException in `Host.StopAsync`). Migrate in an `IHostedService` inserted at index 0 (hosted services start in order); compose without starting anything by `ConfigureTestServices(s => s.RemoveAll<IHostedService>())`. Wolverine applies `IWolverineExtension`s only at start; a test applies them to `WolverineOptions` itself to read `ServiceName`.
- **Pack-time version.** NuGet's `GenerateNuspecDependsOn` runs `_GetPackageFiles` before MinVer; a target on `TargetsForTfmSpecificContentInPackage` with `DependsOnTargets="MinVer"` sees `$(PackageVersion)` and adds `TfmSpecificPackageFile` items, also under `dotnet pack --no-build`. `Directory.Build.targets` overrides `Description`; set `PackageDescription`.
- **Repository checks a template package breaks:** `Sample.KitPackages` does `Assembly.Load` per `src/` folder (skip it), `PackageArtifacts` SourceLink needs a dll (skip by nuspec `packageType` Template), `PackageGraph` needs a row, `validate.py` would evaluate template-content csproj files as packable through the root `Directory.Build.props` (skip `src/PouryaKit.Templates/content`). A `PackageReference` to a Template package restores, but without assets, so it proves nothing: since #54 the publication step installs it from the feed instead ([[templates-packaging-and-publication-facts]]).
- **WebApplicationFactory<Program> in a generated test:** `Program` is public by itself in .NET 10; `UseSetting` values are visible to `builder.Configuration` reads before `Build()` (Wolverine's connection string); two test classes calling `CreateClient` at once start two Hosts and race migrations, so start it in `InitializeAsync` (`_ = Services`). `WithWebHostBuilder(ConfigureTestServices(...))` then `.Services` throws the Host's build exception as is.
- **NuGet graph gap:** a Host's direct `Microsoft.EntityFrameworkCore.Design` with `PrivateAssets="all"` drops that package from a referencing test project's graph although `WolverineFx.EntityFrameworkCore` depends on it; `RestoredPackage.InConsumer` now skips a dependency the graph left out (first validate run failed on it).
- **Global cache pollution:** `dotnet ef`, `dotnet run` or a `dotnet new` restore post-action on a generated solution under a folder whose `NuGet.Config` names a probe feed, without `NUGET_PACKAGES` set, puts dev `PouryaKit.*` versions (height-based, can collide with a later published one) into `~/.nuget/packages`. Remove them file by file after checking `.nupkg.metadata`'s `source` is the probe feed.
- `WebApplicationBuilder.ConfigureContainer` is an explicit interface member: cast to `IHostApplicationBuilder`. Its `configure` callback sees the final collection, which is how a Host without Modularity runs `EnsurePouryaKitDeclaredAuthorizers()`.
- **The growth path as generated at `325834f` (#54 docs reconcile):** the two solutions differ in 12 files and the modular adds Billing, Inventory, `CatalogProducts.cs` and `CrossModuleTests.cs`; 9 change when Catalog becomes a Module (`Directory.Packages.props`, `Catalog.csproj`, `CatalogModule.cs`, the five endpoints, `Program.cs`), 3 only by the extra Modules (`.slnx`, Host csproj, `appsettings.json`). Since #61 the monolith's `AddCatalog()` names `typeof(CatalogModule).Assembly` and no declaration names a Module, and `Program.cs` ends with `AddPouryaKitCompositionChecks()` (a second call is a no-op), no `ConfigureContainer`. `templates.md` "Growing the monolith…" holds the list; re-diff after any change to the monolith's own files.

## validate.py and clean consumers

- `validate.py --output <dir>` fails with `[Errno 17] File exists` when `<dir>` holds an earlier run: after a further commit, `rm -rf` the scratchpad folder (system temp, allowed) and run it again.
- `python3 scripts/packaging/validate.py --no-fetch --output <scratchpad dir>` runs fine from a worktree after the commit (clean tree required): about 5 minutes, Docker needed, 403 runtime tests at #37, then 14 packages and 16 clean consumers.
- `scripts/packaging/validate.py` refuses a dirty checkout and only builds the clean consumers (never runs them), so a consumer proves the packed API compiles; `single-module.cs` is copied as the single-module composition's `Program.cs` (ImplicitUsings and TreatWarningsAsErrors on). Commit first, run it, then add its PASS line to the docs.
- `scripts/packaging/validate.py --no-fetch --output <scratchpad>` works from a worktree (~6 min) but needs a clean tree for its whole run, and this memory directory is tracked: write memory only after it finishes.
- `validate.py` refuses a dirty tree and checks HEAD at the end: commit first, run it (~15 min, Release suite 520 tests), then record the PASS line in a docs-only commit. `consumers/<package>.cs` replaces the generated Program.cs; consumers are built, never run. Pre-check one against `src/` with a scratch Exe project (ImplicitUsings, TreatWarningsAsErrors).
- `validate.py --no-fetch` on #49 passed the first time (~6 min, 421 runtime tests). "Image is too small" in `control-missing-sourcelink.log` is the negative control, not a failure.
- validate.py at #42: 643 runtime tests, `PASS 18 packages, 20 clean consumers`; a new `consumers/<package>.cs` source for an existing package adds no consumer to the count.
- **validate.py's log has no test counts**: it prints commands and the PASS line; take counts from your own verify runs.
- **Running it from a role session (#66, 2026-10-08):** a background Bash with the output redirected to a scratchpad log and `; echo "exit=$?" >> <log>` appended, then a foreground scratchpad Python script that polls the log for the `exit=` line (timeout 600000): it finished inside one wait, under ten minutes. The version and the commit it ran on are in `<output>/manifest.json` (`"version"`, `"commit"`).
- **validate.py flake (2026-10-08):** `CachingTests.With_redis_a_second_host_reads_the_entry_the_first_stored_without_running_its_handler` once failed in the Release runtime suite with `RedisConnectionException` from the test's own `ConnectionMultiplexer` (its container refused the connection); an unchanged rerun passed. Rerun once and record both runs in acceptance.md.
- `validate.py` with both template consumers: about 7.3 min, the template consumers about 85 s of it.
- **`--since <ref>` skips only for docs and AI setup** (`EXEMPT_DIRECTORIES`, `EXEMPT_FILES` at the top of the script): a ticket that changes only `tests/` and docs still validates in full, since `tests/` is built and run. Expect a PASS line, not a SKIP (#68, 2026-10-09: under ten minutes, `PASS 21 packages, 24 clean consumers`).
- **A clean consumer that exercises a packed API:** since #40, `validate.py` copies `scripts/packaging/consumers/<consumer name>.cs` to Program.cs for any consumer that has one; per-package consumers are named by package id, so `PouryaKit.Security.cs`. Consumers are only built, never run. This leaves `inventory.json` alone, which parallel tickets edit. A full `validate.py --no-fetch` took ~6 min: 15 packages, 17 consumers, a Release runtime suite of 479.

## Publication feed (#54 publication, 2026-10-08; SDK 10.0.401)

Check `.github/workflows/package-publication.yml` before relying on it.

- **A `PackageReference` to a `PackageType=Template` package restores silently:** exit 0, no NU warning, an empty target entry (no compile/runtime/build assets). A feed consumer must install it (`dotnet new install <id>@<version> --debug:custom-hive <abs>`) and generate from it.
- **`dotnet new install` and NuGet config** (decompiled `Microsoft.TemplateEngine.Edge` `NuGetApiPackageManager`, ilspycmd): sources come from `Settings.LoadDefaultSettings(Directory.GetCurrentDirectory())`, there is no `--configfile`; an `--add-source` equal to a configured source is skipped, otherwise added unnamed, so it never gets `NuGetPackageSourceCredentials_<name>` (NuGet's `PackageSourceProvider` attaches those to configured named sources only). It ignores packageSourceMapping: every enabled source is queried, the first with the exact version wins. The step runs the install from a folder holding a `NuGet.Config` copy with `dotnet nuget disable source nuget.org`. SDK 10 deprecates `id::version` (prints a notice); use `id@version`.
- **Running a workflow step locally:** a scratchpad Python script extracts the step's `run: |` block (as `tests/releases/publication/test_publication.py`'s `block()` does), swaps the GitHub feed URL for an empty local folder and runs `bash -c` with the step's env; the step's real `dotnet nuget push` then fills that folder (local push warns that `--skip-duplicate` is unsupported, harmless). A missing package in the manifest is the negative control. Earlier `validate.py --output` folders in the session scratchpad hold a real `manifest.json` and `packages/` to feed it.
- The push-and-prove step takes about 40 s locally for 21 packages, two templates generated under two names each (one shared `--packages` folder, so later restores are warm).

## The smoke test in Production and a local template probe (#64, 2026-10-08; SDK 10.0.401, ASP.NET Core 10.0.12)

- **A second, Production Host of the generated `Program` in the smoke test:** `app.WithWebHostBuilder(b => b.UseEnvironment(Environments.Production))`, then `CreateClient()`, beside the fixture's Development Host on the same database, in Debug and Release. The derived factory runs the fixture's `ConfigureWebHost` first (its settings and the migrations hosted service), and the environment reaches `WebApplication.CreateBuilder(args)` because the factory hands the web host builder's settings to the entry point as command-line arguments. Wolverine runs Static there with no registry and only warns. A test changed in place leaves the smoke-test counts at 4 and 5.
- **Probe a template change before `validate.py`** (a few minutes, against 7 to 15): `dotnet pack PouryaKit.slnx -c Release -o <out>/packages` from the dirty tree, `dotnet new install <templates nupkg> --debug:custom-hive <out>/hive`, then per template a folder with the `NuGet.Config` of validate.py's `consumer_feed`, `dotnet new <template> -n <name> --no-restore --debug:custom-hive <out>/hive`, `dotnet restore --configfile` with `NUGET_PACKAGES` and `DOTNET_CLI_HOME` under `<out>`, `dotnet build -c Release --no-restore` and `dotnet test --project … -c Release --no-build`. A red run needs no second pack: edit the generated file (the solution's own `<Name>.ServiceDefaults/Extensions.cs`), build and test again. The pack leaves nothing tracked in the worktree.

## A text rule over a template's own files (#68, 2026-10-09)

- **The monolith's own `CatalogModule.cs` registers `IProductRepository`** (`services.AddScoped<IProductRepository, ProductRepository>()`), though a search for `IRepository` in the template content finds nothing. A rule that refuses the name refuses shipped content; `TemplateRules.RepositoriesTaken` matches a declaration (the type, then a name) or a `…Service<T>` resolution, with `//` comments removed first, so the registration's type argument passes.
- **`Own(Monolith)` is `content/monolith` only.** What both templates share is `Own(Shared)`: join the two for "the monolith's own files", and filter to `.cs` (the lists hold project, solution and JSON files too).
- **Red once for a text rule:** a scratchpad script that swaps one part of the rule at a time and runs `TemplateTests` showed each part matters (six runs, about 5 s each). Put one legitimate shape into the offending set (a comment that names the type) so the exact-messages assertion also pins what the rule must not refuse.

## A third-party version bump (#75, 2026-10-09; WolverineFx 6.46.0 to 6.48.2)

- **The templates pin third-party packages too:** each `content/{modular,monolith}/Directory.Packages.props` pins `WolverineFx.RuntimeCompilation` (and the other packages a generated solution references directly), and `TemplateTests` fails until they equal the root's. A bump of a root pin that a template also pins moves both.
- **Proving what restore moved:** a scratchpad script that collects every `type: package` key of each `obj/project.assets.json` (skip `/content/`) before and after the bump, then `diff`; and a nuspec diff of the bumped packages from `https://api.nuget.org/v3-flatcontainer/<id>/<ver>/<id>.nuspec` (licence, target groups, net10.0 dependencies). Licences of the moved transitive packages read from the cache's nuspecs.
- **A follow-up patch bump (#75 follow-up, 6.48.2 to 6.48.3):** the same seven pins move with one `sed` over the three props files; the restore diff (312 package versions before and after) and the nuspec diff (nuget.org and the cache after the restore) are the proof the brief wants, and `RabbitMqDeliveryTests`, `RecurringCommandTests`, `DelayedCommandTests` and the full suite took about 50 s, 27 s, 16 s and 2m31s on this machine.
- **Where an implementer's brief lives:** the main checkout's untracked `.claude/handoff/<run>/briefs/`, not the worktree; read it by absolute path.
- **`--since` does not skip `.editorconfig` or `tests/` (#77):** only `docs/`, `.agents/`, `.claude/`, `.codex/`, `.githooks/` and five root files are exempt (`EXEMPT_DIRECTORIES` in `validate.py`), so a ticket touching a test project or the editorconfig runs the full validation, whatever its brief expects.

## The smoke test through PouryaKit.Testing (#87, 2026-10-10; SDK 10.0.401, ASP.NET Core 10.0.12)

- **`HostFixture` cannot host a top-level `Program` through `WebApplicationFactory`:** the factory's entry point starts the Host on its own thread right after `Build()`, so the fixture's migrate-then-start order is lost (the #53 bullet above), and every workaround in a test project (a gate hosted service, a second Host to migrate, JasperFx refusing the arguments) is more hosting code. The session's answer: each template Host composes in `AppHost.CreateBuilder(args)` / `AppHost.Build(builder)`, `Program.cs` a one-liner over them, the sample's `ModularMonolithHost` shape. A class name without the `sourceName` (`AppHost`, not `ModularMonolithHost`) survives the engine; its namespace becomes `Acme.Shop.Host` and `acme_shop.Host`.
- **The fixture over `AppHost`:** `CreateHost` passes `--environment`, `--ConnectionStrings:app` and the bearer settings as arguments to `CreateBuilder`, adds `builder.WebHost.UseTestServer()` and calls `Build`; a second Production Host is `ComposeHost("Production", …)` then `HostFixture.StartHostAsync`, a build-failure test asserts on the throw of `Build`, and a broker test builds and never starts. Under MTP the working directory is the test output, where the Host's `appsettings.json` is copied, so it loads as under the factory.
- **Template central versions are not "pins" in the #75-only sense:** the session ruled that the templates' props mirror the repository's versions, so an entry the generated test project needs (`Microsoft.AspNetCore.TestHost` 10.0.12, `PouryaKit.Testing` at `$(PouryaKitVersion)`) is added and an orphan (`Testcontainers.PostgreSql`, `Microsoft.AspNetCore.Mvc.Testing`) removed; `VersionDifferences` only checks a template entry against the root's.
- **`validate.py`'s closure split:** `check_consumer` reads a project under a `tests` path segment as a test project, whose closure may hold `excluded` packages; `inventory.json`'s `tests` key adds the test-only packages to the evidence's expected list; `check_production_publish(host, published, refused)` refuses a published `*.dll` whose stem starts with a refused prefix.
- **A local probe of both templates:** `scratchpad/p87/probe.py` imports `validate` (`consumer_feed`, `template_consumer`, `isolated_env`), packs the dirty tree, installs into a hive and builds and tests both generated solutions (about 4 minutes). Generating both templates with one `-n` and `diff -rq` shows the growth path's file count.

**Why:** each cost a probe or a validation run; the credential rule is not testable without the hosted feed.
**How to apply:** for a new template or any package that is not a library, any `validate.py` run, any clean consumer, any change to the publication workflow, and a hosted proof of the private feed.
