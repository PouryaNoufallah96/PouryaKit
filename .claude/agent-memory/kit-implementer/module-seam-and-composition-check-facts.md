Verified in ticket #61 (2026-10-07), .NET 10.0.12, WolverineFx 6.46.0, JasperFx 2.80.2; check the merged code first:

- **Composition checks run when the container is built, not at start** (fix round, review F1, high): a built, unstarted Host runs Operations through `IGatewayProcessor` (tests do), so a `StartingAsync` check let a `[RequiresPermission]` operation run unchecked. `ValidatingServiceProviderFactory` runs every `ICompositionCheck` on the built provider before returning it; only the replaced-factory sentinel stays at `StartingAsync`. Any Kit guarantee about composition belongs to the build.
- **The Kit's delivery commands** (`Deliver`, `RunDelayedCommand`, `StartRecurringCommand`) are registered by `UsePouryaKitWolverine` in every Host, so a check over "every registered command" misfires (review F3). Registering them per declaration was rejected: on a Module's builder `HostModules` would record a Kit command as the first declaring Module's. The Unit of Work check counts only commands whose type or registered handler (`ImplementationType`) is in a recorded Feature assembly: a scanned handler of a Contracts assembly's command counts too (second review, F7). Fixture: `Unversioned/SeparateCommandHandler` handles `Unowned`'s `UnownedCommand`; the command must sit in an assembly nothing `AddPouryaKitCqrs`-scans without its handler, or the scan fails with "has 0 handlers".
- **`AddPouryaKitModules` no longer calls `AddPouryaKitCqrs()`**: anything a Unit of Work resolves in a factory (the Domain Event drain, review F2) must come with `AddDispatcher`, since `ValidateOnBuild` cannot see inside factories.

- **`Host.StartAsync` order:** it resolves every `IHostedService` first (constructing `WolverineRuntime`, so `WolverineOptions` and every Kit `IWolverineExtension` check run then), then `IStartupValidator` (`ValidateOnStart` options), then each `IHostedLifecycleService.StartingAsync`, then `StartAsync`. Composition checks run at `Build()`, before all of that, so they come before any Wolverine start-time refusal (missing publication, wire-name clash) or options failure; only the replaced-factory sentinel runs at `StartingAsync`, still before Wolverine or the web server starts. One `StartingAsync` exception is rethrown unwrapped (assert `InvalidOperationException`, not `AggregateException`); nothing needs stopping after it.
- **JasperFx `RunJasperFxCommands` with `AutoStartHost`** starts the pre-built Host synchronously in `buildExecutor`, with no catch, so a start failure leaves `Main` as is and `WebApplicationFactory<Program>.Services` rethrows the same `InvalidOperationException` (the generated `HostTests` passed under `validate.py`).
- **Decision A trap:** `module.AddPouryaKitCqrs()` with no assembly on a test Module defined in `ModularMonolith.Tests` scans that whole assembly (every Stub handler), and `EnsureUnitOfWorkForCommands` then throws. Test-only Modules register their one handler by hand; `AddPouryaKitModules` registers the dispatcher.
- **Null-owned declarations fail at build in a Host of Modules**, and Module-named ones fail at build in a Host without Modules that calls `AddPouryaKitCompositionChecks` (the commit-time Snapshot refusal is only the backstop of a Host without the checks). A test that adds `builder.Services.Publish/Subscribe/...` to an `AppFixture.ComposeHost` Host and builds it must name the Module (`typeof(StubModule)`, `typeof(CatalogModule)`); a test that only asserts an earlier failure (Wolverine extension at hosted-service resolution) still gets its own message.
- **A valid Notification Handler, or a Feature command, no Module declares** needs an assembly nothing scans: `tests/ModularMonolith.Tests/Unowned` (its own csproj, excluded from the test project's sources, in the slnx). Every handler in the Stub's assembly belongs to the Stub, so declaring them again without a Module is refused at registration, not at start.
- **Every Module `AddPouryaKitModules` adds is recorded** in `HostComposition.Modules` (`ModulesBuilder.Add` calls `IModuleServices.ModuleOf`), whatever its Composition Root registers (test `QueryOnlyModule`); its Feature assemblies are recorded only by a Kit registration that scans.
- Mutation scripts `mutate61.py` and `mutate61fix.py` (several replacements per mutation) in the session scratchpad: 13 mutations, each restored from a backup in `finally`. `x ?? (DateTime.Now.Year > 0 ? new T() : null) ?? throw ...` disables a `?? throw` guard without a constant-condition warning.
- Edit traps: `s.replace("_module", "Module")` also rewrote `_modules` (use `\b`); IDE0032 is an error for a private field read by an expression-bodied property (make it an auto property). A `cat > <scratchpad>/x.py <<'EOF'` was refused once mid-session after several passed: write scripts with the Write tool.

**Why:** each cost a run or decided a #61 test, and #62 adds its checks on the same runner.
**How to apply:** when adding a composition check, a test Host with Host-level declarations, or a test-only Module. Related: [[declared-authorizer-check-facts]], [[codegen-production-facts]], [[messaging-delivery-facts]].
