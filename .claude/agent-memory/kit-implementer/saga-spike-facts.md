## Saga spike (#141, 2026-10-18; WolverineFx 6.48.3, JasperFx 2.80.2)

- **A Kit subscription shadows a saga on the same CLR type.** `HandlerGraph.HandlerFor(type, endpoint)` returns the `AddMessageHandler` pre-built handler on every queue unless the chain has a sticky endpoint, and a single saga never gets one (`SagaChain.maybeAssignStickyHandlers` separates sagas only with 2+ saga types in `Separated` mode). A saga queue fed with the subscribed type gets `SubscriptionDelivery` and an `UnknownSubscriptionException` dead letter. Fix used: a Kit wrapper type per saga and event, `SagaInput<TSaga, TEvent>`, with `[SagaIdentity] string SagaId`.
- **A custom `IMessageRouteSource` that finds routes ends the search at the first non-additive source**, even one that finds none (`WolverineRuntime.findRoutes`): `AgentMessages` precedes `ExplicitRouting`, so an additive Kit source silently drops the type's subscription routes. The source returns the explicit routes itself (`Transports.AllEndpoints()` whose `Subscriptions` match, `MessageRoute.For`) and is non-additive. `Endpoint.ShouldSendMessage` and `Subscription.IsFromConvention` are internal.
- **The Kit owns the saga's transaction through `SagaSchemaCodegen.HelperType`**: an `IHandlerPolicy` removes any `EnrollAndFetchSagaStorageFrame` (Wolverine's built-in `SagaPersistenceChainPolicy` adds one, before handler policies run, to a chain whose step returns the saga, e.g. a static `Start`) and inserts Wolverine's own frame with a Kit helper type at index 0, then a guard frame; `ISagaStorageFrame` is internal, so the frame must be Wolverine's class. `DatabaseEnvelopeTransaction._tx` and `DatabaseSagaStorage._tx` are private; the helper opens the connection itself from `IMessageDatabase.DataSource` and enlists `new DatabaseEnvelopeTransaction(database, tx)`.
- **Lightweight saga storage commits at the end of the generated method**, after every middleware, postprocessor and `AfterCommit` frame; the envelope's handled mark comes later and outside that transaction (only EF Core's envelope transaction marks in-transaction). A probe in the Kit storage wrapper's `SaveChangesAsync` is the deterministic stop between commit and mark.
- **Wolverine's logical deduplication (6.31+, `MessageDeduplicationMode.CompareByHash`, `RequireDeduplicationId`, `MessageDeduplication.ByMessage<T>`) claims on its own connection** for a relational store; only Marten, Polecat and Fisher supply `TryBuildTransactionalDeduplication`. A kill inside the step loses the step: the redelivery is refused as a duplicate.
- **Fix round (review of 28c3062a)**: a saga identity built as `$"{tenant}:{key}"` let tenant `a:b` with key `c` meet tenant `a` with key `b:c`; escape each part with `Uri.EscapeDataString`, as `HybridQueryCache` does, and test with text keys, not Guids. A timeout's stable identity is kept in `PouryaKitSaga.Timeouts` by envelope id when the Kit's storage inserts or updates the saga, read from `MessageContext.Outstanding` (public: the envelopes the step stored, not yet sent); the helper loads the saga in the step's transaction before Wolverine does, to claim the timeout under that identity. A reading of a spec clause in place of following it is a review finding: follow it, or mark the ADR `proposed` and ask the owner.
- **Second fix round (review of 09f766a9)**: a derived identity of something a step makes several of (timeouts) needs a per-item discriminator: `TimeoutId(step, wireName, ordinal)`, the ordinal counted per type in `MessageContext.Outstanding` order (a `List` Wolverine appends to, `MessageBus.cs:17,73-78`); a step rerun after a rolled-back attempt recomputes the same values. Emissions stay one per type per step. A start-time guarantee the built container answers (`WolverineOptions.ServiceLocationPolicy`) is stated as an `ICompositionCheck` even in a spike's invariant table: reviewers apply the AGENTS build-time rule to ADR rows too.
- **Wolverine names a type at `PublishMessage<T>()`**: called in `UsePouryaKitWolverine`'s `configure` hook it names an Integration Event before the Kit's `RoutingCheck` declares its wire name, and the Host fails to build; register such routes in an `IWolverineExtension`. Never call `ToMessageTypeName()` in a Composition Root.
- Saga state JSON is STJ defaults (PascalCase); the saga table is created lazily at the first step (`EnsureStorageExistsAsync`), in the store's `DatabaseSettings.SchemaName`. A `TimeoutMessage` cascaded from a step carries `Envelope.SagaId` and keeps its stored envelope id when it moves from Scheduled to Incoming; its wire name is its type's full name.
- **Wolverine's default `ServiceLocationPolicy` is `NotAllowed`** (`ServiceLocationPolicy` lives in `JasperFx.CodeGeneration.Model`): a generated chain that takes the Kit's `Operation` (an opaque scoped factory) or a Kit service with an internal implementation is refused at the first message, `Wolverine.Configuration.InvalidServiceLocationException`, and dead-lettered. With `AllowedButWarn`, a middleware's `IServiceProvider` parameter and the step's located services share one scope.
- Harness: the JasperFx source generator in a test project discovers `IWolverineExtension` types, so a nested private extension fails the build (CS0122); make it top level. `IMessageBus` is scoped: publish from a test through a scope. Red runs: a scratchpad Python script that replaces one line (a switch default or one statement), runs one test with `dotnet test --project … --filter-method`, and restores in `finally` (`p141/red141.py`, 12 mutations); make each test's waits locate rows by business data, not by the identity the switch changes, so the red fails at the guarantee's assertion. A Release publish test can run `codegen write` in the spike's own Host folder and delete `Internal/Generated` after; ignore it in a spike `.gitignore`.
- `validate.py --since` ran in full on the spike's code commit (`spikes/` is not exempt): PASS, 31 packages, Release suite 1162, about 15 minutes; the record commit after it stays Markdown-only. **Keep every Markdown file, memory notes included, out of the code commit**: the record lands by cherry-picking the record commit alone (`docs/agents/running-a-spec.md`), so a memory file created in the code commit and edited in the record would not apply; #141 rebuilt its branch and validated again for it.

**Why:** each cost a failed run in #141, and #142 builds the Saga package on the same seams.
**How to apply:** before writing #142's Saga package or any Kit route or handler beside a Wolverine-generated chain. Related: [[wolverine-runtime-and-delivery-facts]], [[marten-stream-write-model-facts]], [[worktree-shell-and-check-gotchas]].
