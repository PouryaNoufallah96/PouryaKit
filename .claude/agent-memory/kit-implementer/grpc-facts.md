## gRPC services and clients (#134, 2026-10-18; Grpc 2.84.0, Google.Protobuf 3.36.2, ASP.NET Core 10.0.12)

- **`Grpc.AspNetCore` carries `Grpc.Tools` with `include="All"`** (its nuspec), so a library on the metapackage pushes protoc's build targets into every consumer. The Kit package references `Grpc.AspNetCore.Server` and `Grpc.Net.ClientFactory`; the project with the `.proto` (Catalog.Contracts) takes `Google.Protobuf`, `Grpc.Core.Api` and `Grpc.Tools` (`PrivateAssets="all"`). `ReferencesOfContracts` rejects only `PouryaKit*` and Modules, so that passes; `PackageGraph.KeptOut` keeps `Grpc.Tools` out of the package.
- **`MapGrpcService` adds a catch-all `{unimplementedService}/{unimplementedMethod:grpcunimplemented}` with no method metadata**: routing's method policy then routes every method on any two-segment path to it, the constraint fails, and a Module's 405 and 415 become 404 (`WebTests` routing rows, only in the full run). `AddGrpc(o => o.IgnoreUnknownServices = true)` skips it (decompiled `ServiceRouteBuilder<T>.CreateUnimplementedEndpoints`).
- **gRPC over TestServer:** `GrpcChannel` or `ConfigurePrimaryHttpMessageHandler(() => new Http2(server.CreateHandler()))`, where `Http2` sets `response.Version = request.Version`; the in-memory server answers 1.1 and the client refuses it. A trailers-only answer written by hand (200, `application/grpc`, `grpc-status`, `grpc-message` escaped with `Uri.EscapeDataString`) is read by Grpc.Net.Client with the exact message.
- **A `Finally` added on a group after `BeginOperationPerRequest()` wraps outside Web's wrapper**, so it catches the `BadHttpRequestException` Web's internal `KitBadRequestException` derives from; Grpc.AspNetCore's delegate turns every service exception into a status itself.
- **Per-call context with no slot in `CallOptions`:** the extension copies the headers into a new `Metadata` and keys the context on that instance in a `ConditionalWeakTable`; the interceptor looks it up and writes `OperationContextHttpHeaders.Pairs`.
- **`IStartupCheck` runs in `StartingAsync`, before Kestrel binds**: `IServerAddressesFeature` holds only `app.Urls`; read `urls`, `http_ports`, `https_ports` and `Kestrel:Endpoints:*:Url` from configuration, parse with `BindingAddress.Parse` (handles `*` and `+`). A `ValidateOnStart` failure comes before it.
- `SharedJsonTests` pins the callers of `UsePouryaKitJson` by type name in two lists; a new caller is added there, and its test names are cited by acceptance and ADR 0006, so keep them.
- A sample `.proto` is not packed by `PouryaKit.Templates` unless its csproj globs `Modules/**/*.proto` (approved line, #134); a gRPC service that calls the Gateway is a Gateway-bound adapter: the monolith excludes it (`**/*GrpcService.cs`) and has its own on `IDispatcher`.
- **Review of #134 (dual, two highs):** an every-address listener (`http_ports`, `*`, `0.0.0.0`) must match only a loopback client, or every peer on the shared container port 8080 fails the start; a writer of Kit headers removes the codec's whole name list (`OperationContextHttpHeaders.Names`, internal), not the names `Pairs` returned, or a stale tenant survives beside a tenantless context. Cross-package reuse of Web's internals goes through `InternalsVisibleTo` in Web's csproj (as Cqrs opens to Web), never a copy.

## Follow-ups (#158, 2026-10-18; ASP.NET Core 10.0.13, Grpc.Net.ClientFactory 2.84.0)

- **Kestrel 10 binds only `http://localhost:5000` with nothing configured** (`AddressBinder.DefaultAddressStrategy`; the docs' https 5001 is the ASP.NET Core 6 text). The default applies only when both the addresses and the listen options are empty, so add it after the precedence, never inside the hosting-URL list (it would flip `preferHostingUrls`). Add it only when `IServer` is Kestrel's (internal `KestrelServerImpl`: compare its assembly with `typeof(KestrelServerOptions).Assembly`), never for a client-only Generic Host or the test server (review F1). Kestrel's `ListenOptions` set in code are internal (`CodeBackedListenOptions`); #159 moved that case after the bind (below). A Kestrel test Host: `builder.WebHost.UseKestrel()` in `AppFixture.ComposeHost`'s configure (overrides its `UseTestServer`; needs `using Microsoft.AspNetCore.Hosting`); in `ModularMonolith.Tests`, `Host.` resolves to the `ModularMonolith.Host` namespace, so write `new HostApplicationBuilder(args)`.
- **`AddGrpcClient<T>(name)` is not idempotent:** a repeat appends a second transient `T`, configure and post-configure, and `AddInterceptor` a second interceptor; only another type under the same name throws (`ReserveClient`). **`services.AddHttpClient(name)` is not side-effect free either:** `AddMetrics` appends `ValidateOnStart<NoOpOptions>` (one descriptor) on every call. A private `record ClientBuilder(string Name, IServiceCollection Services) : IHttpClientBuilder` returns a builder that registers nothing.
- Web's `MapPouryaKitModuleEndpoints` maps every endpoint again on a repeated call (no guard, only `MappedEndpoints.Add`): a latent duplicate, outside a gRPC ticket's scope.
- Decompile framework code with `ilspycmd -t <type> <dll>`; the shared framework is under `~/.local/share/mise/dotnet-root/shared/`, not `/usr/local/share/dotnet`.

## Listeners set in code and the deadline (#159, 2026-10-18; ASP.NET Core 10.0.13)

- **No public reading of Kestrel's code-configured listeners** (`CodeBackedListenOptions`, `OptionsInUse`, `GetListenOptions()` are internal in 10.0.13), so the loopback check compares again in `IHostedLifecycleService.StartedAsync`, reading `IServerAddressesFeature`: `AddressBinder` clears it and adds each bound listener's display name (`http://localhost:6000` for `ListenLocalhost(6000)`, the real port for 0). Gate that step on Kestrel's assembly: `TestServer` sets an `IServerAddressesFeature` too, which `GenericWebHostService` fills with the configured `urls`, so an overridden `urls` would be falsely refused. `Host.StartAsync` rethrows a `StartedAsync` exception with its type. The pre-bind default was dropped: it could not tell "nothing configured" from "code listeners only". `ListenLocalhost(0)` throws (dynamic port on localhost); a test takes a free port from a `TcpListener` on loopback port 0.
- **Port 5000 is unusable on this Mac**: ControlCenter (AirPlay Receiver) listens on `*:5000`, and an orphan Aspire `dcp` held `127.0.0.1:5000`; a Kestrel default bind fails `address already in use`. No test binds 5000: Kestrel's default is proven by feeding the comparison a bound-address list (`InternalsVisibleTo ModularMonolith.Tests` in the Grpc csproj).
- **A refusal in `StartedAsync` must stop the Host itself** (#159 review F1): `Host.StartAsync` rethrows it without calling `StopAsync`, so a caller that catches it keeps Kestrel and every started hosted service; `StopApplication()` only signals, which stops nothing unless someone waits for the shutdown. `await services.GetRequiredService<IHost>().StopAsync(CancellationToken.None)` from `StartedAsync` works (the Host's `_hostStarting` is already true, so it stops every hosted service and notifies `ApplicationStopped`); prove it with `host.Lifetime.ApplicationStopped.IsCancellationRequested` and a refused `TcpClient` connect. `DurableQueuesCheck` and `RecurringCommandStart` stop the Host the same way since the final quality pass (2026-10-23); a recurring start's failure is not the Kit's to build, so a failed stop goes beside it in an `AggregateException`.
- `DateTime.UtcNow + TimeSpan.MaxValue` throws `ArgumentOutOfRangeException`; `deadline < DateTime.MaxValue - now ? now + deadline : DateTime.MaxValue` caps it, and gRPC sends no `grpc-timeout` for `DateTime.MaxValue`.

## A call across an OS process boundary (PR #143 thread, 2026-10-23; ASP.NET Core 10.0.13, Grpc 2.84.0)

- **Kestrel without TLS refuses gRPC on its default listener**: `Http1AndHttp2` with no ALPN answers the client's HTTP/2 with `HTTP_1_1_REQUIRED` (RpcException `Internal`). `Kestrel__EndpointDefaults__Protocols=Http2` in the environment also applies to the `ASPNETCORE_URLS` listener. The sample Host sets none, so as shipped it serves gRPC only over TLS.
- **Running `ModularMonolith.Host` as a process** (`ModularMonolithProcess` on `HostProcess`, the mechanism `InventoryProcess` shares): environment only, since `RunJasperFxCommands` reads arguments as its own ([[wolverine-runtime-and-delivery-facts]]); translate `TestIssuer.HostArguments` `--A:B=v` to `A__B=v` (split on the first `=` only: the base64 key ends in `=`). A Web SDK Host's content root is the working directory, so `HostProcess` starts `dotnet run` in the project's directory. Production on the fixture's migrated database starts in about 2 s from a Debug build: no pre-generated code needed, and it is a Balanced node beside the fixture's Solo one, so the test waits for deliveries before starting it.
- **What a plain sample Host process shows**: `Logging__Console__FormatterName=json` plus `Logging__Console__FormatterOptions__IncludeScopes=true` give one JSON line per entry, the dispatcher's scope an object with `Operation`, `OperationId`, `CorrelationId`, `Module` (Guids as strings). In JSON the "Now listening on: " line ends the URL at a quote. No output shows a continued Operation's Actor or causation; a tenant-scoped answer the peer's token names no tenant for proves the trusted continuation.
- A peer's bearer token for the trusted peer: `TestIssuer.Token(new() { ["sub"] = AppFixture.TrustedPeer })`.

**Why:** each cost a full-suite run or would have shipped a broken HTTP pipeline or package closure.
**How to apply:** any ticket that touches PouryaKit.Grpc, adds a transport on Web's convention, or tests a second Host over an in-memory server. Related: [[web-security-and-openapi-facts]], [[templates-packaging-and-publication-facts]], [[docs-verification-tools]].
