## Integration Events (#16, 2026-10-05; WolverineFx 6.46.0)

- **Wolverine message type names are process-global.** `WolverineMessageNaming` caches `Type -> name` in a static `ImHashMap` and `Envelope.MessageType` comes from `GetType().ToMessageTypeName()`. A per-Host declared wire name (Integration Events: plain Contracts records, no Kit attribute) must go into a static map in `WireNaming`; a second Host in the process declaring another name is refused. Declare only after the Host's own checks pass.
- **`IWolverineExtension.Configure` runs inside the `WolverineOptions` singleton factory**, built when `IWolverineRuntime` (a hosted service) is resolved: an exception there reaches `host.StartAsync()` unwrapped, not `Build()`. Missing-publication and wire-name checks live there; the no-Outbox and queue-durability checks live in `StartupCheck.StartedAsync`.
- **Concurrency proof without flakiness:** decorate `IReceipts` to hold the first delivery right after `RecordAsync` returns true (transaction open, Receipt uncommitted); `update wolverine.wolverine_incoming_envelopes set owner_id = 0 where id = X` makes recovery hand out the same row again at once in the default test Host (use the configured store schema for a custom Host; local queues run `max(ProcessorCount, 5)` in parallel); wait until `pg_stat_activity` shows `wait_event_type = 'Lock'` on the receipts insert; repeat; release. Mutation "RecordAsync always true" gave 3 effects.
- A local durable envelope row is not rewritten when Wolverine starts handling it, only when marked Handled: `pg_xact_commit_timestamp(xmin)` read while the receiver is held still shows the publishing commit.
- `AssertNothingSentAsync` and `WaitForDeliveriesAsync` wait for the store to settle before taking their baseline (ticket #15's last fix), so a setup Operation's late deliveries are no longer charged to the Operation under test.
- A publisher that must reach the Outbox across packages: Kit seams are public interfaces "for a Kit package" (`IReceipts`, `IIntegrationEventOutbox`), never `InternalsVisibleTo`. The test `CommitProbe.Install` reads `ImplementationType`, so any further decorator of `IUnitOfWorkOutbox` must be installed after it and handle a factory descriptor.
- After the #15 fix round (merged 2026-10-05): subscription names are lower-cased in `Subscription`'s constructor, so duplicate-name messages print the lower-cased name; the Outbox and durable-queue checks live in one `StartupCheck` (an `IHostedLifecycleService.StartedAsync`, registered with `TryAddEnumerable` by every declaration call), keyed on the `IOutbox` marker (renamed in #81). Add any new whole-Host delivery check there, not in a second place.
- #16 fix round: `IUnitOfWork -> IUnitOfWorkOutbox -> IReceipts -> IUnitOfWork` is a cycle through factory registrations; MS DI does not detect it and the test run hung (no error) for 10 minutes. Resolve such a Kit service lazily from the scope. Run any new delivery test with `--timeout 180s` (MTP) in the background.
- A durable local queue hands the first attempt the published in-memory instance (checked with ReferenceEquals); a `ScheduleRetry` attempt is read back from the store, a new instance. A test that claims identity/time survive serialisation must assert on a retry or a recovered delivery.
- The restart proof for a receiver: hold in the test `IUnitOfWorkOutbox.FlushAsync` decorator (runs after commit, before the delivery returns, so before acknowledgment) by `Operation.Module`, `StopMode.Quick` the Host, start a new one; count `IReceipts.RecordAsync == false` to prove the new Host really handed it out again.

## Versioned contracts (#49, 2026-10-07; WolverineFx 6.46.0)

- **Wolverine's type route matches by name, not by Type.** `PublishMessage(type)` adds `Subscription.ForType` (`RoutingScope.Type`, `Match = type.FullName`), and `Matches(m)` is true when `m.Name`, `m.FullName` or `m.ToMessageTypeName()` equals that FullName ignoring case. A record deriving from another is NOT routed to the base's subscriptions; a type whose wire name equals another subscribed type's full name IS (probe: routed to `local://tests.routed/`). The Kit refuses it in `Subscriptions.RoutingCollisions`, run by the extension before `WireNaming.Declare`.
- **Reading Wolverine source:** no sources ship in the nupkg; `ilspycmd -p -o <scratch dir> ~/.nuget/packages/wolverinefx/6.46.0/lib/net10.0/Wolverine.dll` (global tool installed) decompiles it in seconds. Inspect routes at runtime with `IWolverineRuntime.RoutingFor(type).Routes.OfType<MessageRoute>().Select(r => r.Uri)`.
- **Red for "Receipts are per subscription":** keying every Receipt by Module also turns away Catalog's second Notification Handler (one Domain Event id), so nothing is published at all; scope the mutation to Integration Events (`IsNotification ? Name : Module.Name`) to see Inventory's v1 or v2 effect go missing.
- #49 fix round: version-migration guidance is easy to get wrong. Receipts are keyed by subscription name, so a v1 and a v2 subscription applying the same effect both apply it. Removing the v1 subscription before the v2 one is live loses effects, because a type with no subscription is not stored. Stopping v1 starves every remaining v1 subscription, and a v1 subscription kept to drain still needs v1's `Publish` declaration or startup fails. Safe rule: replace them all in the release that stops publishing v1. Reviewers also flag "subscriber" (GLOSSARY avoid term); write "subscription".

## Strict wire reading (#60, 2026-10-07; .NET 10.0.12 STJ, WolverineFx 6.46.0, RabbitMQ 4.3.6)

- **STJ strictness, probed:** `RespectRequiredConstructorParameters` makes every ctor parameter without a default value required, a nullable one too (`string? Note` with no default must be present). `RespectNullableAnnotations` refuses null into a non-nullable property or ctor parameter on read AND throws on write. A class of `init` properties without `required` (and base-record init props) still reads any shape with defaults. `JsonSerializerOptions.Strict` (.NET 10) = Disallow unmapped, no duplicate properties, case-sensitive, both Respect flags. Messages: "JSON deserialization for type 'Ns.T' was missing required properties including: 'name'." and "The constructor parameter 'Name' on type 'Ns.T' doesn't allow null values. ..." (full type name).
- **A file-based probe** (`dotnet run probe.cs`) defaults to `PublishAot`, so reflection STJ throws "Reflection-based serialization has been disabled": add `#:property PublishAot=false`. `#:package` restores from the cache offline.
- **Wolverine's read failure:** `HandlerPipeline.TryDeserializeEnvelope` catches and returns `MoveToErrorQueue` (no retries, no failure policy) -> `MessageContext.MoveToDeadLetterQueueAsync` -> `IMessageInbox.MoveToDeadLetterStorageAsync` (`Wolverine.RDBMS` `DatabasePersistence.ConfigureDeadLetterCommands`: id, body, message_type, received_at, exception_type, exception_message). Over the Kit's broker topology the read is at `rabbitmq://queue/{serviceName}`, before the fan-out. The EF outbox serializes at `EfCoreEnvelopeTransaction.PersistOutgoingAsync` (`OutgoingMessage` ctor), inside the commit. Decompiled copies: scratchpad `decomp58/wolverine`, `stj60/{rdbms,efc,wrmq}`.
- **Two contract types under one wire name, one process:** `HandlerGraph.TryFindMessageType` is per Host, so the Catalog Host can `Publish<OtherShape>(wireName, typeof(CatalogModule))` while Inventory.Host `Receive<Shape>(wireName)`; publish straight through `IMessageBus` with the DomainEventId header (`StrictWireReadingTests`). Keep the publishing Host alive until the envelope arrives (an `await using` inside an `if` block disposed it too early).
- **SharedJsonTests trap:** Domain is in `Sample.KitPackages`, so a Domain method that calls `UsePouryaKitJson` (the wire variant) shows up as a caller; exclude Domain from the caller listings.
- **RabbitMQ 4.3.6 `amq.`:** queue and exchange declares under `amq.` fail 403 ACCESS_REFUSED "contains reserved prefix 'amq.*'"; `AMQ.` declares fine (case-sensitive). Wolverine's `RabbitMqExchange.CheckAsync` lower-cases the name. The Kit refuses any case (decision recorded in ADR 0006's #60 amendment; flagged as a design choice).
- **Outbound strict write:** the null throws `JsonException` inside `Envelope.Data`, which Wolverine wraps in `Wolverine.WolverineSerializationException` ("Error trying to serialize message of type …"); the dead letter's `exception_type` is the wrapper. Stack: `WolverineOutbox.WriteAsync` (in `EfUnitOfWork.RunAsync` before the save) -> `MessageBus.PersistOrSendAsync` -> `EfCoreEnvelopeTransaction.PersistIncomingAsync` (unmapped) -> `DatabasePersistence.BuildIncomingStorageCommand` -> `EnvelopeSerializer.Serialize`. Red by `json.UsePouryaKitJson()` in `UsePouryaKitWolverine`, inside the package, instead of touching Domain. The dead-letter table keeps no stack: read it from `Fixture.Logs` entries' exceptions.

## RabbitMQ topology (Spike #50, 2026-10-07; WolverineFx.RabbitMQ 6.46.0, RabbitMQ 4.3.6)

The record is the ticket #50 amendment of ADR 0006; check it before relying on this.

- **One envelope id on two queues:** a fanout exchange copies the Wolverine envelope id to every bound queue. Under `MessageIdentity.IdOnly`, the second Inbox insert raises `DuplicateIncomingEnvelopeException`, and that delivery is acknowledged and dropped silently. A queue per subscription needs `IdAndDestination`, which changes the keys of the incoming and dead-letter tables. The Kit chose one broker queue per Host, fanned out to local queues (keeps `IdOnly`).
- **Dead letters:** without `DisableDeadLetterQueueing()`, Wolverine declares a native `wolverine-dead-letter-queue`, and exhausted deliveries leave Wolverine's storage.
- **Addresses:** a queue listener's address is `rabbitmq://queue/{name}`. Its `Uri.Host` is `queue`, so a lookup by `Destination.Host` breaks. `ScheduleRetry` and recovery of such rows work through the listener circuit.
- **Durable receiver settles first:** the broker delivery is acknowledged once the Inbox insert commits, so the broker queue shows 0 while a retry waits in the store.
- **A mutation that did not fail:** under the fan-out topology, replacing the broker listener's `UseDurableInbox()` with `BufferedInMemory()` did not fail the restart test. The waiting retry sits in the durable local queue.
- **Harness: a vhost per test.** `container.ExecAsync(["rabbitmqctl","add_vhost",v])` plus `set_permissions -p v <user> ".*" ".*" ".*"`, then the AMQP URI path `/v`. The default Testcontainers user is `rabbitmq`.
- **Harness: connection exhaustion.** About 8 Host pairs on fresh databases exhausted PostgreSQL's 100 connections (53300). Set `-c max_connections=1000`, and register a data source with a factory: `AddSingleton(instance)` is never disposed.
- **Harness: builder constructors.** Testcontainers 4.15 marks parameterless builders obsolete; use `new RabbitMqBuilder(image)`.
- **Review lesson.** I first used "two Hosts with the same subscription name split messages under A" as a reason to reject A. It failed the fair-configuration rule: with A's queue named `{ServiceName}.{subscription}`, each Host got every message, and B has the same risk through a shared `ServiceName`. Before a naming or configuration choice counts against an option, try that option's best variant of it. In an ADR, write "Host", not "service" or "consumer", and "subscription", not "subscriber" (GLOSSARY synonyms).
- RabbitMQ.Client 7.2.2 is licensed `Apache-2.0 OR MPL-2.0`; the Kit takes it under Apache-2.0. WolverineFx.RabbitMQ pulls WolverineFx.Newtonsoft and Newtonsoft.Json, both MIT.

## RabbitMQ transport (#51, 2026-10-07; WolverineFx.RabbitMQ 6.46.0, RabbitMQ 4.3.6)

- **Every Wolverine 6 Host has an Application-role listener `stub://replies/`** (BufferedInMemory, `StubTransport`). A "every non-local listener is durable" check refuses every existing Host. Filter broker listeners with `endpoint is IBrokerEndpoint` (`Wolverine.Transports`), which RabbitMqQueue implements and stub/local/tcp do not.
- **`Endpoint.DeadLetterStorage`** (virtual, core) is the transport-neutral "is there a native broker DLQ" signal: `RabbitMqQueue` returns Native when its `DeadLetterQueue` mode is not WolverineStorage. No RabbitMQ type needed.
- **Transport setup works inside an `IWolverineExtension`** (`UseRabbitMq(connectionString)` accepts an amqp:// URI through `ConnectionStringParser`). `UseRabbitMqUsingNamedConnection` registers an `IConnectionFactory` in `options.Services`, too late from an extension; read the connection string at registration instead.
- **`SystemTextJsonSerializer` exposes no `Options`**; prove the JSON by reading the stored broker row's body.
- **Sample Catalog's commands are internal with IVT to `ModularMonolith.Tests` only**, so broker tests that drive Catalog through its Gateway must live there (a new test project cannot send them without widening Catalog's csproj).
- **appsettings.json of a referenced Exe flows into the referencing test's bin** and can shadow the Web Host's; the proof Host keeps its appsettings uncopied and sets `RunWorkingDirectory` to its project directory.
- **Probe timing:** a Catalog Host plus Inventory Host pair on fresh databases and a vhost starts and delivers in about 1.3 s per test; the whole 16-case broker class runs in about a minute.
- **Holding the gap between fan-out and the handled mark, with no Kit hook:** a `before update` trigger on `wolverine_incoming_envelopes` that runs `pg_advisory_xact_lock(n)` when a `rabbitmq:` row turns `Handled`, the lock held by the test's connection. Copies commit while the mark waits; `StopMode.Quick` stop returned at once with the mark still blocked; then `pg_terminate_backend` the `wait_event = 'advisory'` backends, drop the trigger, unlock, start a new Host. Count local copies with `message_type like 'catalog.%'`: the recurring `ReconcileStock` occurrence also sits on a local queue.
- **A child Host process:** `dotnet run --no-build --configuration <AssemblyConfigurationAttribute> --project <path>` with cwd at the repository root and config through env vars (`ConnectionStrings__app`) starts in about 2 s. Readiness: the broker queue's `ConsumerCount` > 0 (passive declare). `-- --help` means nothing to a generic Host: it starts and fails on its absent database.
- **`EndpointFor` to a durable local queue stores `Incoming`, owned by the node** (`DurableLocalQueue.StoreAndForwardAsync`, `PrepareForIncomingPersistence`), so a copy in flight at a kill is handed out again. The S2 `Outgoing`/owner 0 hole is only through an EF `DbContextOutbox`. `PublishAsync` from the fan-out would also hit the type's exchange route and loop forever through a stale binding.
- **A handler's own `MessageContext` swallows send failures (F6).** In a handler `Transaction == this`, so a send only joins `_outstanding`; `FlushOutgoingMessagesAsync` (run by `MessageSucceededContinuation` before `CompleteAsync`) catches each envelope's failure, logs "has been discarded" and never rethrows: a refused copy is lost while the envelope is marked handled. The fan-out sends through `new MessageBus(context.Runtime)` (Transaction null), whose `SendAsync` awaits `StoreAndForwardAsync` and throws after `DurableWriteRetry` (4 tries, ~400 ms). Proof technique: a `before insert` trigger on `wolverine_incoming_envelopes` that raises for one `received_at`; the dead letter's `exception_type` is `Npgsql.PostgresException`. Inventory.Host's own logs go to `RecordedLogs`, not the console.

## WolverineFx 6.48.2 and a broker connection drop (#75, 2026-10-09; WolverineFx 6.46.0 and 6.48.2, RabbitMQ 4.3.6)

- **Dropping a live Host's broker connections:** `rabbitmqctl close_all_connections -p <vhost> "<reason>"` inside the container (`BrokerFixture.DropConnectionsAsync`). Without `-p` (or `--global`) it closes only vhost `/`, which no test uses, so a drop test passes vacuously. Prove the drop landed: wait for the Host queue's `ConsumerCount` to reach 0, then > 0 (about 5 s, the client's recovery interval), then publish.
- **That drop does not reproduce JasperFx/wolverine #4864/#4867** (the 6.46.0 recovery loop that one `ReconnectedAsync` exception ends): the test passed on 6.46.0 too. The defect needs a rebuild that throws (teardown `ObjectDisposedException`/`NullReferenceException` on a channel recovery swapped, or a quorum queue's `BasicConsumeAsync` timeout); upstream's regression injects a fake agent. A single-node forced close raises none.
- **Health checks on 6.48.2:** `Wolverine.RabbitMQ` ships an internal `RabbitMqHealthCheck` and `Wolverine` a `WolverineTransportHealthCheckAdapter`, but nothing calls `BuildHealthCheck`, `AddCheck` or `HealthCheckServiceOptions`: no check is registered by default.
- **The 6.48.x notes:** 6.48.0 carries the listener-rebuild repair; 6.48.1 global-partition order; 6.48.2 leader assignment at scale plus `DurabilitySettings.LeaderTakeoverHoldEvaluations` (default 1, stands down while no other node holds an assignment); 6.48.3 (same day, after the ticket) blue/green warm-ups and an `IQuerySession` commit fix. `gh release view V6.48.2 --repo JasperFx/wolverine` prints a release's notes.

## WolverineFx 6.48.3, the #75 follow-up (2026-10-09; WolverineFx 6.48.3, RabbitMQ 4.3.6)

- **Release notes can omit a merged PR:** `gh api repos/JasperFx/wolverine/compare/V6.48.2...V6.48.3 --jq` (commits and `.files[].filename`) showed #4903 (`IgnoreEnvelopes` in `AddStage`, `TrackedSession`) that the notes leave out. `gh api .../compare/<merge sha>...<tag>` with `behind_by 0` proves a fix is in a tag. Taken: a single Balanced node hits none of 6.48.3's new branches; a multi-instance Host runs the move paths, proven only by upstream's tests.
- **Balanced vs Solo for agent-placement changes:** a Kit Host defaults to Balanced (`PouryaKitMessageStoreOptions.Durability`), so the leader's `AgentCommandDispatcher`/`AssignmentGrid` run on every Balanced node, even one; move-only branches never fire on a single node. Test Hosts run Solo (`UsePouryaKitTestDelivery`); the one started Balanced node is `Inventory.Host` as an OS process in Production (`InventoryProcess`). `DistributeByGroupAffinity` serves only `EventSubscriptionAgentFamily` (Marten projections).
- **Each Kit Host also listens on `wolverine.response.<guid>`** (auto-delete, broker-durable, one consumer), Wolverine's default System reply queue (`DeclareRequestReplySystemQueue = true`), on the listening connection: seen with `rabbitmqctl list_queues -p <vhost>` while a broker test ran. So ADR 0004's "one durable broker listener" is one durable listener plus this one.
- **Observing the test broker:** `docker exec <rabbitmq:4.3.6 container> rabbitmqctl ...` before the server is up creates `/var/lib/rabbitmq/.erlang.cookie` root-owned, and the broker dies at start (`eacces`, `BrokerFixture.InitializeAsync` fails). Gate on `Server startup complete` in `docker logs` first. `list_consumers`/`list_channels`/`list_connections` with column arguments printed nothing there; `list_queues` worked.

**Why:** each decided how delivery extends across Hosts, the version-isolation proof or the topology, or cost a run.
