# PouryaKit

A reusable .NET 10 foundation for modular monoliths built from vertical slices.

Status: Wave 1 is complete, and Wave 2 is under way. The Kit's packages (every entry of `scripts/packaging/inventory.json`), each usable on its own, make up fourteen Capabilities: domain primitives (`PouryaKit.Domain`); commands, queries and validation (`PouryaKit.Cqrs`, `PouryaKit.Validation`); Modules (`PouryaKit.Modularity`); persistence and the Unit of Work (`PouryaKit.Persistence`, `PouryaKit.Persistence.EFCore`, `PouryaKit.Persistence.Postgres`); Dapper reads (`PouryaKit.Persistence.Dapper`); messaging (`PouryaKit.Messaging`, `PouryaKit.Messaging.Wolverine`, `PouryaKit.Messaging.Wolverine.EFCore`), with, from Wave 2, delayed commands that continue the Operation that scheduled them and recurring commands declared under a named system Actor, both durable through a restart; web (`PouryaKit.Web`); testing (`PouryaKit.Testing`); and, from Wave 2, the three Core helpers (`PouryaKit.Core`): predicate composition, implementing-type lookup and the synchronization-context scope, capped at those three, and security (`PouryaKit.Security`): permissions a command or query declares, checked through the existing authorization hook and never checked again for a trusted continuation, beside the authenticated-by-default HTTP access `PouryaKit.Web` sets, which also sends the Operation Context on outgoing HTTP with the standard retry and lets configured, authenticated peer Hosts continue an Operation, and applies configured CORS policies, response compression and a rate limit per Actor whose rejection is a 429 problem response, optional PBKDF2 password hashing with upgrade detection, and optional JWT bearer authentication (`PouryaKit.Security.JwtBearer`): standard ASP.NET Core bearer validation whose issuer, audience, signature and lifetime checks cannot be turned off, with configured token claims normalized into the Actor and tenant; observability (`PouryaKit.Observability`): one activity and one duration in fractional seconds for every command and query, tagged with its Module, operation, Actor kind and outcome, and a delivery's Operation that continues the publishing Operation's trace and tracestate through the Outbox, proven for local delivery, with exporters left to the Host; caching (`PouryaKit.Caching`): a query's successes cached per Actor and tenant over `HybridCache`, never a failure and never inside a write Unit of Work, with the cache tags its commands declare evicted once an Operation commits, and Redis as the application's optional shared cache; paging with allow-listed sorting and filtering: one `PageRequest` and `Page` contract in `PouryaKit.Cqrs`, read through `PouryaKit.Persistence.Dapper` or `PouryaKit.Persistence.EFCore` and bound from the query string by `PouryaKit.Web`; request idempotency: a command that opts in, repeated with the same request id, over HTTP the `Idempotency-Key` its endpoint requires, replays its first success from a key reserved in its own transaction, never running or publishing twice (`PouryaKit.Cqrs`, `PouryaKit.Persistence.EFCore`, `PouryaKit.Web`); and the optional API versions and OpenAPI (`PouryaKit.Web.OpenApi`): versions a Module declares, served on its route group by URL segment and by `api-version` header, a deprecated version's configured sunset, one OpenAPI document per supported version with each operation's security requirement, and the Scalar reference; and the optional RabbitMQ transport (`PouryaKit.Messaging.Wolverine.RabbitMq`): Integration Events and Snapshots delivered between Hosts through one exchange per wire name and one durable queue per Host, fanned out to each subscription's own queue, so Receipts, retries, dead letters, Operation Context and versions hold as inside one Host. The Proving Sample in `samples/ModularMonolith/`, a Host of three Modules, or of Catalog and Billing beside `Inventory.Host` over RabbitMQ, proves every guarantee against PostgreSQL, and RabbitMQ and Redis where they apply, and architecture tests guard its boundaries and every package's dependencies.

The [package validation path](docs/packages.md) builds and tests Release once, packs every package in `scripts/packaging/inventory.json` at one MinVer version, and verifies them in clean package-only consumers. [CI](docs/ci.md) runs this path with read-only permissions, preserving tested-SHA receipts and bounded package artifacts. Same-repository hosted success/failure and permission isolation are verified; real private fork execution has an owner-accepted verification exception. [Private publication](docs/private-packages.md) downloads trusted main originals, uses standard NuGet push and restores every package of the inventory from the private feed. MinVer supplies snapshots and owner-tagged preview/rc versions through the same validation path. The owner narrowed [Phase 5](docs/foundation-review.md#phase-5-packaging-and-releases) on 2026-10-06; the active scope is complete, with [CI run 37465576160](https://github.com/PouryaNoufallah96/PouryaKit/actions/runs/37465576160) and [publication run 37466084084](https://github.com/PouryaNoufallah96/PouryaKit/actions/runs/37466084084) successful at `b234f4f`. The Capabilities of Wave 2 and later include multi-tenancy and the project template.

Build and test with the .NET SDK pinned in `global.json`:

```bash
dotnet build PouryaKit.slnx
dotnet test PouryaKit.slnx
```

With Docker running, validate the Release package set, PostgreSQL suite and clean consumers:

```bash
python3 scripts/packaging/validate.py
```

The command prints its evidence directory outside the checkout, including the packages, checksum manifest and separate runtime and consumer logs. It fetches origin's tags and completes shallow history before MinVer runs. [Package guidance](docs/packages.md) describes consumption and the proof boundary.
