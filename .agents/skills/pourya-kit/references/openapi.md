# API versions and OpenAPI

`PouryaKit.Web.OpenApi`, optional: the API versions a Module declares, served on its own route group by URL segment and by header, a deprecated version's configured sunset, one OpenAPI document per supported version with each operation's security requirement, and the Scalar API reference over those documents. Namespace `PouryaKit.Web.OpenApi`. It references `PouryaKit.Web`, `Asp.Versioning.Http`, `Asp.Versioning.OpenApi`, `Microsoft.AspNetCore.OpenApi` and `Scalar.AspNetCore`. A Host that does not register it, and a Module that declares no version, keep the unversioned paths of [web.md](web.md); `PouryaKit.Web` references none of this stack.

There is no Swagger, Swashbuckle, NSwag or AsyncAPI: the documents are ASP.NET Core's own OpenAPI, and `PackageGraphTests` fails when a Swagger generator arrives in the package's closure.

## Declaring a Module's versions

The Proving Sample's Catalog declares its versions in its Composition Root, beside its endpoints, and its v2-only Feature maps itself to v2:

```csharp
using Asp.Versioning;
using Microsoft.AspNetCore.Builder;
using Microsoft.AspNetCore.Routing;
using PouryaKit.Cqrs;
using PouryaKit.Modularity;
using PouryaKit.Web;
using PouryaKit.Web.OpenApi;

// In the Composition Root:
// module.AddPouryaKitEndpoints("/catalog");
// module.AddPouryaKitApiVersions(
//     "/catalog",
//     versions => versions.HasDeprecatedApiVersion(new ApiVersion(1, 0)).HasApiVersion(new ApiVersion(2, 0))
// );

// Renaming arrived in v2; v1 callers cannot rename.
internal sealed class RenameProductEndpoint : IEndpoint
{
    public void Map(IEndpointRouteBuilder routes) =>
        routes
            .MapPut(
                "/products/{productId}/name",
                async (
                    Guid productId,
                    RenameProductBody body,
                    OperationContext context,
                    IGatewayProcessor<CatalogModule> catalog,
                    CancellationToken cancellationToken
                ) =>
                    (
                        await catalog.SendAsync(new RenameProductCommand(productId, body.Name), context, cancellationToken)
                    ).ToHttpResult()
            )
            .MapToApiVersion(new ApiVersion(2, 0));
}

internal sealed record RenameProductBody(string Name);
```

- `module.AddPouryaKitApiVersions(routePrefix, declare)` names the same prefix as the Module's `AddPouryaKitEndpoints`. `declare` states the versions on the Module's API version set, Asp.Versioning's own `ApiVersionSetBuilder`: `HasApiVersion` for a supported version, `HasDeprecatedApiVersion` for a deprecated one. A second declaration for one prefix throws, and a declaration whose prefix no Module's endpoints are mapped under fails the Host's start:

  ```text
  API versions are declared for the route group /catlog, but no Module's endpoints are mapped under it. Declare them with the prefix the Module's AddPouryaKitEndpoints names, and map the Modules with MapPouryaKitModuleEndpoints.
  ```
- Every endpoint of the Module serves every declared version. An endpoint that exists in some versions only says so with `MapToApiVersion(version)`; an endpoint whose contract changes in a version can be a second `IEndpoint` mapped to that version, beside the first mapped to the others (the Proving Sample has none).
- A version is the Module's: the Host lists none. Versions of different Modules that share a number share one document.
- Each endpoint is mapped twice, on the versioned and on the unversioned path ([What a caller sees](#what-a-caller-sees)). An endpoint's name (`WithName`) stays on its versioned copy only, because ASP.NET Core's endpoint names are unique: a link generated by name is a versioned path, and the document's operation id is on the versioned operation.
- A Module that declares versions in a Host that does not register them fails when its endpoints are mapped:

  ```text
  The Module mapped under /catalog declares API versions, but the Host does not register them. Call AddPouryaKitOpenApi on the Host's services.
  ```

`AddPouryaKitApiVersions` registers the one `IModuleRouteGroups` of `PouryaKit.Web` this package supplies; `MapPouryaKitModuleEndpoints` maps each Module's endpoints on the route builders it returns, inside the Module's authenticated route group ([web.md](web.md#the-host)).

## The Host

```csharp
// In ModularMonolithHost.CreateBuilder, after AddPouryaKitWeb:
builder.Services.AddPouryaKitOpenApi();
builder.Services.Configure<PouryaKitOpenApiOptions>(builder.Configuration.GetSection("PouryaKit:OpenApi"));

// In ModularMonolithHost.Build, after MapPouryaKitModuleEndpoints:
if (app.Environment.IsDevelopment())
{
    app.MapPouryaKitOpenApi().AllowAnonymous();
}
```

- `AddPouryaKitOpenApi()` registers Asp.Versioning with its URL segment reader and its `api-version` header reader, reports each Module's supported and deprecated versions in every response, applies the configured sunsets, and registers one OpenAPI document per supported version with the Kit's notices, security requirements and required `Idempotency-Key` headers.
- `MapPouryaKitOpenApi()` serves `/openapi/v1.json`, `/openapi/v2.json` and so on, and the Scalar reference at `/scalar/`. Like every endpoint they require an authenticated caller unless the returned builder says otherwise; the Proving Sample serves them in Development only, to anyone.

## What a caller sees

| Request | Answer |
|---|---|
| `GET /catalog/v1/products/{id}` | v1, from the URL segment |
| `GET /catalog/products/{id}` with `api-version: 2.0` | v2, from the header |
| `PUT /catalog/v1/products/{id}/name` | 404 problem response: v1 has no such operation |
| `PUT /catalog/products/{id}/name` with `api-version: 1.0` | 400 problem response: the version does not serve it |
| `GET /catalog/products` with no version | 400 problem response |
| `GET /catalog/v1/products` with `api-version: 2.0` | 400 problem response: two versions named |

- Every response of a versioned Module carries `api-supported-versions` and `api-deprecated-versions`. A refusal is the same RFC 9457 problem response as every other failure ([web.md](web.md#problem-responses)).
- A resource's location names the version the request selected: `CreateProduct` answers `Location: /catalog/v2/products/{id}` to a v2 request by URL or by header, so a caller follows it with no header, or with its own `api-version` header, which then names the same version. It generates the link by name, passing the requested version as the `version` route value:

  ```csharp
  links.GetPathByName(
      httpContext,
      GetProductEndpoint.Name,   // GetProduct maps itself .WithName(Name)
      new { productId = id, version = httpContext.RequestedApiVersion?.ToString("VVV", CultureInfo.InvariantCulture) }
  )
  ```

## Deprecation and sunset

```json
{
  "PouryaKit": {
    "OpenApi": {
      "Sunsets": {
        "1.0": {
          "Date": "2027-06-30T00:00:00+00:00",
          "Link": "https://example.com/catalog/api-v1-sunset"
        }
      }
    }
  }
}
```

- The Module deprecates a version (`HasDeprecatedApiVersion`); the Host configures when it ends. `PouryaKitOpenApiOptions.Sunsets` is keyed by the version as the Modules declare it; a key that names no version throws when the options are read.
- A response of a version with a sunset carries `Sunset: Wed, 30 Jun 2027 00:00:00 GMT` and `Link: <https://example.com/catalog/api-v1-sunset>; rel="sunset"; type="text/html"`.
- The version's document states it in `info.description` (`This API version is deprecated. Its sunset date is Wed, 30 Jun 2027 00:00:00 GMT.`, then the link) and in `x-api-versioning.links`, and marks each of its operations `deprecated`.
- Nothing is derived from the current time (ADR 0005): the date is the configured one, never "now + n days", and the notice names it the same way before and after it passes. Asp.Versioning's default notice says "was" or "will be" from the clock; the Kit replaces it.

## Documents and Scalar

- The documents are the versions the Modules declared, as `IApiVersionDescriptionProvider` enumerates them, never a list in the Host. A document holds the operations its version serves, on both paths; the unversioned one lists its `api-version` header parameter. An endpoint of a Module that declares no version appears in every document.
- An operation carries a security requirement exactly when the authorization middleware would challenge an anonymous caller: it allows no anonymous caller, and its authorization data or the authenticated default `AddPouryaKitWeb` sets give it a policy. The requirement names the authentication schemes that policy names, or else the Host's default authenticate scheme, one requirement per scheme, since any of them satisfies it. An `AllowAnonymous` or `AllowAnonymousAs(actor)` operation carries no `security`.
- Only a JWT bearer scheme (its handler is `JwtBearerHandler` or derives from it) is stated, as `components.securitySchemes.<scheme name>` with `type: http`, `scheme: bearer`; the Proving Sample's is `Bearer`. A scheme of any other handler (a cookie, an API key, a test scheme) is left out of the document, so an operation protected only by such a scheme carries no requirement although it refuses anonymous callers. The fixture's Host, whose default scheme is its test scheme, documents none.
- An operation whose endpoint calls `RequireIdempotencyKey()` ([web.md](web.md#a-repeatable-write)) lists a required header parameter `Idempotency-Key` of type string, whose description states the rule its value follows; no other operation lists it. The Proving Sample's `POST /catalog/products` carries it in every version, on both paths.
- The Scalar page at `/scalar/` lists every version's document by its group name (`v1`, `v2`), each read from `/openapi/{name}.json`.

## Testing versions and documents

- The Proving Sample's fixture clients name `api-version: 2.0` (`AppFixture.ApiVersion`), so tests of other Capabilities call the unversioned paths as a v2 caller. A test of versioning removes that header and names its own version per request.
- `OpenApiTests` proves selection by URL and by header, the refusals, the configured sunset in responses and documents, each document's operations, the security requirements against what the pipeline answers, the required `Idempotency-Key` header, Scalar's document list, and a Host of `PouryaKit.Web` alone serving an unversioned route group without any versioning service.
- Read a document over HTTP (`/openapi/v2.json`) and assert its JSON; assert a security requirement against the status an anonymous request gets, so the document cannot drift from the pipeline. A requirement follows the Host's schemes, so a test of the bearer requirement composes the Host with its own default scheme (`AddAuthentication(JwtBearerDefaults.AuthenticationScheme)` after the fixture's).
