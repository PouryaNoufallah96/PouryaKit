# Private publication

Read [private package guidance](../../../../docs/private-packages.md) when consuming GitHub Packages, publishing a main candidate or retrying preserved originals.

Keep the existing shared Release build/test/pack path and the package inventory in `scripts/packaging/inventory.json`. MinVer alone determines versions from full history and tags; publication downloads originals and never rebuilds or supplies a version override. A named `0.x` preview/rc version uses an owner-created `v` tag on current main followed by manual CI on main. No workflow creates a tag or GitHub Release.

Authorize only the exact successful same-repository main CI `push` or `workflow_dispatch` attempt and SHA, with successful AI/package jobs. PR receipts cannot authorize publication. Use official artifact download, bind the receipt/manifest to that provenance, and verify local original hashes. Keep the original artifact and manifest unchanged, and fail if they are unavailable.

Use the fixed GitHub Packages feed, job-scoped `GITHUB_TOKEN` and `pouryakit-private-publication` group with cancellation disabled. Run standard `dotnet nuget push --skip-duplicate`, then restore every library package in the inventory at its exact version in a temporary consumer with fresh caches and GitHub source mapping for `PouryaKit.*`. Install a package of inventory kind `template` from the feed instead, because a `PackageReference` to it restores without assets: `dotnet new install <id>@<version>` into its own hive, run beside a copy of the configuration with nuget.org disabled (the install ignores source mapping and reads its working folder's `NuGet.Config`), then generate each template, by the `shortName` in its `template.json`, as `Acme.Shop` and `acme-shop`, and restore those solutions the same way. Credentials belong only in the push/restore environment, never configuration, artifacts or diagnostics. A newer pending attempt can replace an older pending attempt; GitHub concurrency is not a durable queue.

HTTP 409 skips are not remote-byte identity proof, and the SDK's package validation is no compatibility approval: release automation beyond this scope needs a new scoped ticket ([plan Phase 5](../../../../docs/foundation-review.md#phase-5-packaging-and-releases)). Do not claim all original #24 acceptance criteria. The active Phase 5 scope is complete; [hosted completion evidence](../../../../docs/private-packages.md#hosted-completion) records the main CI and publication that completed it, at version `0.1.0-preview.0.13`, and those that completed Wave 2, at `0.1.0-preview.0.17`. Local workflow checks prove neither feed access nor private visibility.

The successful [retry run 37465070135](https://github.com/PouryaNoufallah96/PouryaKit/actions/runs/37465070135) completed `0.1.0-preview.0.10` from original main CI `37456433718`, attempt `1`, artifact `11408539884`, source `2de265641b8cd94a5ddc17980cdcad530f0a8f60`: Domain was skipped on HTTP 409, twelve packages were pushed and all thirteen restored with fresh caches. Preserve the original artifacts and retry record; never delete, replace or repack that version. This proves availability, not remote raw-byte identity.
