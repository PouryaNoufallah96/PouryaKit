# Package consumption and validation

Read [the package guide](../../../../docs/packages.md) before changing package metadata, inventory, versions or consumer checks. The explicit inventory and existing `PackageGraph` are the owners of the package set and dependency rules. MinVer is the sole version engine; select one manifest version for all Kit references.

Run `python3 scripts/packaging/validate.py` from the Kit checkout with the pinned SDK, Python and Docker. It prints a system-temporary evidence directory with one nupkg per package in `scripts/packaging/inventory.json`, source SHA/version/checksum manifest, separate PostgreSQL test logs and isolated consumer results. `--output` accepts a fresh evidence directory outside the checkout; one that already holds files only with `--keep`, since a PASS removes the directory otherwise.

For a consuming project, use that directory's `packages/` as a local feed, map `PouryaKit.*` to it, and keep nuget.org for third-party packages. Use the version recorded in `manifest.json`. The shared proof builds each library package alone, the documented single-Module set, the copied Proving Sample and the solutions the three project templates generate from the produced `PouryaKit.Templates`, using only package references for Kit dependencies, and runs the generated solutions' smoke tests, so it needs Docker ([templates.md](templates.md)). On a directory kept with `--keep`, `python3 scripts/packaging/composition_proof.py <directory>` then runs the generated modular monolith and service together as processes over one RabbitMQ, a recorded step the validation does not take ([the package guide](../../../../docs/packages.md#the-composition-proof)).

For CI validation or a publication handoff, read [CI guidance](../../../../docs/ci.md). CI calls the same Release path with `--no-fetch` after full-history/tag checkout removes its credentials. Require the tested SHA, successful job result and original artifact manifest; PRs test the merge revision, and neither a PR receipt nor manual non-main CI can authorize publication. Keep NuGet caches, CLI homes and credentials out of retained evidence.

Keep source runtime tests, package builds and hosted execution evidence distinct. The shared path does not publish. The delivered [private publisher](publication.md) has separate hosted publication and restore evidence. `0.1.0-preview.0.28` is also on nuget.org, published by hand with no workflow ([nuget.org publication](../../../../docs/private-packages.md#nugetorg-publication)).
